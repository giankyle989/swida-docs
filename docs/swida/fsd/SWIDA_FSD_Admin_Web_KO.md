# 기능 명세서 (FSD)

## SWIDA — Admin Web

- **버전**: 1.2
- **날짜**: 2026-03-30
- **기반 문서**: SWIDA PRD v1.2, SWIDA TSD v1.2
- **범위**: MVP — 관리자용 플랫폼 관리 웹 애플리케이션
- **관련 문서**: UI/UX 명세서 v1.2, Customer Web FSD v1.0
- **변경 요약 (v1.1 → v1.2):** §1.5 문서 권위 계층 추가 (정보 출처 모순 해결). §1.3 MVP 범위 테이블 업데이트 — 연기된 기능(게시판 게시글, 이벤트, 공지사항, 커뮤니티 게시글)이 Deferred MVP로 명시되며 비활성 사이드바 플레이스홀더 요구사항 포함. §1.4 글로벌 규칙 확장: 미리보기 계약, 데이터 상태, 로컬라이제이션 규칙. §6 리뷰: `under_review` 상태 시각 표시가 빨간색에서 황색(조치 필요 신호)으로 변경. §9 문의: 진행 바 단계-상태 매핑 공식 정의. §16.2 로그아웃은 명시적으로 보이는 버튼 필요. §17 데이터 및 UI 상태(로딩, 빈 상태, 오류, 네트워크) 명세 추가. §18 미리보기 시스템 계약 추가.

## 1. 문서 개요

### 1.1 목적

본 문서는 SWIDA Admin Web 애플리케이션의 페이지 목록과 기능 명세를 정의한다. Admin Web은 SWIDA 플랫폼을 관리하기 위한 핵심 운영 인터페이스로, 일상적인 운영 업무를 위한 전용 관리자 패널로 사용된다. 시각적 디자인, 레이아웃, 인터랙션 세부사항은 별도의 UI/UX 명세서에서 다룬다.

### 1.2 아키텍처 컨텍스트

Admin Web은 `admin.swida.com`에서 제공되는 전용 웹 애플리케이션이다. 인증 및 콘텐츠 관리를 위해 백엔드와 통신한다. 플랫폼 내장 관리자 패널은 모니터링 및 디버깅 목적으로 개발자에게만 접근이 제한되며, 본 문서에서 정의하는 운영 기능에는 사용되지 않는다.

### 1.4 글로벌 규칙

| 항목                    | 규칙                                                                                                                                                                                                                                                                                                                                                                                            |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 언어                    | Admin Web UI는 영어로 표시 (관리자용이며, 고객용이 아님)                                                                                                                                                                                                                                                                                                                                        |
| 날짜/시간               | KST (한국 표준시, UTC+9). 형식: `YYYY-MM-DD HH:mm:ss`                                                                                                                                                                                                                                                                                                                                           |
| 인증                    | 모든 페이지는 관리자 인증 필요. 미인증 요청은 로그인 페이지로 리다이렉트                                                                                                                                                                                                                                                                                                                        |
| API 통신                | 백엔드가 인증 및 콘텐츠 작업을 처리. 자세한 API 사양은 TSD §5.2 참조                                                                                                                                                                                                                                                                                                                            |
| 소프트 삭제 정책        | 업체 목록은 절대 물리 삭제하지 않음. 비활성화된 업체는 비활성 사유와 함께 비공개 처리                                                                                                                                                                                                                                                                                                            |
| 페이지네이션            | 설정 가능한 페이지 크기(10, 20, 50)의 테이블 기반 페이지네이션                                                                                                                                                                                                                                                                                                                                   |
| 로딩 상태               | API 호출 진행 중 데이터 테이블 및 폼에 스켈레톤 플레이스홀더 표시                                                                                                                                                                                                                                                                                                                                |
| 빈 상태                 | "결과가 없습니다" 메시지와 함께 필터 조정 제안 표시. 최초 빈 페이지(예: 업체가 아직 없는 경우)에는 첫 번째 항목 생성 유도 안내 표시.                                                                                                                                                                                                                                                              |
| 오류 상태               | 서버 오류: 빨간색 토스트 "일시적인 오류가 발생했습니다. 잠시 후 다시 시도해주세요." + 재시도 버튼. 네트워크 오류: 빨간색 토스트 "네트워크 연결을 확인해주세요." 두 경우 모두 닫을 때까지 지속 표시.                                                                                                                                                                                                |
| 확인                    | 모든 파괴적 작업(숨김, 삭제, 잠금, 비공개)은 확인 대화상자 필요                                                                                                                                                                                                                                                                                                                                  |
| 토스트 알림             | 모든 쓰기 작업에 대한 성공/오류 피드백                                                                                                                                                                                                                                                                                                                                                           |
| 반응형                  | 데스크톱 우선. 최소 지원 너비: 1024px                                                                                                                                                                                                                                                                                                                                                            |
| 입력 값 검증            | 관리자가 제출하는 모든 자유 텍스트 필드(업체 설명, 비활성 사유 상세, 테마 이름, 검토/관리 사유)는 저장 전 서버 측에서 검증됨. HTML 태그는 제거됨. 렌더링 시 출력 값은 Customer Web에서의 저장형 XSS 방지를 위해 이스케이프됨.                                                                                                                                                                     |
| 중복 제출 방지          | 모든 폼 제출 및 액션 버튼(저장, 공개, 숨김, 삭제, 잠금, 상태 변경)은 첫 클릭 시 서버 응답이 올 때까지 비활성화 + 로딩 상태로 전환됨. 빠른 클릭으로 인한 API 중복 호출을 방지함.                                                                                                                                                                                                                  |
| 충돌 감지               | 모든 편집 폼은 저장 요청에 레코드의 `updatedAt` 타임스탬프를 포함함. `409 Conflict` 응답(다른 세션에서 레코드가 수정됨) 시 모달 대화상자를 표시: "이 항목이 다른 세션에서 수정되었습니다. 새로고침 후 다시 시도하세요." 페이지를 새로고침하는 새로고침 버튼 포함. 관리자가 새로고침할 때까지 저장 작업이 차단됨. 서버 측 구현은 TSD §5.3.1a 참조. |
| 로컬라이제이션 (Admin UI) | Admin Web UI 크롬(라벨, 버튼, 내비게이션, 오류 메시지)은 모두 영어로 표시됨. 콘텐츠 데이터(업체 이름, 설명, 테마 이름 등)는 한국어로 작성되며, 로케일 전환기를 통해 선택적으로 영어 번역 가능. 이 둘은 별개의 관심사임 — "영어 전용 Admin UI"와 "영어 전용 콘텐츠"를 혼동하지 말 것.                                                                                                           |
| 미리보기 계약           | 업체 미리보기는 Customer Web을 새 브라우저 탭에서 열음. 초안(미공개) 업체 미리보기는 URL 파라미터로 전달되는 시간 제한 서명 미리보기 토큰이 필요. Customer Web은 이 토큰을 읽어 해당 세션에서 임시로 공개 전용 필터를 우회함. 토큰 만료: 15분. 전체 미리보기 시스템 명세는 §18 참조.                                                                                                              |

### 1.5 문서 권위 계층

본 FSD, UI/UX 명세서, HTML 프로토타입 간의 모순을 방지하기 위해 다음 계층이 적용된다:

| 계층        | 문서                         | 권위                                                                               | 범위                                    |
| ----------- | ---------------------------- | ---------------------------------------------------------------------------------- | --------------------------------------- |
| 1 (최상위)  | **본 FSD**                   | 기능 로직, 비즈니스 규칙, 상태 전이, 데이터 계약, API 동작                         | 시스템이 하는 일                        |
| 2           | **UI/UX 명세서 v1.2**        | 화면 레이아웃, 인터랙션 흐름, 컴포넌트 패턴, 스토리보드                            | 시스템의 동작 방식과 탐색 방법          |
| 3 (최하위)  | **HTML 프로토타입**           | 시각적 참고 — 색상, 간격, 컴포넌트 미학                                            | 외관                                    |

**규칙:**

- FSD와 UI/UX 명세서가 충돌하면 → **FSD가 우선**. UI/UX 명세서를 FSD에 맞춰 업데이트하고, 불일치 사항을 기록할 것.
- UI/UX 명세서와 프로토타입이 충돌하면 → **UI/UX 명세서가 우선**. 프로토타입은 시각적 참고이며, 인터랙션에 대한 구속력 있는 계약이 아님.
- 프로토타입에 두 문서 모두에서 다루지 않은 인터랙션 패턴이 도입된 경우 → **UI/UX 명세서에 추가**하고, 구현 전 FSD 로직과 대조 검토할 것.
- 엔지니어는 모든 로직 결정에 FSD를 따름. 디자이너는 모든 레이아웃/인터랙션 결정에 UI/UX 명세서를 따름. 프로토타입은 시각적 마감 작업의 출발점으로만 활용.

### 2.2 연기된 MVP 페이지

다음 페이지들은 **본 FSD에 완전히 명세되어 있으며** **백엔드 데이터 모델(TSD §4.4)에도 포함되어 있으나**, UI는 이후 프로토타입 반복으로 연기됨. 이들은 **비활성 사이드바 항목**(회색 텍스트, "Coming soon" 툴팁)으로 표시되어야 하며, 이를 통해 엔지니어가 전체 범위를 파악하고 내비게이션 구조가 예약됨. 완전히 생략해서는 **안 됨**.

| 15  | 이벤트            | `/events`           | Content       | §12      |

**비활성 사이드바 동작:** 연기된 항목은 사이드바에 흐린/회색 텍스트로 표시되며 호버 상태가 없음. 클릭 시 "Coming soon" 툴팁 표시. 구현 전까지 해당 경로는 404를 반환하거나 `/dashboard`로 리다이렉트.

**접근 제어**: 로그인 페이지를 제외한 모든 페이지는 인증된 관리자 세션이 필요하다. 미인증 상태에서 페이지에 접근하면 `/login`으로 리다이렉트된다.

## 3. 인증

### 3.1 로그인 (`/login`)

> PRD Reference: §3.1 Admin Authentication, TSD §5.4.2

**기능 목록**

| #         | 기능                  | 설명                                                                             |
| --------- | --------------------- | -------------------------------------------------------------------------------- |
| F-AUTH-01 | 이메일/비밀번호 로그인 | 관리자가 이메일과 비밀번호로 로그인. 세션이 안전하게 유지됨                      |
| F-AUTH-02 | 세션 저장             | 관리자 세션이 브라우저에 안전하게 저장되며 이후 모든 요청에 사용                  |
| F-AUTH-03 | 로그인 후 리다이렉트  | 로그인 성공 시 `/dashboard`로 리다이렉트                                          |
| F-AUTH-04 | 오류 처리             | 잘못된 자격 증명 또는 서버 오류 시 오류 메시지 표시                               |
| F-AUTH-05 | 이미 인증된 상태      | 관리자가 이미 로그인한 경우 `/login`에서 `/dashboard`로 리다이렉트                |

**입력 제약사항**

| 필드     | 필수 | 제약사항           |
| -------- | ---- | ------------------ |
| Email    | 예   | 유효한 이메일 형식 |
| Password | 예   | 비어 있지 않아야 함 |

**서버 유효성 검사 오류**

| 조건                | 오류                                             |
| ------------------- | ------------------------------------------------ |
| 잘못된 자격 증명    | "Invalid email or password"                      |
| 서버 접속 불가      | "Unable to connect to server. Please try again." |

**행 액션 버튼 (구현 현황):** 행당 인라인 버튼 2개 — "Keep" (녹색 테두리, published로 상태 전환) 및 "Hide" (빨간색 테두리, 사유 대화상자 열림). ⋯ 오버플로 메뉴 없음. 체크박스 컬럼 없음.

**상태 필 렌더링:**

| 상태           | CSS 클래스      | 표시 색상     | 근거                                                                                             |
| -------------- | --------------- | ------------- | ------------------------------------------------------------------------------------------------ |
| `published`    | `.pub`          | 녹색          | 긍정적 / 노출 상태                                                                               |
| `under_review` | `.under-review` | **황색**      | **조치 필요** — hidden과 기능적으로 구별됨. 황색은 "지금 관리자 주의 필요"를 신호함.               |
| `hidden`       | `.hidden`       | 빨간색        | 종료 / 차단 상태                                                                                  |

> **중요:** `under_review`와 `hidden`은 모두 "Customer Web에서 비노출"을 의미하지만 **시각적으로 구별되어야** 함. 리뷰 테이블을 스캔하는 관리자는 조치가 필요한 리뷰(`under_review` = 황색)와 이미 처리된 리뷰(`hidden` = 빨간색)를 즉시 식별할 수 있어야 함. 두 상태에 같은 색상을 사용하면 효율적 분류가 불가함. 프로토타입은 두 상태 모두에 `.hidden` (빨간색)을 사용 — 구현 시 수정되어야 하는 알려진 시각적 차이.

**신고 수 컬럼:** 색상 배지로 표시 — 높은 건수(≥3건 신고)는 빨간색 배경, 낮은 건수는 황색 배경.

**검토/관리 사유 선택** (PRD §8.4)

| Reason Code     | Display Label         |
| --------------- | --------------------- |
| `spam`          | Spam                  |
| `inappropriate` | Inappropriate content |
| `fake_review`   | Fake review           |
| `irrelevant`    | Irrelevant            |
| `other`         | Other                 |

**상태 전이**

```
published ──→ hidden (관리자 숨김)
published ──→ deleted (관리자 소프트 삭제)
under_review ──→ published (관리자 승인)
under_review ──→ hidden (관리자 숨김)
under_review ──→ deleted (관리자 소프트 삭제)
hidden ──→ published (관리자 복원)
deleted ──→ published (관리자 복원 — 확인 필요: "이 리뷰는 이전에 삭제되었습니다. 복원하면 다시 표시됩니다.")
```

**복원 전 검증 (deleted → published)**

삭제된 리뷰를 `published` 상태로 복원하기 전에 시스템이 다음 검사를 수행한다. 검사에 실패하면 복원이 차단된다:

| #   | 검사 항목             | 실패 조건                                           | 오류 메시지                     |
| --- | --------------------- | --------------------------------------------------- | ------------------------------- |
| 1   | 작성자 계정 상태      | 작성자 계정이 잠김 (`blocked = true`)               | "Author account is locked"      |
| 2   | 상위 업체 상태        | 상위 업체가 공개되지 않음 (초안 또는 비공개)         | "Shop is currently unpublished" |

두 검사는 확인 대화상자가 표시되기 전에 실행된다. 검사에 실패하면 복원 버튼이 비활성화되고 오류 메시지가 인라인으로 표시된다. 리뷰를 복원하려면 관리자가 먼저 근본 문제(계정 잠금 해제 또는 업체 공개)를 해결해야 한다.

**평점 재계산**: 상태 변경 시 상위 업체의 평균 평점 및 리뷰 수가 자동으로 재계산됨 (PRD §8.5).

**진행 바 단계-상태 매핑:**

각 문의 카드의 5단계 진행 바는 문의 상태에 직접 매핑됨. 이 매핑은 결정적임 — 프론트엔드는 상태 필드만으로 활성 단계를 도출하며, 추가 상태가 필요 없음.

| 단계 | 상태            | 바 세그먼트 색상                   | 비고                                                                              |
| ---- | --------------- | ---------------------------------- | --------------------------------------------------------------------------------- |
| 1    | `new`           | 현재 = 브랜드, 2–5 = 회색         | 첫 연락 미완료                                                                    |
| 2    | `contacted`     | 1 = 녹색, 2 = 브랜드, 3–5 = 회색  | 관리자가 연락함                                                                    |
| 3    | `awaiting_info` | 1–2 = 녹색, 3 = 브랜드, 4–5 = 회색 | 업체 오너 정보 대기 중                                                              |
| 4    | `approved`      | 1–3 = 녹색, 4 = 브랜드, 5 = 회색  | 목록 생성 준비 완료                                                                |
| 5    | `published`     | 1–5 = 녹색                         | 최종 — 목록 공개                                                                   |
| —    | `rejected`      | 전체 회색                          | 최종 — 진행 표시 없음; 카드에 진행 바 대신 "Rejected" 라벨 표시                    |

**상태 전이 규칙 (서버 측 적용):**

- `new` → `contacted`만 가능 (또는 `rejected`)
- `contacted` → `awaiting_info`만 가능 (또는 `rejected`)
- `awaiting_info` → `approved`만 가능 (또는 `rejected`)
- `approved` → `published`만 가능 (업체 생성 + 공개 시 자동 트리거, 또는 `rejected`)
- `rejected` → `new` (관리자 재오픈 — 확인 필요)
- `published`는 최종 — 추가 전이 불가

**프론트엔드 도출:** 주요 액션 버튼 라벨과 상태는 현재 `status` 필드에서 전적으로 도출됨:

| 상태            | 주요 버튼      | 버튼 스타일           | 액션                                                  |
| --------------- | -------------- | --------------------- | ----------------------------------------------------- |
| `new`           | Contact →      | 녹색 (승인 스타일)    | 상태를 `contacted`로 전진                              |
| `contacted`     | Approve →      | 브랜드 색상           | 상태를 `awaiting_info`로 전진                          |
| `awaiting_info` | Approve →      | 브랜드 색상           | 상태를 `approved`로 전진                               |
| `approved`      | Create Draft → | 브랜드 색상           | `/shops/new?from_inquiry={id}`로 이동                  |
| `published`     | View Shop →    | Ghost                 | 연관 업체 목록으로 링크                                |
| `rejected`      | Reopen →       | Ghost                 | 상태를 `new`로 되돌림 (확인 필요)                      |

**문의 카드 상태 배지 색상:**

| 상태            | 색상                      |
| --------------- | ------------------------- |
| `new`           | 파란색                    |
| `contacted`     | 녹색                      |
| `awaiting_info` | 파란색 (`.new` 스타일 사용) |
| `approved`      | 브랜드 색상 (주황색)       |
| `rejected`      | 빨간색                    |
| `published`     | 녹색                      |

**지연 카드 스타일링:** 지연 문의가 있는 카드는 3px 빨간색 좌측 테두리 액센트 (`border-left: 3px solid var(--red)`) 적용.

**상태 흐름 다이어그램**

```
new ──→ contacted ──→ awaiting_info ──→ approved ──→ published
  └──→ rejected       └──→ rejected      └──→ rejected
         └──→ rejected
```

**기능 목록**

| #          | 기능                 | 설명                                                                                                                                                                                                                                     |
| ---------- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| F-AUDIT-04 | 필터 — 관리자        | 향후 필터 (현재 프로토타입에 미포함)                                                                                                                                                                                                      |
| F-AUDIT-05 | 필터 — 날짜          | 향후 필터 (현재 프로토타입에 미포함)                                                                                                                                                                                                      |
| F-AUDIT-06 | 필터 — 문서          | 텍스트 검색 입력: "Search shop or field..." — 업체 이름 또는 필드 이름으로 필터                                                                                                                                                            |

| F-AUDIT-08 | 정렬                 | 정렬 기준: 타임스탬프 (기본값: 최신순)                                                                                                                                                                                                    |
| F-AUDIT-09 | 페이지네이션          | 테이블 페이지네이션. "Showing N–M of Total log entries" 표시                                                                                                                                                                               |

**플랫 행 형식 (구현 현황):** 각 감사 로그 항목은 모든 정보가 인라인으로 포함된 단일 테이블 행: 타임스탬프, 관리자 이름, 업체 이름, 작업 필, 필드 이름(모노스페이스), 이전→이후 변경 인라인. 확장 가능한 행 없음 — 단일 저장 작업의 각 필드 변경이 자체 플랫 행을 생성.

**작업 필 색상 매핑:**

| 작업         | CSS 클래스 | 색상   |
| ------------ | ---------- | ------ |
| published    | `.pub`     | 녹색   |
| field update | `.draft`   | 황색   |
| unpublished  | `.hidden`  | 빨간색 |
| created      | `.new`     | 파란색 |

**Change 컬럼 형식:** `<span class="diff-old">before_value</span> → <span class="diff-new">after_value</span>`. 이전 값은 빨간색 취소선 텍스트; 이후 값은 녹색.

> 자세한 데이터 스키마는 TSD §4.4.7 참조.

감사 로그는 업체 변경 사항뿐만 아니라 모든 상태 변경 관리자 작업을 포함한다:

| 콘텐츠 유형         | 감사 대상 작업                                                                     |

| Board Post          | Create, Update, Delete, Publish, Unpublish                                         |
| Event               | Create, Update, Delete, Publish, Unpublish                                         |
| Notice              | Create, Update, Delete, Publish, Unpublish                                         |
| Community Post      | Hide, Restore, Delete (검토/관리 작업)                                             |

**보안 이벤트 로그**

콘텐츠 감사 로그 외에도 다음 보안 민감 이벤트는 모니터링 및 인시던트 대응을 위해 서버 측에 기록된다:

## 16. 글로벌 레이아웃 및 내비게이션

### 16.1 셸 레이아웃

Admin Web은 **사이드바 전용 셸**을 사용한다. 별도의 전체 너비 글로벌 헤더 바는 없다. 레이아웃 구성:

- **왼쪽 사이드바** (고정 너비, 전체 뷰포트 높이): 로고 마크, 내비게이션 그룹 섹션, 하단의 관리자 사용자 신원 포함.
- **상단 바** (고정, 메인 콘텐츠 영역 내부): 현재 페이지 제목, 브레드크럼 경로 (예: "SWIDA Admin › Overview"), 우측의 컨텍스트 액션 버튼 (예: "+ New Shop", "Export CSV") 표시. 이는 페이지 수준 상단 바이며, 글로벌 헤더가 아님.
- **메인 콘텐츠 영역** (스크롤 가능, 나머지 너비 채움): 테이블, 폼, 카드가 포함된 페이지 본문.

## 18. 미리보기 시스템 계약

이 섹션은 업체 미리보기 기능(F-SHOP-11, F-SHOP-32)의 전체 명세를 정의한다.

### 18.1 "미리보기"의 의미

미리보기는 관리자가 업체 목록이 Customer Web에서 고객에게 어떻게 보일지를 정확히 확인할 수 있게 한다 — 아직 공개적으로 표시되지 않는 초안(미공개) 업체도 포함.

### 18.2 동작 방식

| 단계 | 설명                                                                                                                                                                                              |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 관리자가 업체 목록 행의 "Preview" 버튼(👁)이나 업체 수정 폼의 "Preview (Customer View)" 버튼을 클릭.                                                                                                |
| 2    | Admin Web이 백엔드에 시간 제한 서명 미리보기 토큰을 요청: `POST /api/admin/shops/{id}/preview-token`                                                                                               |
| 3    | 백엔드가 `shop_documentId`와 `admin_user_id`를 포함하는 암호학적으로 서명된 토큰(JWT, 15분 만료)을 생성. 토큰을 반환.                                                                               |
| 4    | Admin Web이 새 브라우저 탭에서 URL 열기: `{CUSTOMER_WEB_URL}/[locale]/shop/{slug}?preview_token={token}`                                                                                           |
| 5    | Customer Web이 `preview_token` 쿼리 파라미터를 읽음. 존재하고 유효한 경우, 공개 전용 필터를 우회하여 업체를 조회 (토큰과 함께 `GET /api/shops/{id}?status=draft` 호출).                              |
| 6    | Customer Web이 공개 시 보이는 것과 동일하게 업체를 표시하며, 페이지 상단에 업체가 아직 공개되지 않았음을 나타내는 "Preview mode" 배너 표시.                                                           |
| 7    | 토큰 만료 (15분): 토큰이 만료되었거나 유효하지 않은 경우, Customer Web은 "Preview link expired" 페이지를 표시. 관리자는 Preview를 다시 클릭해야 함.                                                  |

### 18.3 초안 표시 규칙

| 업체 상태   | Customer Web에서의 동작 (공개)    | 유효한 미리보기 토큰 사용 시 동작  |
| ----------- | --------------------------------- | ---------------------------------- |
| `published` | 정상 표시                         | 정상 표시 (토큰은 선택)            |
| `draft`     | 비표시 — 404 페이지               | "Preview mode" 배너와 함께 표시    |

### 18.4 환경 규칙

- 미리보기는 항상 **동일 환경의** Customer Web을 연다. 프로덕션 Admin Web은 프로덕션 Customer Web을 미리보기. 스테이징은 스테이징을 미리보기.
- Admin Web의 `NEXT_PUBLIC_CUSTOMER_URL` 환경 변수가 미리보기 링크의 기본 URL을 정의.
- 미리보기 토큰은 환경별로 범위가 지정됨 — 스테이징에서 생성된 토큰은 프로덕션에서 작동하지 않음.
