## 1. 소개

### 1.1 목적

본 기능 명세서(FSD)는 SWIDA 고객 웹 애플리케이션의 모든 페이지 및 컴포넌트에 대한 정확한 동작, 사용자 인터랙션, UI 상태, 유효성 검사, 오류 처리 및 인수 기준을 정의합니다. 이 문서는 제품 비전(PRD)과 기술 아키텍처(TSD)를 시각적 디자인(Figma)과 연결하는 프론트엔드 개발자를 위한 단일 진실 공급원 역할을 합니다.

### 1.2 범위

본 문서는 고객 웹만을 다룹니다 — `www.swida.com`에서 샵 검색, 검색, 리뷰 및 제휴 문의 기능을 제공하는 Next.js 애플리케이션입니다. 관리자 웹과 Strapi 백엔드는 본 FSD의 범위에서 제외됩니다.

### 1.3 참조 문서

| 문서 | 버전 | 목적 |
|---|---|---|
| SWIDA PRD | v1.1 | 제품 요구사항, 비즈니스 규칙, 데이터 모델 |
| SWIDA TSD | v1.1 | 기술 스택, API 계약, 데이터베이스 스키마, 인프라 |
| Figma 디자인 | 최신 | 시각적 디자인, 레이아웃, 컴포넌트 명세 |

### 1.4 표기 규칙

- **Figma 참조:** 각 페이지 섹션에는 해당 Figma 화면 이름으로 연결되는 `Figma:` 태그가 포함됩니다
- **URL 패턴**은 동적 로케일 세그먼트(`ko` 또는 `en`)에 `[locale]`을 사용합니다
- **API 엔드포인트**는 TSD §5.2에 정의된 Strapi REST API 계약을 참조합니다
- **i18n 키**는 `t('key.name')` 형식으로 표시됩니다 — 실제 문자열은 `messages/ko.json` 및 `messages/en.json`에 있습니다
- 별도 명시가 없는 한 모든 시간은 **KST (한국 표준시, UTC+9)** 기준입니다
- **상태**는 다음 패턴으로 문서화됩니다: 기본 → 로딩 → 로드됨 → 비어있음 → 오류

### 1.5 PRD와의 차이점

Figma 디자인에는 PRD v1.1에 없는 기능 및 내비게이션 변경사항이 도입되었습니다. 본 FSD는 UI/UX의 진실 공급원으로서 Figma 디자인을 따릅니다. PRD는 아래 추가 사항을 반영하여 업데이트되어야 합니다:

| 기능 | PRD 상태 | FSD 상태 | 비고 |
|---|---|---|---|
| 이벤트 페이지 | PRD에 없음 | 포함 | 신규 네비게이션 항목, 신규 콘텐츠 타입 필요 |
| 게시판 섹션 | PRD에 없음 | 포함 | PRD의 "리뷰" 네비게이션 항목 대체. 포함 내용: 샵 추천, 마사지 정보, 커뮤니티 |
| 에디터 추천 (스위다 추천샵) | PRD에 없음 | 포함 | 홈페이지의 큐레이션 편집 카드, 신규 콘텐츠 타입 필요 |
| 샵 뱃지 (프리미엄, 신규) | PRD에 없음 | 포함 | 샵 카드의 시각적 뱃지 |
| 할인 가격 (취소선) | PRD에 없음 | 포함 | 프로모션/세일 가격 기능, 샵 데이터 모델 확장 |
| 공지 배너 (공지) | PRD에 없음 | 포함 | 순환 공지사항, 신규 콘텐츠 타입 필요 |
| 내비게이션 구조 | 상위 6개 항목 | 재구성 | Figma는 드롭다운 메뉴 사용: 샵 검색 ▾, 이벤트, 게시판 ▾, 제휴문의 |
| 내 주변 검색 위치 | 별도 네비게이션 항목 | 샵 검색 드롭다운 내부 | 최상위 네비게이션에서 하위 항목으로 이동 |
| 리뷰 메뉴 | 최상위 네비게이션 항목 | 게시판 드롭다운 내부 | 게시판 섹션으로 통합 |

## 2. 전체 레이아웃 & 내비게이션

> **Figma:** 메인 - Main (헤더 및 푸터 표시)

### 2.1 페이지 쉘

고객 웹의 모든 페이지는 일관된 레이아웃 쉘을 공유합니다:

```
┌─────────────────────────────────────────────────┐
│  공지 배너 (순환)                                  │
├─────────────────────────────────────────────────┤
│  헤더 (로고, 검색바, 내비게이션, 인증 버튼)           │
├─────────────────────────────────────────────────┤
│                                                  │
│  페이지 콘텐츠 (경로별 상이)                         │
│                                                  │
├─────────────────────────────────────────────────┤
│  푸터                                             │
└─────────────────────────────────────────────────┘
```

**구현:** `app/[locale]/layout.tsx`의 루트 레이아웃이 공지 배너, 헤더, `{children}` (페이지 콘텐츠), 푸터를 렌더링합니다.

> **참고:** 검색 관련 페이지(상세 검색, 테마별 검색, 지역별 검색, 내 주변 검색)는 헤더와 페이지 콘텐츠 사이에 **서브 내비게이션 바**를 추가로 렌더링합니다. 이 서브 네비게이션은 §4.2에 정의되며, 방문 후기 피드 및 제휴문의 페이지와 공유됩니다.

### 2.2 공지 배너

**목적:** 순환 방식의 관리자 관리 공지사항(시스템 공지, 프로모션, 점검 안내) 표시.

**위치:** 헤더 위 페이지 최상단에 고정. 전체 너비, 컴팩트한 높이.

**시각적 디자인:**
- 진한 네이비/블루 배경에 흰색 텍스트
- 좌측: 주황색 "NOTICE" 뱃지 + 공지 제목 텍스트 (너무 길면 말줄임표로 잘림)
- 우측: "자세히보기" 링크
- 일정 시간 간격으로 여러 공지를 자동 순환

**동작:**

| 항목 | 명세 |
|---|---|
| 데이터 소스 | `GET /api/notices?sort=createdAt:desc&filters[status][$eq]=published&locale={locale}` (신규 엔드포인트) |
| 순환 | 5초마다 자동 전환. 호버 시 일시 정지. |
| 클릭 | 공지 제목 또는 "자세히보기" 클릭 시 공지 상세 페이지 또는 외부 URL로 이동 (공지별 설정 가능) |
| 빈 상태 | 활성 공지가 없으면 배너 완전 숨김 — 빈 공간 없음 |
| 최대 표시 수 | 최신 발행 공지 5개 순환 |
| 닫기 기능 | 닫기 불가 — 공지가 있으면 항상 표시 |
| 모바일 | 전체 너비, 텍스트 잘림. 동일한 순환 동작. |

**필요한 신규 콘텐츠 타입:** `notice` — §16.1 참조

### 2.3 헤더

**위치:** 뷰포트 상단에 고정 (공지 배너 아래). 스크롤 중에도 표시 유지.

**레이아웃 (데스크톱 — 좌에서 우):**

```
┌─────────────────────────────────────────────────────────────────┐
│  [Swida 로고]  │  [검색바 + 🔍]  │  내비게이션 항목  │  인증     │
└─────────────────────────────────────────────────────────────────┘
```

#### 2.3.1 로고

- Swida 브랜드 로고 (주황색 "S" 아이콘 + "Swida" 텍스트)
- 클릭 → 홈페이지로 이동 (`/[locale]`)
- 대체 텍스트: "Swida - 마사지 & 웰니스 검색 플랫폼"

#### 2.3.2 검색바

**위치:** 헤더 중앙, 두드러진 배치.

**시각적 디자인:**
- 라운드 입력 필드, 플레이스홀더 텍스트: `t('header.search.placeholder')` → "지역, 업소명, 테마를 검색해보세요"
- 입력 필드 우측에 파란색 검색 아이콘 버튼 (🔍)

**동작:**

| 액션 | 결과 |
|---|---|
| 포커스 | 입력 활성화, 드롭다운 없음 |
| 입력 후 Enter 또는 🔍 클릭 | 이름 검색 결과로 이동: `/[locale]/search?q={query}` |
| 빈 채로 제출 | 동작 없음 (빈 검색 방지) |
| 최대 길이 | 100자 |

**유효성 검사:** 공백 제거. 제거 후 최소 1자 이상이어야 제출 가능.

#### 2.3.3 내비게이션 항목

메인 내비게이션은 4개 항목으로 구성됩니다. 두 항목은 드롭다운 서브 메뉴를 가집니다.

```
샵 검색 ▾   |   이벤트   |   게시판 ▾   |   제휴문의
```

**내비게이션 항목: 샵 검색 — 드롭다운**

| 하위 항목 | 레이블 | 경로 |
|---|---|---|
| 상세 검색 | 상세 검색 | `/[locale]/search` |
| 테마별 검색 | 테마별 검색 | `/[locale]/theme` |
| 지역 검색 | 지역별 검색 | `/[locale]/location` |
| 내주변 검색 | 내 주변 검색 | `/[locale]/nearby` |

> **Figma:** Drop_Down_샵검색

**내비게이션 항목: 이벤트 — 직접 링크**

경로: `/[locale]/events`

**내비게이션 항목: 게시판 — 드롭다운**

| 하위 항목 | 레이블 | 경로 |
|---|---|---|
| 샵 추천 | 샵 추천 | `/[locale]/board/recommendations` |
| 마사지 정보 | 마사지 정보 | `/[locale]/board/info` |
| 커뮤니티 | 커뮤니티 | `/[locale]/board/community` |

> **Figma:** Drop_Down_게시판

**내비게이션 항목: 제휴문의 — 직접 링크**

경로: `/[locale]/partnership`

**드롭다운 동작:**

| 항목 | 명세 |
|---|---|
| 트리거 | 내비게이션 항목 클릭으로 열기/닫기 토글 (호버 아님) |
| 외관 | 라운드 모서리, 미세한 그림자, 흰색 배경의 플로팅 패널 |
| 하위 항목 | 세로로 쌓임, 파란색 텍스트, 얇은 구분선으로 구분 |
| 닫기 | 외부 클릭, 상위 내비게이션 항목 재클릭, 또는 하위 항목 선택 |
| 활성 상태 | 현재 페이지의 내비게이션 항목이 시각적으로 강조됨 |
| 키보드 | Enter/Space로 토글. 방향키로 하위 항목 탐색. Escape로 닫기. |

#### 2.3.4 인증 버튼

**로그아웃 상태:**

헤더 우측에 두 개의 버튼:

| 버튼 | 스타일 | 액션 |
|---|---|---|
| 로그인 | 아웃라인 / 보조 | `/[locale]/auth/login`으로 이동 |
| 회원 가입 | 채워진 / 기본 (주황색) | `/[locale]/auth/signup`으로 이동 |

**로그인 상태:**

두 버튼 대신:

| 요소 | 액션 |
|---|---|
| 사용자 표시 이름 또는 아바타 | 클릭 → 드롭다운: 마이페이지, 내 리뷰, 로그아웃 |
| 로그아웃 | JWT 삭제, 홈페이지로 리다이렉트 |

### 2.4 푸터

> **Figma:** 메인 - Main (하단 섹션)

**위치:** 모든 페이지 콘텐츠 아래 페이지 하단. 고정 아님.

**레이아웃 (데스크톱 — 4열):**

```
┌────────────────────────────────────────────────────────────────┐

│                 │                │  서비스이용약관     │          │
│                 │                │  제휴문의          │          │
├────────────────────────────────────────────────────────────────┤
│  © 2026 SWIDA Co., Ltd. All Rights Reserved.                   │
└────────────────────────────────────────────────────────────────┘
```

**열 상세:**

| 열 | 내용 |
|---|---|
| Swida 브랜드 | Swida 로고 (어두운 배경에 흰색) + 태그라인: "전국 마사지 업소 정보 No.1 플랫폼 '스위다'" + SWIDA 미션에 관한 부가 텍스트 |
| 고객센터 | 전화번호: `1588-1234` (두드러지게 스타일링). 운영시간: "평일 09:00 - 18:00 (주말/공휴일 제외)" |
| 메뉴 | 링크: 이용안내, 개인정보처리방침, 서비스이용약관, 제휴문의 |
| SNS | 소셜 미디어 아이콘 버튼 (SWIDA 공식 계정 링크) |

**저작권:** 4열 아래 중앙 정렬: "© 2026 SWIDA Co., Ltd. All Rights Reserved."

**푸터 배경:** 어두운 네이비/차콜. 흰색 텍스트.

**모바일:** 세로로 쌓임 — 브랜드 → 고객센터 → 메뉴 → SNS → 저작권.

### 2.5 언어 전환기

**위치:** 미정 (현재 Figma에 표시되지 않음). 헤더 또는 푸터 우측 상단 배치 권장.

**동작:**

| 액션 | 결과 |
|---|---|
| "EN" / "한국어" 토글 클릭 | 다른 로케일의 동등한 페이지로 이동. 예: `/ko/shop/healing-spa` → `/en/shop/healing-spa` |
| URL 변경 | 로케일 세그먼트 변경, 다른 경로/쿼리 파라미터는 유지 |
| 콘텐츠 대체 | 번역 콘텐츠 없으면 한국어로 표시 + "번역 준비 중" 표시 |

### 2.6 반응형 브레이크포인트

| 브레이크포인트 | 이름 | 너비 | 레이아웃 변경 |
|---|---|---|---|
| `sm` | 모바일 | < 768px | 단일 열, 햄버거 메뉴, 카드 세로 쌓임 |
| `md` | 태블릿 | 768px–1023px | 2열 그리드, 압축 내비게이션 |
| `lg` | 데스크톱 | 1024px–1279px | 전체 내비게이션, 3-4열 그리드 |
| `xl` | 와이드 데스크톱 | ≥ 1280px | 최대 콘텐츠 너비 ~1200px, 중앙 정렬 |

**모바일 내비게이션 (< 768px):**
- 헤더가 로고 + 검색 아이콘 + 햄버거 메뉴 (☰)로 축소됨
- 햄버거를 누르면 모든 내비게이션 항목과 인증 버튼이 있는 전체화면 슬라이드인 드로어가 열림
- 드롭다운은 드로어에서 펼칠 수 있는 아코디언 섹션이 됨

### 2.7 전체 로딩 및 오류 상태

**페이지 수준 로딩:**
- 대상 페이지 레이아웃과 일치하는 스켈레톤 화면 (일반적인 스피너 아님)
- 헤더와 푸터는 즉시 렌더링; 페이지 콘텐츠 영역만 스켈레톤 표시

**페이지 수준 오류:**
- 콘텐츠 영역 중앙에 친절한 오류 메시지
- "다시 시도" 버튼
- 헤더와 푸터는 계속 작동

**네트워크 오류 / 오프라인:**
- 토스트 알림: "인터넷 연결을 확인해주세요"
- 사용 가능한 경우 캐시된 콘텐츠 유지 표시 (ISR/SSG 페이지)

**토스트 알림:**
- 위치: 헤더 아래 상단 중앙
- 4초 후 자동 닫힘
- 종류: 성공 (초록), 오류 (빨강), 정보 (파랑), 경고 (노랑)

## 3. 홈페이지

> **Figma:** 메인 - Main
> **경로:** `/[locale]` (예: `/ko`, `/en`)
> **렌더링:** SSG + ISR (revalidate: 300초)
> **SEO:** 색인됨, 사이트맵 포함

### 3.1 페이지 목적

홈페이지는 SWIDA의 주요 진입점입니다. 고객이 마사지 및 웰니스 샵을 찾을 수 있는 다양한 경로를 제공하는 탐색 허브 역할을 합니다: 테마별, 지역별, 근접성별, 큐레이션 편집 추천별. 관련 샵을 즉시 노출하고 탐색을 장려하도록 설계되었습니다.

### 3.2 데이터 소스

| 섹션 | API 엔드포인트 | 캐시 |
|---|---|---|
| 공지 배너 | `GET /api/notices?sort=createdAt:desc&filters[status][$eq]=published&pagination[pageSize]=5&locale={locale}` | Redis: 5분 |
| 히어로 배너 | `GET /api/banners?sort=display_order:asc&filters[status][$eq]=published&filters[placement][$eq]=homepage_hero&locale={locale}` | Redis: 5분 |
| 테마 그리드 | `GET /api/themes?sort=display_order:asc&locale={locale}&populate[icon][fields][0]=url` | Redis: 24시간 |

| 내 주변 샵 | `GET /api/shops/nearby?lat={lat}&lng={lng}&radius=5000&locale={locale}&pagination[pageSize]=4` | 캐시 없음 (GPS 의존) |
| 에디터 추천 | `GET /api/editorial-picks?sort=display_order:asc&filters[status][$eq]=published&pagination[pageSize]=3&locale={locale}` | Redis: 1시간 |

### 3.3 페이지 섹션 (위에서 아래)

#### 3.3.1 히어로 배너

**목적:** SWIDA의 가치 제안 또는 특집 캠페인을 소개하는 전체 너비 프로모션 배너.

**시각적 디자인:**
- 콘텐츠 영역에 걸친 전체 너비 이미지/그라디언트 배경
- 오버레이 텍스트 (좌측 정렬): 흰색, 굵은 헤드라인 텍스트 (예: "내 주변 가장 가까운 최고의 힐링 명소")
- CTA 버튼: 흰색 텍스트의 주황색 채워진 버튼 (예: "지금 바로 예약하기")
- 이미지는 라이프스타일/웰니스 비주얼

**동작:**

| 항목 | 명세 |
|---|---|
| 데이터 소스 | 관리자 관리 `banner` 콘텐츠 타입 (신규 — §16.2 참조) |
| 순환 | 배너가 여러 개인 경우: 6초마다 페이드 전환으로 자동 순환. 하단 점 표시기. |
| CTA 클릭 | 배너에 설정된 URL로 이동 (내부 페이지 또는 외부 링크 가능) |
| 단일 배너 | 순환 컨트롤 없음, 점 없음 |
| 빈 상태 | 게시된 배너가 없으면 SWIDA 브랜딩과 상세 검색으로 연결되는 "검색 시작하기" CTA가 있는 정적 기본 히어로 표시 |
| 모바일 | 동일한 레이아웃, 텍스트 크기 축소. CTA 버튼은 탭 가능하게 유지 (최소 44px 높이). |

**필요한 신규 콘텐츠 타입:** `banner` — §16.2 참조

#### 3.3.2 테마 그리드

**목적:** 모든 마사지/서비스 테마에 대한 원터치 접근 그리드.

**시각적 디자인:**
- 섹션에 별도 헤더 없음 (테마는 아이콘/레이블로 자명함)
- 그리드 레이아웃: 데스크톱에서 6열, 12개 테마를 위해 2행 × 6열로 배치
- 각 테마 셀: 위에 원형 아이콘 + 아래에 테마 이름 레이블
- 아이콘은 커스텀 일러스트레이션 (테마 콘텐츠 타입의 미디어로 저장)

**표시되는 테마 (Figma 기준):**
1행: 전체보기, 아로마, 한국마사지, 커플마사지, 스포츠, 발마사지
2행: 태국마사지, 홈케어, 스웨디시, 스톤테라피, 풀미용미, 중국마사지

**동작:**

| 액션 | 결과 |
|---|---|
| "전체보기" 클릭 | `/[locale]/theme`으로 이동 (모든 테마 표시) |
| 다른 테마 클릭 | `/[locale]/theme/{theme-slug}`로 이동 (해당 테마 샵 결과) |
| 호버 (데스크톱) | 아이콘 미세 확대 애니메이션 |

**상태:**

| 상태 | 표시 |
|---|---|
| 로딩 | 텍스트 플레이스홀더가 있는 12개 스켈레톤 원 |
| 로드됨 | 디자인대로 테마 그리드 |
| 오류 | 섹션 완전 숨김 (비핵심) — 오류 조용히 로깅 |

**모바일 (< 768px):** 4열, 3행. 필요 시 가로 스크롤 또는 줄바꿈.

#### 3.3.3 지역 빠른 선택 바 (지역별 마사지 찾기)

**목적:** 주요 지역의 샵에 원터치 접근, 상세 지역 검색 바로가기 제공.

**시각적 디자인:**
- 섹션 헤더: "지역별 마사지 찾기" (좌측 정렬)
- 헤더 우측: "상세검색+" 링크 (파란색 텍스트)
- 헤더 아래: 지역 칩/버튼의 가로 행
- 표시되는 칩 (Figma 기준): 서울, 경기, 인천, 부산, 대구, 광주, 대전, 울산
- 각 칩: 지역명이 있는 아웃라인 알약/버튼 스타일

**동작:**

| 액션 | 결과 |
|---|---|
| 지역 칩 클릭 | `/[locale]/location/{region-slug}`로 이동 (해당 지역으로 사전 필터링된 지역 검색 페이지) |
| "상세검색+" 클릭 | `/[locale]/search`로 이동 (상세 검색 페이지) |
| 가로 오버플로 (모바일) | 칩을 줄바꿈 없이 가로 스크롤 |

**데이터 소스:** `GET /api/regions`의 지역. 관리자가 표시 순서 설정 가능. 홈페이지에는 인기 상위 8개 지역만 표시 — 전체 목록은 지역별 검색 페이지에 있음.

#### 3.3.4 현재 위치 표시

**목적:** 감지된 고객의 위치를 표시하고 변경할 수 있도록 함.

**시각적 디자인:**
- 위치 핀 아이콘 (◎) + "현재 위치:" 레이블 + **굵은 위치 텍스트** (예: "서울 강남구 역삼동") + "변경" 링크 (주황색/빨간색 텍스트)

**동작:**

| 항목 | 명세 |
|---|---|
| GPS 요청 | 홈페이지 로드 시 `navigator.geolocation.getCurrentPosition()` 요청 |
| 권한 허용 | 좌표를 역지오코딩하여 가장 가까운 구/동 이름 획득 (Google Maps Geocoding API 또는 카카오 로컬 API 사용). "현재 위치: {구/동 이름}"으로 표시 |
| 권한 거부 | "현재 위치: 위치 정보를 사용할 수 없습니다" 표시 + 권한 대화상자를 다시 트리거하는 "위치 허용하기" 버튼 |
| 권한 대기 중 | "현재 위치: 위치 확인 중..." + 미세한 로딩 애니메이션 |
| "변경" 클릭 | 고객이 캐스케이딩 드롭다운 (LocationCascade 컴포넌트와 동일)에서 지역 및 구를 수동 선택할 수 있는 모달/드로어 열기. 아래 내 주변 샵 섹션을 그에 따라 업데이트. |
| 위치 변경 | 위치 변경 시 (GPS 또는 수동), 새 좌표 또는 선택한 구로 내 주변 샵 섹션 재요청 |

**역지오코딩:** 카카오 로컬 API (`GET https://dapi.kakao.com/v2/local/geo/coord2regioncode.json?x={lng}&y={lat}`)를 사용하여 GPS 좌표를 한국 행정 주소로 변환. `region_2depth_name` (구)와 `region_3depth_name` (동) 추출.

#### 3.3.5 내 주변 추천샵 (내 주변 추천샵 HOT!)

**목적:** 고객의 현재 위치 근처의 최고 평점 또는 가장 인기 있는 샵 표시.

**시각적 디자인:**
- 섹션 헤더: "내 주변 추천샵" + 좌측에 "HOT!" 뱃지 (빨강/주황), 우측에 "더보기→" 링크
- 4개 샵 카드의 가로 행 (데스크톱), 모바일에서는 스크롤 가능
- 샵 카드에는 썸네일에 뱃지 포함 (프리미엄, 신규)

**샵 카드 내용 (카드당):**

| 요소 | 데이터 소스 | 표시 |
|---|---|---|
| 썸네일 이미지 | `shop.thumbnail.url` | 직사각형 이미지, 라운드 모서리 |
| 뱃지 | `shop.is_premium`, `shop.is_new` (신규 필드 — §16.5 참조) | 썸네일 좌측 상단에 오버레이. `is_premium`이면 "프리미엄" (금색), `is_new`이면 "신규" (파란색) |
| 샵 이름 | `shop.name` | 이미지 아래 굵은 텍스트 |
| 위치 | `shop.district.name` | 회색 텍스트 (예: "서울 강남구 역삼동") |
| 평점 + 리뷰 수 | `shop.average_rating` + `shop.total_reviews` | "★ 4.9 (322)" |
| 원래 가격 | `shop.original_price` (신규 필드) | 취소선 회색 텍스트 (예: "~~40,000원~~") |
| 세일 가격 | `shop.sale_price` (신규 필드) | 굵은 컬러 텍스트 (예: "**30,000원 ~**") |

**동작:**

| 액션 | 결과 |
|---|---|
| 샵 카드 클릭 | `/[locale]/shop/{slug}`로 이동 |
| "더보기→" 클릭 | `/[locale]/nearby`로 이동 (내 주변 검색 페이지) |
| GPS 사용 불가 | 대체 표시: "위치 정보를 허용하면 내 주변 추천 매장을 확인할 수 있어요" + "위치 허용하기" 버튼 |
| 가로 스크롤 (모바일) | 카드를 단일 행에서 가로 스크롤 |

**데이터:** `pageSize=4`, 5km 반경 내 평점 내림차순으로 정렬된 내 주변 검색 API (`/api/shops/nearby`)에서 가져옴. GPS 좌표 필요.

**상태:**

| 상태 | 표시 |
|---|---|
| GPS 대기 중 | 펄싱 애니메이션이 있는 스켈레톤 카드 (4개) |
| GPS 허용됨, 데이터 로딩 | 스켈레톤 카드 |
| 로드됨 | 디자인대로 4개 샵 카드 |
| 반경 내 결과 없음 | 메시지: "주변에 등록된 매장이 없습니다. 다른 지역을 검색해보세요." |
| GPS 거부됨 | 권한 요청 버튼이 있는 대체 메시지 |
| API 오류 | 섹션 숨김 — 오류 로깅 |

**필요한 신규 데이터 모델 필드:** `original_price`, `sale_price`, `is_premium`, `is_new` — §16.5 참조

#### 3.3.6 에디터 추천 (Swida 추천샵 Editor's Choice)

**목적:** 테마별 샵 컬렉션을 소개하는 관리자 큐레이션 편집 추천.

**시각적 디자인:**
- 섹션 헤더: "**Swida 추천샵**" + "**Editor's Choice**" (부제목/뱃지 스타일)
- 가로 행에 3개의 편집 카드 (데스크톱)
- 각 카드는 세로/세로 방향:
  - 큰 배경 이미지 (텍스트 가독성을 위한 어두운 오버레이)
  - 이미지 좌측 하단에 뱃지 태그: "BEST THEME", "RECOMMEND", "NEW OPEN" (컬러 알약 뱃지)
  - 이미지 하단에 오버레이된 제목 텍스트 (흰색, 굵음) (예: "지친 하루의 끝, 커플 스파로 힐링하세요")
  - 제목 아래 설명 텍스트 (흰색, 작음) (예: "강남권 최고의 분위기를 자랑하는 커플 전용 스파 베스트 5를 소개합니다.")
- 3개 카드 아래: 중앙 정렬된 "더보기" 버튼 (아웃라인)

**동작:**

| 액션 | 결과 |
|---|---|
| 편집 카드 클릭 | 편집 상세 페이지로 이동: `/[locale]/board/recommendations/{slug}` 또는 각 피크에 설정된 커스텀 URL |
| "더보기" 클릭 | `/[locale]/board/recommendations`로 이동 (샵 추천 게시판) |
| 호버 (데스크톱) | 시각적 피드백을 위한 약간의 이미지 줌 / 밝기 변화 |

**데이터 소스:** `editorial-pick` 콘텐츠 타입 (신규 — §16.3 참조). 관리자가 제목, 설명, 이미지, 뱃지 태그, 링크 URL, 표시 순서로 각 픽을 생성.

**상태:**

| 상태 | 표시 |
|---|---|
| 로딩 | 그라디언트 플레이스홀더가 있는 3개 스켈레톤 카드 |
| 로드됨 | 디자인대로 카드 |
| 비어있음 (게시된 픽 없음) | 섹션 완전 숨김 |
| 오류 | 섹션 숨김 — 오류 로깅 |

**모바일 (< 768px):** 카드 세로 쌓임 (행당 1개, 전체 너비) 또는 스냅 스크롤이 있는 가로 캐러셀.

#### 3.3.7 지역별 마사지 추천

**목적:** 인기 지역별로 구성된 큐레이션 샵 컬렉션 강조 표시.

**시각적 디자인:**
- 섹션 헤더: "지역별 마사지 추천"
- 2개의 가로 카드 (데스크톱) — 더 넓은/가로 형식
- 각 카드 레이아웃:
  - 좌측: 썸네일 이미지 (지역/분위기 사진)
  - 우측: 제목 (굵음, 예: "강남구 최고 인기샵"), 설명 텍스트, 해시태그 칩 (예: #압구정, #신사, #한남)
- 카드 아래: 중앙 정렬된 "더보기" 버튼 (아웃라인)

**동작:**

| 액션 | 결과 |
|---|---|
| 지역 카드 클릭 | 해당 지역 페이지 또는 큐레이션 목록으로 이동: `/[locale]/location/{region-slug}/{district-slug}` 또는 커스텀 URL |
| 해시태그 칩 클릭 | 해당 지역 또는 태그로 필터링된 검색으로 이동 |
| "더보기" 클릭 | `/[locale]/location`으로 이동 (지역별 검색 페이지) |

**데이터 소스:** `region-recommendation` 콘텐츠 타입 (신규 — §16.4 참조). 관리자가 제목, 설명, 이미지, 해시태그, 연결된 지역/구, 표시 순서로 각 추천을 생성.

**상태:**

| 상태 | 표시 |
|---|---|
| 로딩 | 2개 스켈레톤 카드 |
| 로드됨 | 디자인대로 카드 |
| 비어있음 | 섹션 완전 숨김 |
| 오류 | 섹션 숨김 — 오류 로깅 |

**모바일 (< 768px):** 카드 세로 쌓임 (행당 1개, 전체 너비).

### 3.4 홈페이지 데이터 페칭 전략

**서버 사이드 (SSG/ISR — 빌드 타임 + 재검증 시 실행):**
- 히어로 배너
- 테마 그리드

## 4. 상세 검색 페이지

> **Figma:** 상세검색 - Advanced Search
> **경로:** `/[locale]/search`
> **렌더링:** SSR (동적 필터로 인해 SSG 비실용적)
> **SEO:** `noindex` (쿼리 파라미터가 있는 필터링된 결과)

### 4.1 페이지 목적

상세 검색 페이지는 가장 포괄적인 검색 모드입니다. 키워드 검색, 위치 필터링, 편의시설 토글, 테마 선택 및 가격 범위를 단일 인터페이스로 결합합니다. 파워 유저 검색 도구이자 헤더 검색바 및 "상세검색+" 링크의 도착지입니다.

### 4.2 서브 내비게이션 바

모든 검색 페이지는 헤더 바로 아래에 가로 탭 바를 공유합니다. 이 서브 네비게이션은 6가지 검색/콘텐츠 모드 간 빠른 전환을 제공합니다.

**탭 (좌에서 우):**

| 탭 | 레이블 | 경로 | 아이콘 |
|---|---|---|---|
| 상세 검색 | 상세 검색 | `/[locale]/search` | 🔍 |
| 테마별 검색 | 테마별 검색 | `/[locale]/theme` | 🏷️ |
| 지역별 검색 | 지역별 검색 | `/[locale]/location` | 📍 |
| 내 주변 검색 | 내 주변 검색 | `/[locale]/nearby` | 📡 |
| 방문 후기 | 방문 후기 | `/[locale]/reviews` | ✍️ |
| 업소 제휴 | 업소 제휴 | `/[locale]/partnership` | 💎 |

**동작:**
- 활성 탭은 주황색/채워진 배경으로 강조됨
- 탭 클릭 시 해당 페이지로 이동
- 모바일 (< 768px): 탭이 넘칠 경우 가로 스크롤 가능

> **PRD 차이점:** 서브 네비게이션에는 헤더 네비게이션 드롭다운에 없는 "방문 후기"와 "업소 제휴"가 포함됩니다. 이것들은 방문 후기 피드 및 제휴문의 페이지로의 대체 탐색 경로를 제공합니다.

### 4.4 필터 사이드바 (좌측 패널)

**헤더:** "필터" 아이콘 + "필터" 텍스트 + "초기화" 리셋 링크 (우측 정렬)

**필터 그룹 (위에서 아래):**

#### 4.4.1 키워드 검색
- 플레이스홀더 "업소명 검색"이 있는 검색 입력
- 좌측에 돋보기 아이콘
- 샵 이름으로 검색 (`$containsi`)

#### 4.4.2 지역 선택
- 두 개의 캐스케이딩 드롭다운:
  - 레벨 1: "시/도 전체" → 지역 선택
  - 레벨 2: "시/군/구 전체" → 선택된 지역에 따라 동적으로 구 로드
- 레벨 1이 선택될 때까지 레벨 2는 비활성화

#### 4.4.3 서비스 혜택
편의시설/기능 필터 체크박스 목록:

| 체크박스 | API 필터 | 설명 |
|---|---|---|
| 24시간 영업 | `filters[is_24hr][$eq]=true` | 24시간 운영 (신규 필드 필요) |
| 주차가능 | `filters[amenities][parking_available][$eq]=true` | 주차 가능 |
| 샤워가능 | `filters[amenities][shower][$eq]=true` | 샤워 시설 |
| 수면가능 | `filters[amenities][sleeping][$eq]=true` | 수면 공간 |
| 개인실 | `filters[amenities][private_room][$eq]=true` | 개인실 |
| Wifi | `filters[amenities][wifi][$eq]=true` | 무료 WiFi |
| 예약필수 | `filters[booking_required][$eq]=true` | 예약 필수 |

#### 4.4.4 테마
- 다중 선택 토글 칩/알약
- 모든 테마가 작은 알약 버튼으로 표시 (예: 스웨디시, 로미로미, 발마사지, 중국, 한국, 커플, 스포츠, 아로마, 홈케어, 타이, 스톤)
- 선택된 테마는 주황색 아웃라인으로 강조됨
- 여러 테마 선택 가능 (테마 내 OR 논리, 다른 필터와는 AND 논리)

#### 4.4.5 가격대
- 두 핸들이 있는 범위 슬라이더
- 최소: 0원, 최대: 20만원+
- 선택된 범위를 필터로 표시
- API: `filters[sale_price][$gte]=min&filters[sale_price][$lte]=max`

#### 4.4.6 검색 버튼
- 전체 너비 주황색 버튼: "검색하기"
- 클릭 시 선택된 모든 필터 적용 및 결과 새로고침
- 필터는 URL 쿼리 파라미터에 유지됨

**"초기화" 동작:** 모든 필터 선택 지우기, 드롭다운을 기본값으로 초기화, 키워드 입력 지우기, 가격 범위 초기화. 자동으로 재검색하지 않음 — 사용자가 "검색하기"를 클릭해야 함.

### 4.5 결과 영역 (우측 패널)

#### 4.5.1 결과 헤더
- 텍스트: "상세 검색 결과 총 **{count}**개" — `meta.pagination.total`의 수
- 활성 필터 칩이 제거 가능한 태그로 표시: 예: `[강남구 ✕]` `[스웨디시 ✕]` `[24시간 ✕]`
- 칩의 ✕ 클릭 시 해당 필터 제거 및 결과 재요청

#### 4.5.2 정렬 옵션
우측 정렬 정렬 링크:

| 정렬 | 레이블 | API 파라미터 | 기본값 |
|---|---|---|---|
| 평점 높은순 | 평점 높은순 | `sort=average_rating:desc` | ✓ (기본, 강조됨) |
| 리뷰 많은순 | 리뷰 많은순 | `sort=total_reviews:desc` | |
| 추천순 | 추천순 | `sort=recommendation_score:desc` | |
| 가격 낮은순 | 가격 낮은순 | `sort=sale_price:asc` | |

활성 정렬 옵션은 주황색/굵게 스타일링.

#### 4.5.3 샵 카드 (검색 결과 카드)

3열 그리드의 각 카드 포함:

| 요소 | 데이터 | 표시 |
|---|---|---|
| 썸네일 | `shop.thumbnail.url` | 큰 직사각형 이미지, 라운드 모서리 |
| 뱃지 | `shop.is_premium` / `shop.is_new` | `is_premium`이면 "PREMIUM" (금색), 관리자 추천이면 "BEST" (빨강, §16.5 참조), `is_new`이면 "신규" |
| 즐겨찾기 하트 | 클릭으로 저장/취소 | 이미지 우측 상단 하트 아이콘 (♡/♥). 로그인 필요. |
| 샵 이름 | `shop.name` | 이미지 아래 굵은 텍스트 |
| 평점 | `shop.average_rating` | "★ 4.9" 주황색 별 + 숫자 (이름 우측) |
| 위치 | `shop.district.name` | "📍 서울 강남구 청담동" 회색 텍스트 |
| 테마 태그 | `shop.themes[].name` | 작은 회색 알약 태그 (예: "아로마", "주차가능", "샤워실") |
| 가격 레이블 | "회원가" | 작은 회색 레이블 |
| 세일 가격 | `shop.sale_price` | 굵은 주황색 텍스트: "**30,000원 ~**" |

**카드 클릭:** `/[locale]/shop/{slug}`로 이동
**하트 클릭:** 로그인 시 → 즐겨찾기 토글 (API 호출). 미로그인 시 → 로그인 페이지로 리다이렉트.

#### 4.5.4 페이지네이션
- 이 Figma 화면에는 표시되지 않지만 결과 수로 암시됨 (1,234개 결과)
- SEO를 위한 페이지 기반 페이지네이션 (페이지별 고유 URL)
- URL 패턴: `/[locale]/search?...&page=2`

| API 오류 | "검색 중 오류가 발생했습니다. 다시 시도해주세요." + 재시도 버튼 |

### 4.8 인수 기준

| # | 기준 | 우선순위 |
|---|---|---|
| DS-01 | 모든 필터 유형 (키워드, 위치, 편의시설, 테마, 가격)이 올바르게 결과를 필터링 | P0 |
| DS-02 | 캐스케이딩 위치 드롭다운 작동 — 레벨 2가 레벨 1 선택 후 로드됨 | P0 |
| DS-03 | 활성 필터가 결과 위에 제거 가능한 칩으로 표시됨 | P0 |
| DS-04 | "초기화"가 모든 필터를 기본 상태로 리셋 | P1 |
| DS-05 | 정렬 옵션이 결과 순서를 변경하고 URL에 유지됨 | P0 |
| DS-06 | 필터 상태가 URL 쿼리 파라미터에 유지됨 | P0 |
| DS-07 | 샵 카드가 올바른 샵 상세 페이지로 이동 | P0 |
| DS-08 | 즐겨찾기 하트가 로그인 필요, 로그인 시 올바르게 토글됨 | P1 |
| DS-09 | 가격 범위 슬라이더가 sale_price로 결과를 필터링 | P1 |
| DS-10 | 결과가 2초 이내에 로드됨 | P0 |

### 4.9 필요한 신규 데이터 모델 필드

| 필드 | 콘텐츠 타입 | 설명 |
|---|---|---|
| `is_24hr` | 샵 | 불리언 — 샵이 24시간 운영하는지 여부. 주요 필터로 사용. |
| `recommendation_score` | 샵 | 정수 — "추천순" 정렬을 위한 관리자 관리 또는 알고리즘으로 계산된 점수. |

## 5. 테마별 검색 페이지

> **Figma:** 테마별 검색 - Theme-based Search
> **경로:** `/[locale]/theme` (전체 테마) 또는 `/[locale]/theme/{theme-slug}` (테마별 필터)
> **렌더링:** 테마 목록 페이지는 SSG; 필터링된 결과는 SSR
> **SEO:** 테마 목록 페이지 및 개별 테마 페이지 색인됨

### 5.1 페이지 목적

테마별 검색 페이지는 고객이 마사지/서비스 테마별로 샵을 탐색할 수 있도록 합니다. 위에 전체 테마 그리드가 있어 탐색할 수 있고, 아래에 선택된 테마로 필터링된 결과가 표시됩니다.

### 5.2 레이아웃

상세 검색 (§4.3)과 동일하나 추가 사항: **테마 그리드**가 서브 내비게이션 바와 필터/결과 영역 사이에 표시됩니다.

### 5.3 테마 그리드 (상단 섹션)

- 홈페이지 (§3.3.2)와 동일한 테마 그리드 — 2행 × 6열의 12개 테마
- 현재 선택된 테마는 주황색 아웃라인/배경으로 강조됨
- "전체보기"는 모든 샵 표시 (테마 필터 없음)
- 다른 테마 클릭 시 결과 즉시 재필터링

### 5.4 필터 사이드바

상세 검색 (§4.4)과 동일한 필터 사이드바이나 "테마" 섹션 없음 (테마는 상단 그리드를 통해 선택되므로). 포함: 키워드 검색, 위치 선택, 서비스 혜택, 가격대, 검색 버튼.

### 5.5 결과 영역

상세 검색 (§4.5)과 동일한 구조:
- 결과 헤더: "**아로마** 검색 결과 총 **1,004**개" — 선택된 테마 이름 표시
- 활성 필터 칩
- 정렬 옵션 (동일한 4개 옵션)
- 샵 카드 그리드 (3열)
- 페이지네이션

### 5.5.1 데이터 소스

| 데이터 | API 엔드포인트 |
|---|---|
| 테마 목록 | `GET /api/themes?sort=display_order:asc&locale={locale}&populate[icon][fields][0]=url` |
| 샵 결과 | `GET /api/shops?filters[themes][slug][$eq]={theme-slug}&locale={locale}&sort=average_rating:desc&pagination[page]={page}&pagination[pageSize]=9` + 추가 사이드바 필터 |

### 5.6 동작

| 액션 | 결과 |
|---|---|
| 그리드에서 테마 클릭 | URL이 `/[locale]/theme/{theme-slug}`로 변경되고, 결과가 해당 테마로 필터링되며, 사이드바 필터 초기화 |
| "전체보기" 클릭 | URL이 `/[locale]/theme`로 변경, 모든 샵 표시 |
| 사이드바 필터 적용 | 선택된 테마에 추가 필터 적용 |
| 테마 미선택 (첫 방문) | 테마 그리드만 표시, 사용자에게 테마 선택 안내 |

### 5.7 SEO 메타데이터

개별 테마 페이지 (`/[locale]/theme/{theme-slug}`)는 다음으로 색인됩니다:
- 제목: "{테마 이름} 마사지 - SWIDA"
- 설명: "{테마 이름} 마사지 매장을 찾아보세요. 전국 {count}개 매장 정보와 리뷰를 확인하세요."

### 5.8 인수 기준

| # | 기준 | 우선순위 |
|---|---|---|
| TS-01 | 테마 그리드에 모든 테마와 아이콘이 표시됨 | P0 |
| TS-02 | 테마 선택 시 결과가 올바르게 필터링됨 | P0 |
| TS-03 | 선택된 테마가 그리드에서 시각적으로 강조됨 | P0 |
| TS-04 | 사이드바 필터가 선택된 테마와 조합하여 작동 | P0 |
| TS-05 | 테마 페이지 URL이 크롤 가능하고 색인됨 | P0 |

### 5.9 상태

| 상태 | 표시 |
|---|---|
| 첫 방문 (테마 미선택) | 테마 그리드 표시, 결과 영역에 안내문: "테마를 선택해주세요" |

## 6. 지역별 검색 페이지

> **Figma:** 지역별 검색 - Region-based Search
> **경로:** `/[locale]/location` 또는 `/[locale]/location/{region-slug}` 또는 `/[locale]/location/{region-slug}/{district-slug}`
> **렌더링:** 지역/구 조합 페이지는 SSG; 필터링된 결과는 SSR
> **SEO:** 지역 페이지 색인됨 (지역/구별 크롤 가능 URL)

### 6.1 페이지 목적

지역별 검색 페이지는 고객이 지리적 지역별로 샵을 탐색할 수 있도록 합니다. 빠른 레벨 1 선택을 위한 지역 칩 바가 상단에 있고, 아래에 선택된 지역 (및 선택적으로 구)으로 필터링된 결과가 표시됩니다.

### 6.2 레이아웃

상세 검색 (§4.3)과 동일하나 추가 사항: **지역 칩 바**가 서브 내비게이션 바와 필터/결과 영역 사이에 표시됩니다.

### 6.3 지역 칩 바 (상단 섹션)

**헤더:** "지역별 마사지 찾기" (좌측) + "상세검색+" 링크 (우측)

**칩:** 가로 행의 지역 알약 — 전체, **서울** (강조됨), 경기, 인천, 부산, 대구, 광주, 대전

| 액션 | 결과 |
|---|---|
| 지역 칩 클릭 | URL이 `/[locale]/location/{region-slug}`로 변경되고, 결과가 해당 지역으로 필터링됨. 사이드바의 레벨 2 드롭다운이 선택된 지역의 구를 표시하도록 업데이트. |
| "전체" 클릭 | 모든 샵 표시, 지역 필터 없음 |
| "상세검색+" 클릭 | `/[locale]/search`로 이동 (상세 검색) |

**활성 상태:** 선택된 지역 칩은 주황색 채워진 배경 (다른 것들은 아웃라인).

### 6.4 필터 사이드바

상세 검색 (§4.4)과 동일한 필터 사이드바에 **전체 필터 세트** 포함: 키워드 검색, 위치 선택, 서비스 혜택 (체크박스), 테마 칩, 가격대, 검색 버튼. **사이드바의 레벨 1 드롭다운은 지역 칩 바와 동기화됩니다** — 지역 칩 선택 시 레벨 1 드롭다운이 자동 업데이트되며 반대도 동일. 테마 검색 (§5)과 달리, 이 페이지에서는 테마가 최상위 선택기로 이미 표현되지 않으므로 테마 칩 섹션이 포함됩니다.

### 6.5 결과 영역

상세 검색 (§4.5)과 동일한 구조:
- 결과 헤더: "**서울 강남구** 검색 결과 총 **1,004**개"
- 활성 필터 칩
- 정렬 옵션 (동일한 4개 옵션)
- 샵 카드 그리드 (3열)
- 페이지네이션

### 6.5.1 데이터 소스

| 데이터 | API 엔드포인트 |
|---|---|
| 지역 목록 | `GET /api/regions?sort=display_order:asc&locale={locale}` |
| 구 목록 | `GET /api/districts?filters[region][slug][$eq]={region-slug}&locale={locale}` |
| 샵 결과 | `GET /api/shops?filters[region][slug][$eq]={region-slug}&filters[district][slug][$eq]={district-slug}&locale={locale}&sort=average_rating:desc&pagination[page]={page}&pagination[pageSize]=9` + 추가 사이드바 필터 |

### 6.6 SEO 메타데이터

지역 페이지는 다음으로 색인됩니다:
- 제목: "{지역} {구} 마사지 - SWIDA" (예: "서울 강남구 마사지 - SWIDA")
- `/ko`와 `/en` 버전 모두 사이트맵에 포함

### 6.7 인수 기준

| # | 기준 | 우선순위 |
|---|---|---|
| LS-01 | 지역 칩 바에 모든 주요 지역이 표시됨 | P0 |
| LS-02 | 지역 선택 시 결과가 필터링되고 사이드바 드롭다운과 동기화됨 | P0 |

| LS-05 | 지역 페이지 URL이 두 로케일 모두에 대한 사이트맵에 색인됨 | P0 |

### 6.8 상태

| 상태 | 표시 |
|---|---|
| 첫 방문 (지역 미선택) | "전체"가 활성화된 지역 칩 바, 모든 샵 표시 |
| 지역 선택됨, 로딩 | 그리드 레이아웃의 스켈레톤 카드 (9개) |

## 7. 내 주변 검색 페이지

> **Figma:** 내주변 검색 - Popular Area Search
> **경로:** `/[locale]/nearby`
> **렌더링:** CSR (GPS 의존, 완전 동적)
> **SEO:** `noindex` (동적, 개인화된 콘텐츠)

### 7.1 페이지 목적

내 주변 검색 페이지는 지도 + 목록 분할 뷰로 GPS 기반 샵 탐색을 제공합니다. 고객은 지도에 표시된 샵과 거리순으로 정렬된 스크롤 가능한 목록을 함께 볼 수 있습니다.

### 7.2 레이아웃

```
┌──────────────────────────────────────────────────────────┐

├──────────────────────────────────────────────────────────┤
│  현재 위치: 서울 강남구 역삼동  [변경]                       │
│  브레드크럼: 서울 > 강남구 > 역삼동 > 주변 샵               │
├───────────────────────────┬──────────────────────────────┤
│                           │  주변 추천 샵  12개            │
│                           │  정렬: [거리순] 추천순 가격순   │
│       인터랙티브 지도      ├──────────────────────────────┤
│    (Google Maps / Kakao)  │  샵 목록 카드 1 (450m)        │
│                           │  샵 목록 카드 2 (820m)        │
│    핀과 이름 레이블로      │  샵 목록 카드 3 (1.2km)       │
│    표시된 샵              │  샵 목록 카드 4 (1.5km)       │
│                           │                              │
│                           │  [결과 더보기 (4/12)]          │
├───────────────────────────┴──────────────────────────────┤
│  푸터                                                     │
└──────────────────────────────────────────────────────────┘
```

### 7.3 현재 위치 바

홈페이지 현재 위치 표시 (§3.3.4)와 동일한 동작:
- "변경" 버튼이 있는 감지된 위치 표시
- 페이지 로드 시 GPS 요청
- 브레드크럼 경로: 서울 > 강남구 > 역삼동 > 주변 샵

### 7.4 지도 패널 (좌측)

**지도 제공자:** Google Maps 또는 Kakao Map (관리자 웹과의 일관성을 위해 동일하게 사용)

**기능:**

| 기능 | 명세 |
|---|---|
| 중심 | 사용자의 GPS 좌표 |
| 줌 레벨 | 반경 내 모든 결과를 표시하도록 자동 조정, 또는 기본 줌 ~14 |
| 샵 핀 | 각 주변 샵이 지도에 컬러 핀/마커로 표시됨 |
| 핀 레이블 | 각 핀 옆에 샵 이름 레이블 표시 (예: "더 원 테라피", "아모레 테라피") |
| 핀 레이블 스타일 | 흰색 텍스트의 주황색/어두운 라운드 알약 |

| 줌 컨트롤 | +/- 버튼 (지도 우측 상단) |
| 내 위치 버튼 | 타겟 아이콘 (⊙) 버튼으로 사용자의 GPS 위치로 재중심화 |
| 지도 인터랙션 | 드래그 가능, 줌 가능. 지도 이동 시 재검색 없음 (검색은 지도 범위 기반이 아닌 GPS 기반) |

### 7.5 샵 목록 패널 (우측)

**헤더:** "주변 추천 샵" + "**12개**" 수 (주황색)

**정렬 탭:**

| 정렬 | 레이블 | API 파라미터 | 기본값 |
|---|---|---|---|
| 거리순 | 거리순 | `sort=distance:asc` (커스텀 컨트롤러) | ✓ (기본, 주황색 강조됨) |
| 추천순 | 추천순 | `sort=recommendation_score:desc` | |
| 가격순 | 가격순 | `sort=sale_price:asc` | |

**샵 목록 카드 (가로 레이아웃):**

각 카드는 가로 행 (다른 페이지의 세로 그리드 카드와 다름):

| 요소 | 데이터 | 위치 |

| 샵 이름 | `shop.name` | 이미지 우측 상단, 굵음 |
| 평점 + 리뷰 수 | "★ 4.8 (128)" | 이름 아래 |
| 해시태그 | `shop.themes[].name` + 편의시설 플래그에서 파생 | 예: "#강남구 #스웨디시 #아로마 #커플환영" |
| 거리 | API `distance` 필드에서 계산 | 우측 정렬, 주황색 텍스트 |
| 원래 가격 (취소선) | `shop.original_price` | 우측 하단, 회색 취소선 |
| 세일 가격 | `shop.sale_price` | 우측 하단, 굵은 주황색 |

**카드 클릭:** `/[locale]/shop/{slug}`로 이동

**"결과 더보기" 버튼:**
- 목록 하단에 표시: "결과 더보기 (4/12)" — 현재 수 / 전체 수 표시
- 클릭 시 다음 배치 결과 로드 (목록에 추가, 페이지 전환 아님)
- 이것은 **더 보기 페이지네이션** (페이지 기반 아님) — 페이지가 CSR이고 `noindex`이므로

### 7.6 지도-목록 인터랙션

### 8.3 브레드크럼

경로: `{지역} > {구} > {동/지역} > {샵 이름}`
예시: "서울 > 동대문구 > 장안동 > 골드문"

각 브레드크럼 세그먼트는 클릭 가능하며 해당 지역별 검색 페이지로 이동합니다.

### 8.4 이미지 갤러리

**레이아웃:** 메인 큰 이미지 (좌측) + 썸네일 그리드 (우측, 2열 × 2-3행)

| 요소 | 명세 |
|---|---|
| 메인 이미지 | `shop.images`의 가장 큰 이미지, 두드러지게 표시 |
| 썸네일 그리드 | 다음 4-5개의 이미지가 작은 썸네일로 표시 |
| "+12 더보기" 오버레이 | 이미지가 6개 이상인 경우, 마지막 썸네일에 "+{count} 더보기" 오버레이 표시 |
| 메인 이미지 클릭 | 전체화면 이미지 라이트박스/갤러리 열기 |
| 썸네일 클릭 | 메인 이미지를 클릭한 썸네일로 교체 |
| "+더보기" 클릭 | 해당 이미지부터 시작하는 전체화면 갤러리 열기 |
| 즐겨찾기 하트 (♡) | 메인 이미지 우측 상단. 즐겨찾기 토글. 로그인 필요. |

### 8.5 샵 정보 섹션

**샵 이름:** 큰 헤딩 텍스트 (예: "골드문 스웨디시 & 테라피")

**즐겨찾기 수:** "♡ 207" — 하트 아이콘 + 수, 샵 이름과 같은 줄 우측 정렬

**평점 + 리뷰 수:** "★ 4.9  리뷰 128개" — 주황색 별, 평점 숫자, 리뷰 수 링크 ("리뷰 128개" 클릭 시 리뷰 탭으로 스크롤)

**상세 정보 (아이콘 + 텍스트 행):**

| 아이콘 | 콘텐츠 | 데이터 소스 |
|---|---|---|
| 📍 | 전체 주소 (예: "서울 동대문구 장안동 123-45 (장한평역 2번출구)") | `shop.address` |
| 🕐 | 운영 시간 (예: "매일 11:00 ~ 익일 05:00 (연중무휴)") | `shop.operating_hours` + `shop.closed_days` |
| 🅿️ | 주차 정보 (예: "건물 지하 무료 주차 가능") | `shop.amenities.parking_detail` |
| ✓ | 편의시설 요약 (예: "남녀공용, 개인실 완비") | 편의시설 컴포넌트에서 파생 |

**해시태그 태그:** 주요 기능을 요약한 회색 알약 태그 행:
예: `#24시간` `#주차가능` `#샤워실완비` `#커플환영` `#역세권`
샵 편의시설 및 기능에서 파생. 태그 클릭 시 해당 기능으로 필터링된 상세 검색으로 이동.

**컴포넌트 (위에서 아래):**

#### 8.6.1 지도 버튼

#### 8.6.2 가격 표시
- 원래 가격 (취소선, 작음, 회색): "~~80,000원~~"
- 레이블: "회원가"
- 세일 가격 (크게, 굵음, 주황색): "**60,000원 ~**"

#### 8.6.3 서비스 카테고리 탭
- 서비스 카테고리 간 전환을 위한 가로 탭
- 예: `[스웨디시]` `[타이/아로마]`
- 각 탭은 해당 카테고리의 서비스 메뉴 항목을 표시

#### 8.6.4 코스/서비스 목록
선택된 카테고리의 서비스 표:

| 열 | 예시 |
|---|---|
| 코스명 | "A코스 (60분)" |
| 가격 | "80,000원" |

#### 8.6.5 예약 CTA

| 전화 예약하기 | 주황색 채워짐, 전화 아이콘 | 모바일에서 전화 다이얼러 열기 (`tel:{shop.phone_number}`); 데스크톱에서 전화번호 표시 |
| 문자 예약하기 | 주황색 아웃라인, 메시지 아이콘 | 모바일에서 SMS 열기 (`sms:{shop.phone_number}`); 데스크톱에서 전화번호 표시 |

샵 정보 섹션 아래 가로 탭 바:

|---|---|---|

| 이벤트 (2) | 이벤트 | 샵별 이벤트/프로모션 (괄호 안 수). 신규 기능 — §16.6 참조 |

**기본 탭:** 리뷰 (Figma에 표시된 대로 — 리뷰 탭이 활성화되어 주황색)

### 8.7.1 가격&코스 탭 콘텐츠

**목적:** 카테고리별로 그룹화된 모든 이용 가능한 코스/서비스를 보여주는 전체 서비스 메뉴.

**레이아웃:**
- 카테고리 헤더로 그룹화된 서비스 (예: "스웨디시", "타이/아로마") — 예약 사이드바 탭 (§8.6.3)과 동일한 카테고리
- 각 서비스 행:

| 요소 | 데이터 소스 | 표시 |
|---|---|---|
| 서비스명 | `service_menu_item.name` | 예: "A코스 (60분)" |
| 시간 | `service_menu_item.duration` | 예: "60분" |
| 가격 | `service_menu_item.price` | 예: "80,000원" |
| 설명 | `service_menu_item.description` | 선택적 — 서비스명 아래 간략한 텍스트 |

- 상단에 원래/세일 가격 표시기 (예약 사이드바와 동일)
- 서비스 메뉴 항목이 없으면: "서비스 정보가 등록되지 않았습니다."

### 8.7.2 이벤트 탭 콘텐츠

**목적:** 샵별 프로모션 및 이벤트 표시.

**레이아웃:**
- 각 이벤트 카드:

| 요소 | 데이터 소스 | 표시 |
|---|---|---|
| 이벤트 이미지 | `shop_event.image.url` | 배너 이미지 (선택적 — 이미지 없으면 플레이스홀더 표시) |
| 이벤트 제목 | `shop_event.title` | 굵은 헤딩 |
| 이벤트 설명 | `shop_event.description` | 본문 텍스트 |
| 이벤트 기간 | `shop_event.start_date` – `shop_event.end_date` | "2026.03.15 ~ 2026.04.15" (기간 설정 시) |

- 탭 레이블에 괄호 안 수 표시: "이벤트 (2)"
- 데이터 소스: `GET /api/shop-events?filters[shop][slug][$eq]={slug}&filters[status][$eq]=published&sort=createdAt:desc&locale={locale}`
- 이벤트가 없으면: "현재 진행 중인 이벤트가 없습니다."

### 8.7.3 이용안내 탭 콘텐츠

**목적:** 추가 이용 정보 — 안내, 정책, 규정, 참고 사항.

**레이아웃:**
- 샵의 `usage_guide` 필드 (신규 필드 — Text/Long 또는 Rich Text)에서 렌더링된 자유 형식 리치 텍스트 콘텐츠
- 일반적인 콘텐츠: 상세 안내, 주차 안내, 예약 정책, 취소 정책, 연령 제한, 단체 예약 정보 등
- 콘텐츠가 없으면: "이용안내가 등록되지 않았습니다."

**필요한 신규 데이터 모델 필드:** `usage_guide` — `shop` 콘텐츠 타입의 Text (Long) 또는 Rich Text 필드.

### 8.8 리뷰 탭 콘텐츠

#### 8.8.1 리뷰 요약
- "전체 평점" 레이블 + "★ 4.9" (주황색)
- "리뷰 작성+" 링크 (우측 정렬, 주황색) → 리뷰 제출 폼 열기 (로그인 필요)

#### 8.8.2 리뷰 목록
각 리뷰 카드:

| 요소 | 데이터 |
|---|---|
| 작성자 아바타 | 이니셜이 있는 원 (예: "김") |
| 작성자 닉네임 | 예: "힐링마스터" |
| 뱃지 | 예: "2회 첨" (2회 방문) |
| 날짜 | 상대적: "2일 전", "1주일 전" |
| 별 평점 | 5개 주황색 별 (채워짐/비어있음) |
| 리뷰 텍스트 | 전체 리뷰 본문 |
| 신고 버튼 | "신고" 링크/아이콘 — 리뷰 신고 (아래 참조) |

**리뷰 텍스트:** 전체 표시 (잘림 없음). 긴 리뷰는 "더보기" 링크로 펼칠 수 있음.

**리뷰 신고 흐름:**
1. 리뷰 카드의 "신고" 클릭
2. 미로그인 시 → 반환 URL이 있는 로그인 페이지로 리다이렉트
3. 로그인 시 → 사유 선택 모달 표시: `spam`, `fake`, `inappropriate`, `irrelevant`, `other`
4. 제출 시 → `{ reason }`과 함께 `POST /api/reviews/{id}/report`
5. 성공 → 토스트 "신고가 접수되었습니다." 해당 리뷰의 신고 버튼 비활성화.
6. 신고된 리뷰는 Strapi 라이프사이클 훅을 통해 `under_review` 상태로 전환 (PRD §8.5)

**"리뷰 작성+" 흐름:**
1. "리뷰 작성+" 클릭
2. 미로그인 시 → 반환 URL이 있는 로그인 페이지로 리다이렉트
3. 로그인 시 계정 잠김 → 토스트 표시: "계정이 정지되었습니다. 관리자에게 문의해주세요."
4. 로그인 시 → 리뷰 제출 폼 표시 (인라인 또는 모달):
   - 별 평점 선택 (1-5, 필수)
   - 리뷰 텍스트 영역 (10-500자, 필수)
   - 제출 버튼
5. 제출 시 → `{ rating, comment, shop: documentId }`와 함께 `POST /api/reviews`
6. 성공 → 토스트 "리뷰가 등록되었습니다" + 새 리뷰 목록 앞에 추가
7. 오류 → 오류 메시지와 함께 토스트

#### 8.8.3 리뷰 페이지네이션
하단에 페이지 기반 페이지네이션: `< [1] 2 3 4 5 >`

- 각 페이지에 ~5-10개 리뷰 표시
- URL: `/[locale]/shop/{slug}?tab=reviews&page=2`

### 8.9 주변 추천샵 (이 주변 추천샵)

**위치:** 탭 콘텐츠 영역 아래, 푸터 위.

**시각적 디자인:**
- 섹션 헤더: "이 주변 추천샵"
- 4개 샵 카드의 가로 행
- 각 카드: 평점 뱃지 (★ 4.8), 샵 이름, 위치 + 도보 거리 (예: "도보 5분"), 취소선 원래 가격과 함께 세일 가격이 있는 썸네일 이미지

**데이터 소스:** `GET /api/shops/nearby?lat={shop.latitude}&lng={shop.longitude}&radius=3000&pagination[pageSize]=4` — 사용자의 GPS가 아닌 현재 샵의 좌표를 사용하여 요청.

**도보 거리 계산:** API는 `distance` 필드를 미터 단위로 반환합니다. 고객 웹은 공식을 사용하여 도보 시간 추정치로 변환합니다: `walking_minutes = Math.round(distance_meters / 80)` (평균 보행 속도 ~80m/분 가정). 각 카드에 "도보 {N}분"으로 표시. 거리가 3km 초과인 경우 대신 `Math.round(distance_meters / 500)`을 사용하여 "차량 {N}분" 표시.

**카드 클릭:** 해당 주변 샵의 `/[locale]/shop/{slug}`로 이동.

## 16. 필요한 신규 콘텐츠 타입

Figma 디자인은 현재 PRD/TSD에 없는 신규 Strapi 콘텐츠 타입이 필요한 UI 기능을 도입합니다. 고객 웹이 이를 사용하기 전에 Strapi 백엔드와 관리자 웹에 추가되어야 합니다.

### 16.1 공지 (`notice`)

**목적:** 모든 페이지 상단에 표시되는 순환 공지 배너.

| 필드 | Strapi 필드 타입 | 필수 | 설명 |
|---|---|---|---|
| 제목 | Text (Short) | 예 | 배너에 표시되는 공지 헤드라인 텍스트 |
| 링크 URL | Text (Short) | 아니오 | 클릭 시 이동할 URL (내부 또는 외부) |
| 링크 타겟 | Enumeration | 아니오 | `_self` (기본), `_blank` |
| 상태 | Enumeration | 예 | `draft`, `published`, `archived` |
| 표시 순서 | Integer | 아니오 | 정렬 우선순위 (낮을수록 높은 우선순위) |
| 시작 날짜 | DateTime | 아니오 | 선택적 — 이 날짜 이후에만 공지 표시 |
| 종료 날짜 | DateTime | 아니오 | 선택적 — 이 날짜 이후 자동으로 공지 숨김 |

**i18n:** 활성화 (제목 및 링크 URL 현지화)
**초안 & 발행:** 활성화

### 16.2 배너 (`banner`)

**목적:** 홈페이지 (및 잠재적으로 다른 페이지)에 표시되는 히어로 배너.

| 필드 | Strapi 필드 타입 | 필수 | 설명 |
|---|---|---|---|
| 제목 | Text (Short) | 예 | 배너에 오버레이된 헤드라인 텍스트 |
| 부제목 | Text (Short) | 아니오 | 헤드라인 아래 보조 텍스트 |
| CTA 텍스트 | Text (Short) | 아니오 | 버튼 텍스트 (예: "지금 바로 예약하기") |
| CTA URL | Text (Short) | 아니오 | CTA 버튼이 이동하는 URL |
| 이미지 | Media (Single) | 예 | 배경 이미지 |
| 배치 | Enumeration | 예 | `homepage_hero`, `search_top` (확장 가능) |
| 상태 | Enumeration | 예 | `draft`, `published` |
| 표시 순서 | Integer | 아니오 | 순환 순서를 위한 정렬 우선순위 |

**i18n:** 활성화 (제목, 부제목, CTA 텍스트 현지화)
**초안 & 발행:** 활성화

### 16.3 편집 추천 (`editorial-pick`)

**목적:** 홈페이지에 표시되는 큐레이션 편집 추천 카드 ("Swida 추천샵 Editor's Choice").

| 필드 | Strapi 필드 타입 | 필수 | 설명 |
|---|---|---|---|
| 제목 | Text (Short) | 예 | 카드 제목 (예: "지친 하루의 끝, 커플 스파로 힐링하세요") |
| 설명 | Text (Long) | 예 | 카드 설명 텍스트 |
| 이미지 | Media (Single) | 예 | 카드 배경 이미지 |
| 뱃지 태그 | Enumeration | 예 | `best_theme`, `recommend`, `new_open`, `hot`, `premium` |
| 링크 URL | Text (Short) | 예 | 클릭 시 이동할 URL |
| 상태 | Enumeration | 예 | `draft`, `published` |
| 표시 순서 | Integer | 아니오 | 정렬 우선순위 |

**i18n:** 활성화 (제목, 설명 현지화)
**초안 & 발행:** 활성화

### 16.4 지역별 추천 (`region-recommendation`)

**목적:** 홈페이지의 지역 기반 샵 컬렉션 카드 ("지역별 마사지 추천").

| 필드 | Strapi 필드 타입 | 필수 | 설명 |
|---|---|---|---|
| 제목 | Text (Short) | 예 | 카드 제목 (예: "강남구 최고 인기샵") |
| 설명 | Text (Long) | 예 | 카드 설명 |
| 이미지 | Media (Single) | 예 | 썸네일 이미지 |
| 해시태그 | JSON | 아니오 | 해시태그 문자열 배열 (예: ["#압구정", "#신사", "#한남"]) |
| 연결된 지역 | Relation (→ Region) | 아니오 | 선택적 지역 링크 |
| 연결된 구 | Relation (→ District) | 아니오 | 선택적 구 링크 |
| 링크 URL | Text (Short) | 아니오 | 커스텀 URL 오버라이드 (연결된 지역/구를 사용하지 않는 경우) |
| 상태 | Enumeration | 예 | `draft`, `published` |
| 표시 순서 | Integer | 아니오 | 정렬 우선순위 |

**i18n:** 활성화 (제목, 설명, 해시태그 현지화)
**초안 & 발행:** 활성화

### 16.5 샵 데이터 모델 확장

다음 필드를 기존 `shop` 콘텐츠 타입에 추가해야 합니다:

| 필드 | Strapi 필드 타입 | 필수 | 설명 |
|---|---|---|---|
| 원래 가격 | Integer | 아니오 | KRW 기준 원래/정가 시작 가격 (세일 가격이 있을 때 취소선으로 표시) |
| 세일 가격 | Integer | 아니오 | KRW 기준 할인/프로모션 시작 가격 |
| 프리미엄 여부 | Boolean | 아니오 | 샵이 프리미엄 등록인지 여부 ("PREMIUM" 뱃지 제어) |
| 베스트 여부 | Boolean | 아니오 | 샵이 관리자 큐레이션 최고 선택인지 여부 ("BEST" 뱃지 제어) |
| 신규 여부 | Boolean | 아니오 | 샵이 새로 등록되었는지 여부 ("신규" 뱃지 제어). 샵이 최근 30일 이내에 발행된 경우 라이프사이클 훅으로 자동 설정. |

**뱃지 표시 로직:**

| 뱃지 ID | 레이블 | 색상 | 조건 |
|---|---|---|---|
| `premium` | PREMIUM / 프리미엄 | 금색/노란색 | `shop.is_premium === true` |
| `best` | BEST | 빨간색 | `shop.is_best === true` (관리자 큐레이션 추천 샵) |
| `new` | 신규 | 파란색 | `shop.is_new === true` 또는 샵이 최근 30일 이내에 발행됨 |

**가격 표시 로직:**

| 시나리오 | 표시 |
|---|---|
| `original_price`와 `sale_price` 모두 존재하고 `sale_price < original_price` | `original_price`에 취소선 + `sale_price` 강조 표시 |
| `sale_price`만 존재 (또는 동일한 경우) | `sale_price`만 표시, 취소선 없음 |
| 둘 다 없음 | 가장 저렴한 `service_menu_item`의 가격 표시 (대체) |
| 가격 데이터 없음 | "가격 문의" 표시 |

### 16.6 샵 이벤트 (`shop-event`)

**목적:** 샵 상세 페이지 "이벤트" 탭에 표시되는 샵별 프로모션 또는 이벤트.

| 필드 | Strapi 필드 타입 | 필수 | 설명 |
|---|---|---|---|
| 제목 | Text (Short) | 예 | 이벤트 제목 |
| 설명 | Text (Long) | 예 | 이벤트 세부 사항 |
| 이미지 | Media (Single) | 아니오 | 이벤트 배너 이미지 |
| 샵 | Relation (→ Shop) | 예 | 이 이벤트가 속한 샵 |
| 시작 날짜 | DateTime | 아니오 | 이벤트 시작 날짜 |
| 종료 날짜 | DateTime | 아니오 | 이벤트 종료 날짜 |
| 상태 | Enumeration | 예 | `draft`, `published`, `expired` |

**i18n:** 활성화 (제목, 설명 현지화)
**초안 & 발행:** 활성화

### 16.7 즐겨찾기 / 북마크 (`favorite`)

**목적:** 로그인한 고객이 빠른 접근을 위해 샵을 저장/북마크할 수 있도록 함.

| 필드 | Strapi 필드 타입 | 필수 | 설명 |
|---|---|---|---|
| 사용자 | Relation (→ Users-Permissions User) | 예 | 즐겨찾기한 고객 |
| 샵 | Relation (→ Shop) | 예 | 즐겨찾기된 샵 |

**API 엔드포인트:**

| 메서드 | 엔드포인트 | 인증 | 설명 |
|---|---|---|---|
| POST | `/api/favorites` | 고객 JWT | 샵을 즐겨찾기에 추가 |
| DELETE | `/api/favorites/:id` | 고객 JWT | 샵을 즐겨찾기에서 제거 |
| GET | `/api/favorites?filters[user][id][$eq]={userId}` | 고객 JWT | 사용자의 즐겨찾기 목록 조회 |

**동작:** (사용자, 샵) 쌍에 고유 제약 — 사용자는 샵을 한 번만 즐겨찾기할 수 있음.
