# 기능 명세서 (FSD)

## SWIDA — Customer Web

- **버전**: 1.0
- **날짜**: 2026-03-26
- **기반 문서**: SWIDA PRD v1.1, SWIDA TSD v1.1
- **범위**: MVP — 고객 대상 업체 탐색 웹 애플리케이션
- **관련 문서**: UI/UX 명세서 (별도 작성 예정)

---

## 1. 문서 개요

### 1.1 목적

본 문서는 SWIDA Customer Web 애플리케이션의 페이지 목록과 기능 명세를 정의합니다. 각 페이지의 역할, 표시 데이터, 사용자 인터랙션 방식을 다룹니다. 시각 디자인, 레이아웃, 인터랙션 세부사항은 별도의 UI/UX 명세서에서 다룹니다.

### 1.2 MVP 범위

| 포함 | 미포함 (향후 개발) |

### 1.3 공통 규칙

| 항목 | 규칙 |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 통화 | KRW (₩). 가격은 정수에 쉼표 구분자로 표시 (예: ₩50,000) |
| 날짜/시간 | KST (한국 표준시, UTC+9). 형식: 날짜 `YYYY.MM.DD`, 시간 `HH:mm` |
| 시간대 | 영업중/영업종료 태그 판정 시 한국 표준시(Asia/Seoul) 사용 |
| 로케일 라우팅 | 경로 기반: `/ko/...` (기본값), `/en/...`. 루트 `/`는 `/ko`로 리다이렉트 |
| 페이지네이션 | SEO를 위한 페이지 기반 (무한 스크롤 아님). 각 페이지에 고유 URL 부여 |
| 필터 상태 | 모든 활성 필터는 URL 쿼리 파라미터에 유지 (공유 및 북마크 가능) |
| 반응형 | 모바일 우선 디자인, 세 단계: 모바일, 태블릿, 데스크톱 |
| 인증 | 탐색 시 선택 사항. 리뷰 작성, 리뷰 신고, 커뮤니티 게시글 작성, 댓글 작성 시 필수 |
| 빈 상태 | 필터를 넓히거나 다른 검색 모드를 시도하도록 안내하는 친절한 메시지 표시 |
| 로딩 상태 | 모든 데이터 로딩 상태에 스켈레톤 플레이스홀더 적용 (UI/UX 명세서에 정의) |
| 오류 처리 | API 오류 시 토스트 알림 표시. 네트워크 장애 시 재시도 옵션 제공 |
| 입력 살균 | 모든 사용자 입력 텍스트 필드(리뷰 댓글, 파트너십 메시지, 닉네임, 검색어)는 저장 전 서버 측에서 살균됨. HTML 태그가 제거됨. 출력 시 XSS 방지를 위해 이스케이프 처리. 클라이언트 측 살균은 보조 수단일 뿐 — 클라이언트 입력을 절대 신뢰하지 않음. |
| 제출 보호 | 모든 폼 제출 버튼은 첫 클릭 시 비활성화 + 로딩 상태로 전환되며 서버 응답까지 유지. 이는 모든 쓰기 작업(회원가입, 리뷰, 파트너십 문의, 비밀번호 재설정 요청, 로그인)에서 이중 제출을 방지함. 서버 측 중복 방지가 최종 방어선 — 클라이언트 측 비활성화는 UX 전용. |

**접근 제어**

| 사용자 상태 | 접근 가능 페이지 | 제한된 행동 처리 |
| ---------------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 비로그인 | 모든 공개 페이지 (열람만 가능) | 리뷰 작성 / 신고 → 로그인으로 리다이렉트. 마이페이지 / 프로필 수정 → 로그인으로 리다이렉트. 커뮤니티 게시글 작성 / 댓글 → 로그인으로 리다이렉트. |
| 로그인 (활성) | 모든 페이지 + 리뷰 작성 + 마이페이지 + 커뮤니티 게시글 작성 + 댓글 | 로그인 / 회원가입 / 비밀번호 찾기 / 비밀번호 재설정 → 홈페이지로 리다이렉트 |
| 로그인 (잠김/정지) | 모든 페이지 (열람만 가능) + 마이페이지 (보기 전용) | 리뷰 작성 / 신고 → 오류 메시지. 커뮤니티 게시글 작성 / 댓글 → 오류 메시지. |

## 3. 인증

### 3.1 로그인 (`/[locale]/auth/login`)

> PRD 참조: §3.3 고객, §11.5 보안

**기능 목록**

| # | 기능 | 설명 |
| --------- | ----------------------- | ------------------------------------------------------------------------------------------ |
| F-AUTH-01 | 이메일/비밀번호 로그인 | 표준 이메일 + 비밀번호 인증 (PRD §3.3) |
| F-AUTH-02 | 카카오 소셜 로그인 | 카카오 계정을 통한 로그인 (PRD §3.3) |
| F-AUTH-03 | 네이버 소셜 로그인 | 네이버 계정을 통한 로그인 (PRD §3.3) |
| F-AUTH-04 | 이메일 회원가입 | 이메일, 비밀번호, 닉네임으로 신규 계정 생성 |
| F-AUTH-05 | 로그인 후 리다이렉트 | 로그인 성공 후, 로그인 전 사용자가 있던 페이지로 리다이렉트 |
| F-AUTH-06 | 잠긴 계정 처리 | 계정이 잠김/정지 상태인 경우, 오류 메시지를 표시하고 리뷰 기능 로그인을 차단 |

**가입 입력 제약사항**

| 필드 | 필수 | 제약사항 | 비고 |
| ------------ | -------- | -------------------------- | ---------------- |
| 이메일 | 예 | 유효한 이메일 형식, 고유 | — |
| 비밀번호 | 예 | 최소 6자 | — |
| 닉네임 | 예 | 2–20자, 고유 | 리뷰에 표시됨 |

**서버 유효성 검사 오류**

| 조건 | 오류 |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| 잘못된 이메일/비밀번호 | "이메일 또는 비밀번호가 올바르지 않습니다" / "Invalid email or password" |
| 이미 등록된 이메일 | "이미 등록된 이메일입니다" / "This email is already registered" |
| 이미 사용 중인 닉네임 | "이미 사용 중인 닉네임입니다" / "This display name is already taken" |
| 계정 정지 | "계정이 정지되었습니다. 관리자에게 문의해주세요." / "Your account has been suspended. Please contact the administrator." |

### 3.2 OAuth 콜백 (`/[locale]/auth/callback`)

| # | 기능 | 설명 |
| --------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| F-AUTH-07 | 토큰 교환 | 소셜 로그인을 완료하고 사용자 세션 생성 |
| F-AUTH-08 | 자동 가입 | 최초 소셜 로그인 사용자는 자동으로 가입 처리 |
| F-AUTH-09 | 오류 처리 | OAuth 흐름 실패 시 오류 메시지를 표시하고 로그인 페이지로 리다이렉트. 실패 유형에 따라 오류 메시지가 다름 (아래 참조). 로그인 전 리다이렉트 대상은 세션 스토리지에 보존되어 사용자가 위치를 잃지 않고 재시도 가능. |

**OAuth 오류 메시지**

| 실패 유형 | 오류 메시지 |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 제공자 연결 불가 | "소셜 로그인 서비스에 연결할 수 없습니다. 잠시 후 다시 시도해주세요." / "Unable to connect to the social login service. Please try again later." |
| 토큰 교환 실패 | "로그인 처리 중 오류가 발생했습니다. 다시 시도해주세요." / "An error occurred during login. Please try again." |
| 계정 충돌 (이메일이 다른 제공자로 이미 존재) | "이미 다른 방법으로 가입된 이메일입니다." / "This email is already registered with a different login method." |

**복구:** OAuth 실패 시, `?error=oauth_failed` 쿼리 파라미터와 함께 로그인 페이지로 리다이렉트. 로그인 페이지에서 적절한 오류 메시지를 표시하고 재시도를 위해 원래 반환 URL을 유지.

### 3.3 세션 관리

> PRD 참조: §11.5 보안, TSD §5.4.1

| # | 기능 | 설명 |
| ------------ | ---------------- | --------------------------------------------------------------------- |
| F-SESSION-01 | 세션 저장 | 로그인 세션이 브라우저에 안전하게 저장됨 |

| F-SESSION-04 | 세션 만료 | 세션 만료 시 보호된 작업을 시도하면 로그인으로 리다이렉트 |

### 3.4 로그아웃

| # | 기능 | 설명 |
| ----------- | ------------- | -------------------------------------- |
| F-LOGOUT-01 | 세션 초기화 | 로그인 세션 종료 및 사용자 상태 초기화 |
| F-LOGOUT-02 | 리다이렉트 | 로그아웃 후 홈페이지로 이동 |

### 3.5 회원가입 (`/[locale]/auth/signup`)

> PRD 참조: §3.3 고객, §11.5 보안

**기능 목록**

| # | 기능 | 설명 |
| --------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F-AUTH-10 | 이메일 가입 양식 | 이메일, 비밀번호, 비밀번호 확인, 닉네임 필드가 포함된 양식 |
| F-AUTH-11 | 동의 절차 | "전체 선택" 체크박스 + 이용약관 및 개인정보 처리방침에 대한 개별 필수 체크박스. 두 항목 모두 체크해야 제출 가능. |

### 3.6 비밀번호 재설정

> PRD 참조: §3.3 고객, §11.5 보안

#### 3.6.1 비밀번호 찾기 (`/[locale]/auth/forgot-password`)

**기능 목록**

| # | 기능 | 설명 |
| --------- | ---------------------- | ---------------------------------------------------------------------------------------------------------- |
| F-AUTH-16 | 비밀번호 재설정 요청 | 사용자가 재설정 링크를 받기 위해 이메일 주소를 제출 |
| F-AUTH-17 | 이메일 발송 | 시스템이 토큰화된 재설정 링크가 포함된 이메일 발송. 토큰은 1시간 후 만료, 일회용. |
| F-AUTH-18 | 확인 메시지 | 제출 후: 이메일 존재 여부와 관계없이 동일한 성공 메시지 표시 (사용자 열거 방지) |

**입력 필드**

| 필드 | 필수 | 제약사항 |
| ----- | -------- | ------------------ |
| 이메일 | 예 | 유효한 이메일 형식 |

**서버 동작**

- 이메일이 존재하는 경우: 토큰화된 링크가 포함된 비밀번호 재설정 이메일 발송
- 이메일이 존재하지 않는 경우: 동일한 성공 메시지 표시 (계정 존재 여부 표시 없음)
- 이메일 발송 실패(SMTP 오류) 시: 이메일, 타임스탬프, 오류 세부정보와 함께 서버 측에 실패 로그 기록. 사용자에게는 동일한 성공 메시지 표시 (열거 방지를 위해 발송 실패를 표시하지 않음). 관리자 대시보드 또는 모니터링에서 발송 실패를 표면화해야 함.
- 속도 제한: 이메일당 시간당 최대 3회 재설정 요청

**확인 메시지**

| 조건 | 메시지 |
| --------------- | ---------------------------------------------------------------------------------------- |
| 제출 (항상) | "비밀번호 재설정 링크가 이메일로 발송되었습니다. 이메일을 확인해주세요." / "A password reset link has been sent to your email. Please check your inbox." |

**이메일 발송 실패 복구**

확인 메시지가 표시된 후, **60초** 후에 "이메일을 받지 못하셨나요? 다시 보내기" ("Didn't receive the email? Resend") 링크가 나타남. 링크를 클릭하면 동일한 주소로 비밀번호 재설정 이메일을 재발송. 이 재발송 동작은 **시간당 최대 3회**로 속도 제한됨 (초기 요청 제한과 공유). 속도 제한 초과 시 표시: "요청 횟수를 초과했습니다. 잠시 후 다시 시도해주세요." / "Too many requests. Please try again later."

#### 3.6.2 비밀번호 재설정 (`/[locale]/auth/reset-password?token=XXX`)

**기능 목록**

| # | 기능 | 설명 |
| --------- | ----------------- | ---------------------------------------------------------------------------------------------- |
| F-AUTH-19 | 토큰 유효성 검사 | 페이지 로드 시 토큰 검증. 유효하지 않거나 만료된 경우 → 오류 메시지 + 비밀번호 찾기 링크 |

| F-AUTH-21 | 재설정 성공 | 성공 시: 확인 메시지 + 로그인 페이지로 리다이렉트 |

**입력 필드**

| 비밀번호 확인 | 예 | 새 비밀번호와 일치해야 함 | 실시간 일치 검사 |

| 비밀번호 너무 짧음 | "비밀번호는 최소 6자 이상이어야 합니다" / "Password must be at least 6 characters" |
| 비밀번호 불일치 | "비밀번호가 일치하지 않습니다" / "Passwords do not match" |

**스토리보드: 비밀번호 재설정**

```
[1] 사용자가 로그인 페이지에서 "비밀번호 찾기"를 클릭 → /[locale]/auth/forgot-password로 이동.
[2] 사용자가 이메일을 입력 → 제출을 클릭.
[3] 시스템이 재설정 이메일 발송 (계정이 존재하는 경우). 동일한 확인 메시지 표시.

[5a] 토큰 유효 → 새 비밀번호 양식 표시.

```

## 부록 B. 영업중/영업종료 태그 로직

> PRD 참조: §5.6 메타데이터 — 영업중/영업종료 태그

**동작 방식**

업체의 영업시간과 현재 한국 시간(KST)을 기반으로 시스템이 영업/종료 상태를 판정합니다.

- 업체에 자유 텍스트 영업시간 설명이 있는 경우, 그대로 표시됩니다 (자동 영업/종료 계산 없음).
- 그 외의 경우, 시스템은 현재 요일에 해당하는 업체의 구조화된 영업시간을 확인합니다.
- 오늘에 대한 영업시간이 설정되어 있지 않으면, 업체는 영업종료로 표시됩니다.
- 야간 영업시간 (예: 18:00-02:00)은 자정을 넘어 정확하게 처리됩니다.
- 업체에 커스텀 레이블이 없는 한, 표시 태그는 "영업중" (Open) 또는 "영업종료" (Closed)가 기본값입니다.

> 데이터 구조 상세사항은 TSD §4.4.4 및 §6.4를 참조하세요.

**표시 규칙**

- Customer Web에는 게시된 업체만 표시됩니다
- 비게시 업체는 영업/종료 상태와 관계없이 절대 표시되지 않습니다
- `open_tag` 또는 `close_tag`가 비어있거나 null인 경우 기본 레이블로 대체됩니다

## 부록 D. 보류된 인증 기능

다음 기능은 UI/UX 명세서에 정의되어 있지만 MVP에서 보류되었습니다:

| 기능 | 사유 | 의존성 |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | ---------------------------------------- |
| ID 찾기 (닉네임으로 이메일 찾기) | 전화번호 없이 신뢰할 수 있는 대체 식별자 없음 | 전화/SMS 인증 |
| 전화/SMS 인증 | PRD MVP 범위에 포함되지 않음 | SMS 서비스 연동 |
| 웰컴 쿠폰 (가입 시 3,000원) | 쿠폰 시스템이 PRD MVP 범위에 포함되지 않음 | 쿠폰 콘텐츠 타입 + 관리자 관리 |
| 강화된 비밀번호 규칙 (8자 이상, 영숫자 + 특수문자) | 현재 FSD/PRD는 최소 6자만 명시 | 요구사항 강화를 위한 PRD 업데이트 |
| 서버 측 리뷰 속도 제한 (Strapi 미들웨어를 통한 10/사용자/시간, 3/사용자/업체/일) | Cloudflare WAF는 사용자당 일일 ~400+ 허용; 리뷰 폭주 방지를 위한 앱 수준 제한 필요 | Strapi 커스텀 미들웨어 + Redis 카운터 |

> 이러한 기능은 의존성이 해결되고 PRD 범위가 업데이트될 때 FSD에 추가되어야 합니다.
