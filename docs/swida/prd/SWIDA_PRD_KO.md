# SWIDA — 제품 요구사항 문서 (PRD)

## 1. 개요

**제품명:** SWIDA (Swedish + 쉬다)

**설명:** SWIDA는 대한민국 시장을 위해 특화된 마사지 및 웰니스 업체 탐색 플랫폼입니다. 지역 마사지·웰니스 업체와 휴식 서비스를 찾는 고객을 연결하는 역할을 합니다. 업체 등록은 간단한 어드민 관리 온보딩 프로세스를 통해 이루어지며, 고객은 위치, 서비스 테마, 거리, 편의시설 기반 필터링을 통해 풍부한 검색·탐색 경험을 누릴 수 있습니다.

**타겟 시장:** 대한민국

**플랫폼:** 웹 (반응형 — 모바일 & 데스크톱)

**핵심 가치 제안:**
- **고객**: 네이버/카카오에 흩어진 검색 없이 취향과 위치에 맞는 마사지·웰니스 업체를 한곳에서 신뢰할 수 있게 탐색할 수 있는 중앙화된 디렉토리
- **업체 사장님**: 자체 디지털 채널 관리나 새로운 플랫폼 학습 없이도 노출과 검색 가능성 향상
- **SWIDA(비즈니스)**: 프리미엄 노출, 광고, 파트너십 티어를 통한 미래 수익화 잠재력을 갖춘 확장 가능한 리스팅 플랫폼

## 2. 목표 및 성공 지표

### 2.1 비즈니스 목표
- 대한민국에서 가장 종합적인 마사지·웰니스 업체 디렉토리 구축
- 마사지 서비스 탐색의 핵심 도구로 SWIDA 브랜드 확립
- 어드민 관리 등록을 통한 업체 사장님 온보딩 파이프라인 구축 (저마찰)
- 미래 수익화를 위한 기반 마련 (프리미엄 리스팅, 피처드 노출, 광고)

### 2.2 핵심 성공 지표 (KPI)
| 지표 | 목표 (MVP, 6개월) |
|---|---|
| 총 등록 업체 수 | 500개 이상 |
| 월간 활성 사용자 (고객) | 10,000명 이상 |
| 평균 세션 시간 | 3분 이상 |
| 월간 리뷰 제출 수 | 500건 이상 |
| 월간 파트너십 문의 수 | 50건 이상 |

## 3. 사용자 역할 및 권한

### 3.1 어드민

어드민은 SWIDA 플랫폼의 중앙 운영자입니다. 모든 업체 데이터는 어드민을 통해 관리됩니다.

**권한:**
- **업체 관리:** 업체 리스팅 생성·조회·수정·삭제(CRUD) — 위치, 테마, 편의시설, 이미지, 설명 등 모든 관련 데이터 포함. 커스텀 Admin Web 애플리케이션(Next.js)을 통해 수행되며 Strapi REST API와 통신합니다.
- **업체 공개 여부:** Admin Web 인터페이스를 통해 업체를 게시 또는 미게시 처리합니다. Strapi의 기본 제공 초안 및 게시(Draft & Publish) 시스템을 API를 통해 작동시킵니다. 게시된 업체는 Customer Web에 표시되고, 미게시 업체는 숨겨집니다. 업체별로 고객 대면 영업 상태 표시를 위한 커스텀 영업 중/종료 태그를 설정할 수 있습니다.
- **미리보기:** 고객에게 표시되는 업체 리스팅 화면을 그대로 미리보기 가능 — 게시 전 품질 확인을 위한 완전한 읽기 전용 고객 뷰. Admin Web 내 "미리보기" 버튼을 통해 Customer Web 업체 상세 페이지를 미리보기/초안 모드로 열 수 있습니다.
- **콘텐츠 관리:** 서비스 테마, 위치 카테고리(1단계 및 2단계), 편의시설 옵션 등 동적 데이터 관리 — Admin Web 인터페이스에서 Strapi 컬렉션 타입을 통해 관리됩니다.
- **리뷰 및 콘텐츠 모더레이션:** Admin Web을 통해 부적절한 고객 리뷰 및 게시물 검토, 신고, 숨김, 삭제 가능. 어드민은 언제든지 모든 리뷰 또는 게시물을 공개 뷰에서 숨길 수 있습니다.
- **고객 계정 관리:** 스팸, 허위 리뷰, 괴롭힘 등 남용 행위를 보이는 고객 계정을 잠금/정지 처리. 잠긴 계정은 리뷰 또는 게시물 제출이 차단됩니다. 어드민은 적절한 시점에 계정을 잠금 해제할 수 있습니다.
- **대시보드:** 플랫폼 통계(총 업체 수, 총 리뷰 수, 사용자 활동, 파트너십 문의)를 확인할 수 있는 어드민 대시보드 — Admin Web(Next.js)의 전용 페이지로 구축됩니다.

**인증:** Strapi 어드민 API를 통한 어드민 인증 (이메일/비밀번호, JWT 방식). Admin Web(Next.js)은 전용 어드민 도메인(`admin.swida.com`)에서 제공되며, 인증 및 데이터 관리를 위해 Strapi 어드민 API 엔드포인트와 통신합니다. 권한이 부여된 어드민 사용자만 로그인 가능 — 고객 및 업체 사장님은 Admin Web에 접근할 수 없습니다.

> **아키텍처 참고:** Strapi는 **헤드리스 API 전용 백엔드**로 운영됩니다. Strapi 기본 제공 어드민 패널은 모니터링, 디버깅, 긴급 운영을 위해 **개발자 전용**으로 제한되며 — 일상적인 플랫폼 관리에는 사용되지 않습니다. 주요 어드민 인터페이스는 SWIDA의 운영 워크플로우에 맞게 맞춤 제작된 Next.js 애플리케이션(Admin Web)입니다. 인증된 어드민 사용자만 Admin Web에 접근할 수 있으며, 고객, 업체 사장님, 기타 역할은 접근할 수 없습니다.

### 3.2 업체 (업체 사장님)

업체 사장님은 SWIDA 플랫폼에 **직접 접근 권한이 없습니다**. 업체 회원가입, 로그인, 셀프서비스 포털은 존재하지 않습니다.

**온보딩 흐름:**
1. 업체 사장님이 입소문, SNS, 또는 파트너십 페이지를 통해 SWIDA를 알게 됨
2. 업체 사장님이 SNS(카카오톡, 인스타그램 DM 등) 또는 이메일로 어드민에게 직접 연락
3. 업체 사장님이 필요한 업체 정보(상호명, 주소, 테마, 편의시설, 이미지 등) 제공
4. 어드민이 정보를 확인한 후 Admin Web을 통해 리스팅 생성
5. 리스팅이 활성화되면 어드민이 업체 사장님에게 알림

**향후 고려 사항:** 이후 단계에서 업체 사장님 셀프서비스 포털을 도입하여 리스팅 직접 관리, 리뷰 응답, 홍보 콘텐츠 업로드 등의 기능 제공을 검토할 수 있습니다.

### 3.3 고객

고객은 SWIDA의 주요 최종 사용자입니다. 업체 탐색 및 검색에는 계정이 **필요하지 않지만**, 리뷰 제출을 위해서는 계정이 필요합니다.

**권한:**
- 다양한 필터와 검색 모드를 사용하여 등록된 모든 업체 탐색 및 검색
- 위치, 테마, 편의시설, 이미지, 리뷰 등 업체 상세 프로필 조회
- 모든 업체에 리뷰 및 별점 제출 (방문 인증 불필요, 업체별/일별 제한 없음 — 남용은 어드민 계정 제어로 관리)
- GPS 기반 주변 검색으로 가까운 업체 탐색
- 마이페이지를 통해 업체 북마크/저장하여 빠른 접근
- 마이페이지에서 개인 프로필, 작성한 리뷰, 북마크한 업체 확인
- 프로필 수정 페이지에서 프로필 사진 변경
- 텍스트, 사진 (최대 5장), 동영상 (최대 1개), 해시태그로 커뮤니티 게시글 작성
- 게시판 게시글 및 커뮤니티 게시글에 댓글 작성 (1단계 대댓글)
- 게시판 게시글, 커뮤니티 게시글, 이벤트에 좋아요 (사용자당 대상당 1회)
- 커뮤니티 활동으로 포인트 획득 및 사용자 레벨 (Lv.1–Lv.5) 진행
- 관리자 작성 게시판 콘텐츠 (업체 추천, 마사지 정보) 탐색
- 플랫폼 이벤트 및 공지사항 탐색

**인증:** 이메일 또는 소셜 로그인(카카오, 네이버)을 통한 선택적 회원가입/로그인 — Strapi Users & Permissions 플러그인에서 커스텀 카카오/네이버 프로바이더로 처리. 리뷰 작성, 리뷰 신고, 커뮤니티 게시글 작성, 댓글 작성, 좋아요, 북마크 시 필요.

**이메일 인증:** 이메일 회원가입 시 인증 단계가 포함됩니다. 가입 후 인증 링크가 포함된 확인 이메일이 발송됩니다. 사용자는 플랫폼을 즉시 탐색할 수 있지만(업체 조회, 검색, 북마크), 쓰기 작업(리뷰 작성, 리뷰 신고, 커뮤니티 게시글 작성, 댓글, 좋아요)을 수행하려면 이메일 인증을 완료해야 합니다. 미인증 사용자가 이러한 작업을 시도하면 이메일 확인 안내가 표시됩니다. "인증 이메일 재발송" 옵션을 제공합니다.

## 4. 위치 시스템

SWIDA는 대한민국 행정구역에 맞춘 2단계 계층적 위치 시스템을 사용합니다.

### 4.1 1단계 — 광역 (시/도)

광역시와 도를 나타내는 최상위 지리적 그룹입니다.

**Strapi 콘텐츠 타입:** `region` (컬렉션 타입)

**예시:** 서울특별시, 부산광역시, 경기도, 인천광역시, 대구광역시, 제주특별자치도 등

### 4.2 2단계 — 시/군/구

1단계 광역 내 하위 지역입니다. 2단계 옵션은 선택된 1단계 광역에 따라 **동적으로 필터링**됩니다.

**Strapi 콘텐츠 타입:** `district` (컬렉션 타입, 관계 → 하나의 `region`에 속함)

**예시 (서울특별시):** 강남구, 마포구, 종로구, 서초구, 영등포구 등
**예시 (부산광역시):** 해운대구, 부산진구, 동래구, 수영구 등

### 4.3 규칙
- 모든 업체는 정확히 하나의 2단계 위치(구/군/시)에 등록되어야 합니다.
- 2단계 옵션은 1단계 광역 선택 후에만 표시됩니다.
- 어드민은 Admin Web을 통해 1단계 및 2단계 항목 전체를 관리합니다 (추가, 수정, 삭제).
- 위치 데이터는 출시 시 Strapi 시드 스크립트를 통해 대한민국 전체 행정구역으로 **반드시** 사전 입력되어야 합니다 (출시 차단 요소 — 위치 데이터 없이는 플랫폼이 작동하지 않음).

## 5. 업체 리스팅 데이터 모델

각 업체 프로필은 다음 필드 및 컴포넌트를 포함하는 Strapi **컬렉션 타입**(`shop`)으로 정의됩니다.

### 5.1 기본 정보

| 필드 | Strapi 필드 타입 | 필수 여부 | 설명 |
|---|---|---|---|
| 업체명 | 텍스트 (단문) | 예 | 공식 상호명 |
| 슬러그 | UID (업체명 기반) | 예 | URL 친화적 식별자, 자동 생성 |
| 소개 | 텍스트 (장문) | 예 | 간략한 소개/개요 (최대 500자) |
| 주소 | 텍스트 (단문) | 예 | 전체 도로명 주소 |
| 광역 | 관계 (→ Region) | 예 | 1단계 위치 (시/도) |
| 구/군/시 | 관계 (→ District) | 예 | 2단계 위치 (시/군/구) |
| 위도 | 소수 (Float) | 예 | GPS 위도 — 어드민이 지도 핀 드롭 방식으로 입력 (커스텀 필드 플러그인) |
| 경도 | 소수 (Float) | 예 | GPS 경도 — 어드민이 지도 핀 드롭 방식으로 입력 (커스텀 필드 플러그인) |
| 전화번호 | 텍스트 (단문) | 아니오 | 주요 연락처 전화번호 |
| 영업 시간 | JSONB (요일별 스케줄) + 텍스트 (단문) 오버라이드 | 예 | 요일별 영업/마감 시간을 JSONB로 저장 (`operating_hours`), 특이사항을 위한 자유 텍스트 필드 (`operating_hours_text`) 포함 (예: "공휴일 영업시간 변동 가능"). TSD §5.1 스키마 참조. |
| 마감 주문 시간 | 텍스트 (단문) | 아니오 | 최종 예약/워크인 접수 시간 |
| 정기 휴무일 | 텍스트 (단문) | 예 | 정기 휴무일 (예: 매주 일요일, 공휴일) |
| 임시 휴무 | 텍스트 (장문) | 아니오 | 임시 휴업 또는 특별 휴일 일정 |
| 이미지 | 미디어 (복수) | 예 | 업체 사진 (최소 1장, 최대 10장), Strapi Upload 프로바이더를 통해 MinIO에 저장 |
| 썸네일 | 미디어 (단일) | 예 | 검색 결과에 표시되는 대표 이미지 |

### 5.2 서비스 정보

| 필드 | Strapi 필드 타입 | 필수 여부 | 설명 |
|---|---|---|---|
| 서비스 테마 | 관계 (→ Theme, 다대다) | 예 | 하나 이상의 마사지/서비스 테마 |
| 서비스 메뉴 | 컴포넌트 (반복 가능: `service-menu-item`) | 예 | 개별 서비스 항목 목록 (5.2.1 참조) |
| 가격대 | 텍스트 (단문) | 아니오 | 일반적인 가격 정보 (예: ₩30,000–₩80,000) |
| 예약 필수 | 불리언 | 예 | 사전 예약 필요 여부 |
| 예약 URL/전화 | 텍스트 (단문) | 아니오 | 예약용 링크 또는 전화번호 |

#### 5.2.1 서비스 메뉴 항목 (Strapi 반복 가능 컴포넌트: `service-menu-item`)

| 필드 | Strapi 필드 타입 | 설명 |
|---|---|---|
| 생성일 | 타임스탬프 | Strapi 자동 관리 |

| 영업 중 태그 | 텍스트 (단문, nullable) | 업체가 현재 영업 시간 내 운영 중일 때 Customer Web에 표시되는 커스텀 레이블 (예: "영업중", "OPEN"). 비어 있으면 기본값 "영업중"으로 표시됩니다. |
| 영업 종료 태그 | 텍스트 (단문, nullable) | 업체가 영업 시간 외일 때 Customer Web에 표시되는 커스텀 레이블 (예: "영업종료", "CLOSED"). 비어 있으면 기본값 "영업종료"로 표시됩니다. 게시된 업체에만 해당 — 미게시 업체는 표시되지 않습니다. |
| 평균 별점 | 소수 (Float) | 리뷰 변경 시 Strapi 라이프사이클 훅을 통해 계산 |
| 총 리뷰 수 | 정수 | 게시된 리뷰 수, 라이프사이클 훅을 통해 업데이트 |

> **참고:** Customer Web에서의 업체 공개 여부는 Strapi 기본 제공 초안 및 게시(Draft & Publish) 시스템으로 완전히 제어됩니다. 어드민이 Admin Web을 통해 업체를 게시 또는 미게시 처리합니다 (Strapi의 Draft & Publish API 호출) — 별도의 커스텀 불리언이 필요하지 않습니다. 게시된 업체만 고객 대면 검색 결과, 업체 상세 페이지, 사이트맵에 표시됩니다. Strapi REST API는 기본적으로 퍼블릭 쿼리에서 초안 항목을 제외하므로 기본 공개 여부 필터링을 위한 커스텀 정책이 필요하지 않습니다.

> **비활성 사유 참고:** Admin Web을 통해 업체를 미게시 처리할 때, 어드민은 업체가 오프라인으로 전환된 이유를 기록하기 위해 `inactive_reason`을 **반드시** 설정해야 합니다. 이 필드는 필수이며, 사유 없이 미게시 처리할 수 없습니다. 감사 목적 및 잠재적 재활성화 워크플로우를 위해 커스텀 필드로 저장됩니다.

> **영업 중/종료 태그 참고:** `open_tag` 및 `close_tag` 필드는 고객에게 표시되는 상태 레이블을 업체별로 커스터마이징할 수 있습니다. 영업 중/종료 여부는 업체의 `영업시간` 필드와 현재 KST(한국 표준시)를 비교하여 결정됩니다. 미게시 업체는 태그 설정에 관계없이 Customer Web에 절대 표시되지 않습니다.

## 6. 검색 및 필터링 시스템

SWIDA는 메인 네비게이션에서 접근 가능한 5가지 검색 모드를 제공합니다. 모든 검색 결과는 썸네일, 업체명, 2단계 위치, 상위 테마, 평균 별점, 리뷰 수를 포함한 **페이지네이션** 형태의 업체 카드 목록을 반환합니다.

**페이지네이션 전략:** 모바일 및 데스크톱 전 기기에서 전통적인 페이지 기반 페이지네이션이 사용됩니다. SEO를 우선시하는 의도적 결정으로 — 각 결과 페이지가 고유하고 크롤링 가능한 URL을 가져 네이버 및 구글의 최대 색인 가능성을 보장합니다.

**API 사용:** Customer Web(Next.js)은 필터링, 정렬, 페이지네이션을 위한 쿼리 파라미터와 함께 Strapi REST API를 호출합니다. Strapi의 기본 제공 `filters`, `sort`, `pagination`, `populate` 파라미터가 대부분의 검색 모드를 기본적으로 처리합니다. 복잡한 쿼리(주변 검색, 한국어 고급 텍스트 검색)는 커스텀 Strapi 컨트롤러/라우트로 처리됩니다.

### 6.1 상세 검색 (고급)

여러 필터를 동시에 조합하는 가장 포괄적인 검색 모드입니다.

**사용 가능한 필터:**
- **업체명** — 키워드/부분 일치 → Strapi 필터: `$containsi`
- **1단계 + 2단계 위치** — 캐스케이딩 드롭다운 → Strapi 필터: `filters[region][documentId][$eq]` 및 `filters[district][documentId][$eq]`
- **서비스 테마** — 다중 선택 → Strapi 필터: `filters[themes][documentId][$in]`
- **편의시설** — 토글 체크박스 → Strapi 필터: `filters[amenities][parking_available][$eq]=true`
- **예약 필수** — 예 / 아니오 / 상관없음 → Strapi 필터: `filters[booking_required][$eq]`

**동작 방식:** 필터는 AND 로직으로 결합됩니다 (Strapi 기본값). 선택된 **모든** 조건에 부합하는 업체만 반환됩니다. 비어 있거나 선택되지 않은 필터는 무시됩니다.

### 6.2 테마 검색

마사지/서비스 테마 중심의 탐색 경험입니다.

**동작 방식:**
- 모든 사용 가능한 테마를 선택 가능한 카드 또는 태그로 표시 (`GET /api/themes`에서 가져옴)
- 테마 선택 시 해당 테마가 태그된 모든 업체를 별점 내림차순으로 반환 → `filters[themes][documentId][$eq]={themeId}&sort=average_rating:desc`
- 테마 선택 후 위치로 결과를 추가로 좁힐 수 있음

### 6.3 지역 검색

2단계 위치 계층을 사용하여 지역별 업체를 탐색합니다.

**동작 방식:**
- 고객이 1단계 광역 먼저 선택 → `GET /api/regions`
- 2단계 옵션이 동적으로 로드됨 → `GET /api/districts?filters[region][documentId][$eq]={regionId}`
- 2단계 선택 시 해당 구의 모든 업체를 별점 내림차순으로 반환

### 6.4 주변 검색

GPS 기반으로 고객 근처의 업체를 탐색합니다.

**동작 방식:**
- 최초 사용 시 브라우저/기기 위치 정보 권한 요청
- 사용자 선택 가능한 반경(최소: 1km, 최대: 10km, 기본값: 5km, 프리셋: 1km, 3km, 5km, 10km) 내에서 거리순(가까운 곳 먼저)으로 업체 반환
- 고객과 각 업체 간의 거리 표시
- 주변 검색 결과 내에서 테마 또는 편의시설로 추가 필터링 가능

**구현:** PostGIS를 사용하는 원시 SQL 쿼리를 실행하는 커스텀 Strapi 컨트롤러(`/api/shops/nearby`) 필요:
```sql
SELECT *, ST_Distance(
  ST_MakePoint(longitude, latitude)::geography,
  ST_MakePoint(:userLng, :userLat)::geography
) AS distance
FROM shops
WHERE published_at IS NOT NULL
  AND ST_DWithin(
    ST_MakePoint(longitude, latitude)::geography,
    ST_MakePoint(:userLng, :userLat)::geography,
    :radiusMeters
  )
ORDER BY distance ASC
```

### 6.5 이름 검색

업체명으로 간단하게 키워드 검색합니다.

**동작 방식:**
- 업체명 전체 또는 일부 입력 → Strapi 필터: `filters[name][$containsi]`
- 관련성 순으로 일치하는 업체 반환
- 대소문자 구분 없음, 한국어 문자 매칭 지원 (초성 검색은 MVP 범위 외 — §12 참조)

### 6.6 검색 UX 규칙

**기본 정렬 순서:**
- 상세 검색 → 별점 내림차순 → `sort=average_rating:desc`
- 테마 검색 → 별점 내림차순 → `sort=average_rating:desc`
- 지역 검색 → 별점 내림차순 → `sort=average_rating:desc`
- 주변 검색 → 거리순 (가까운 곳 먼저) → 커스텀 컨트롤러
- 이름 검색 → 관련성 → 커스텀 컨트롤러 또는 `$containsi` 기본값

**사용 가능한 정렬 옵션:** 별점, 리뷰 수, 최신 등록 순 → `sort=average_rating:desc`, `sort=total_reviews:desc`, `sort=createdAt:desc`

**결과 없음:** 친근한 메시지 표시 (예: "검색 결과가 없습니다"), 필터를 넓히거나 다른 검색 모드를 시도하도록 안내합니다.

**필터 상태:** 모든 활성 필터는 URL 쿼리 파라미터로 유지됩니다. 검색 결과 페이지를 공유, 브라우저 즐겨찾기 등록, 뒤로 가기 후에도 복원 가능합니다.

**결과 수:** 결과 상단에 항상 표시 (예: "검색 결과 42개"). Strapi는 응답 메타데이터에 `pagination.total`을 반환합니다.

**비활성 업체:** 모든 검색 결과 및 사이트맵에서 완전히 제외됩니다. Strapi의 기본 제공 초안 및 게시 시스템은 기본적으로 공개 API 응답에서 미게시 항목을 제외합니다. `is-active-shop` 정책이 추가적인 안전장치로 작동합니다.

### 7.2 어드민 대면 메뉴 (Admin Web — Next.js)

Admin Web은 맞춤형 어드민 경험을 제공하는 커스텀 Next.js 애플리케이션입니다. 인증된 어드민 사용자만 접근 가능합니다. Strapi 기본 제공 어드민 패널은 모니터링, 디버깅, 긴급 운영을 위해 **개발자 전용**으로 제한되며 일상적인 플랫폼 관리에는 사용되지 않습니다.

| Admin Web 페이지/섹션 | 설명 |
|---|---|
| **대시보드** | 플랫폼 개요 통계 (총 업체 수, 리뷰 수, 사용자 수, 문의 수) |
| **업체** | 검색, 필터, 정렬 기능이 포함된 모든 업체 리스팅 CRUD 인터페이스 |
| **테마** | 서비스 테마 추가, 수정, 삭제 |
| **광역 및 구/군/시** | 1단계 및 2단계 위치 항목 관리 |
| **리뷰** | 리뷰 조회, 신고, 숨김, 모더레이션 |
| **파트너십 문의** | 상태 워크플로우를 포함한 수신 파트너십 요청 추적 및 관리 |
| **사용자** | 고객 계정 관리 (잠금/해제, 활동 조회) |

**커스텀 어드민 기능:**
- **대시보드:** 차트 및 트렌드가 포함된 플랫폼 통계 — 커스텀 Strapi 분석 엔드포인트(`GET /api/dashboard/stats`, TSD §5.2.5)에서 데이터를 가져오는 Next.js 페이지로 구축됩니다.
- **감사 로그 뷰어:** 모든 리스팅 변경 이력을 검색 및 필터링 가능한 테이블로 표시합니다. 데이터는 라이프사이클 훅을 통해 Strapi `audit-log` 컬렉션 타입에 저장됩니다.
- **지도 핀 드롭:** 업체 리스팅 생성 또는 수정 시 위도/경도 선택을 위한 통합 지도 컴포넌트 (카카오맵).

### 7.3 어드민 운영 워크플로우 (MVP)

업체 사장님이 리스팅을 직접 관리하지 않으므로, Admin Web이 핵심 운영 엔진입니다. 출시 시 다음 워크플로우가 필요합니다.

**리스팅 게시 흐름:**
`초안(draft)` → `게시됨(published)`
- **초안:** 어드민이 Admin Web을 통해 부분 데이터로 리스팅을 생성합니다. 고객에게 비공개입니다. Strapi의 기본 제공 초안 상태가 API를 통해 기본적으로 처리합니다.
- **게시됨:** 어드민이 Admin Web을 통해 리스팅을 게시합니다 (Strapi 게시 API 호출). 업체가 모든 고객 대면 검색 결과, 업체 상세 페이지, 사이트맵에 즉시 표시됩니다. 업체를 숨기려면 (예: 임시 휴업 또는 규정 위반), 어드민이 Admin Web을 통해 미게시 처리하면 됩니다.

> Strapi v5의 기본 제공 초안 및 게시 시스템은 기본적으로 공개 API 응답에서 초안 항목을 제외하므로 기본 공개 여부 제어를 위한 커스텀 정책이나 미들웨어가 필요하지 않습니다.

**비활성 사유 코드:**
업체를 미게시 처리할 때 어드민은 이유를 기록하기 위해 `inactive_reason`을 **반드시** 선택해야 합니다 (필수 필드):
- `closed` — 사업체 영구 폐업
- `owner_request` — 업체 사장님의 삭제 요청
- `violation` — 플랫폼 정책 위반
- `stale` — 현재 영업 상태 확인 불가
- `other` — 자유 텍스트 설명 필요 (별도의 `inactive_reason_detail` 텍스트 필드에 저장)

**소프트 삭제 정책:**
업체 리스팅은 **절대 완전히 삭제되지 않습니다**. 삭제 또는 비활성화된 업체는 미게시 처리되어 고객 대면 검색에서 숨겨집니다. 모든 이력 데이터(리뷰, 이미지, 메타데이터)는 감사 및 잠재적 재활성화를 위해 보존됩니다.

**감사 로그:**
업체 리스팅의 모든 변경 사항이 다음 정보와 함께 기록됩니다:
- 변경한 사람 (어드민 사용자) — Admin Web 세션에서 캡처 (API를 통해 Strapi에 전달)
- 변경된 내용 (필드 수준 차이)
- 변경 시간 (타임스탬프)
- 변경 전/후 값

> Strapi 라이프사이클 훅(`beforeUpdate`)을 사용하여 필드 변경 사항을 캡처하고 `audit-log` 컬렉션 타입에 기록합니다. Strapi Enterprise에는 기본 제공 감사 로그가 있습니다.

## 8. 리뷰 시스템

### 8.1 리뷰 콘텐츠 타입 (Strapi 컬렉션 타입: `review`)

| 필드 | Strapi 필드 타입 | 필수 여부 | 설명 |
|---|---|---|---|
| 작성자 | 관계 (→ Users-Permissions User) | 예 | 리뷰를 제출한 고객 |
| 업체 | 관계 (→ Shop) | 예 | 리뷰 대상 업체 |
| 별점 | 정수 (최소: 1, 최대: 5) | 예 | 별점 |
| 내용 | 텍스트 (장문) | 예 | 리뷰 본문 (10–500자, 커스텀 유효성 검사기로 검증) |
| 상태 | 열거형 | 예 | `published`, `hidden`, `under_review`, `deleted` |
| 모더레이션 사유 | 열거형 (nullable) | 아니오 | `spam`, `inappropriate`, `fake_review`, `irrelevant`, `other` |
| 신고 수 | 정수 | 아니오 | 사용자 신고 접수 횟수 |

### 8.2 리뷰 제출
- **리뷰 가능 대상:** 등록된 모든 고객 (Strapi Users & Permissions를 통해 로그인 필요). 잠금/정지된 계정은 리뷰를 제출할 수 없습니다.
- **방문 인증:** 불필요
- **별점:** 1–5점 척도 (필수)
- **내용:** 자유 텍스트 리뷰 본문 (필수, 10–500자)
- **제한:** 업체별 또는 일별 리뷰 제한 없음. 남용 방지는 어드민 수준의 계정 관리로 처리됩니다 (8.5항 참조).

### 8.3 리뷰 표시
- 리뷰는 각 업체의 상세 페이지에 최신 순으로 표시됩니다.
- 각 리뷰에 작성자 표시명, 별점, 내용, 제출 날짜가 표시됩니다.
- 업체의 평균 별점 및 총 리뷰 수가 눈에 잘 띄게 표시됩니다.

### 8.4 리뷰 모더레이션
- 어드민은 Admin Web을 통해 부적절하거나 학대적이거나 스팸성 리뷰를 신고 처리할 수 있습니다.
- **어드민은 언제든지** Admin Web을 통해 모든 리뷰 또는 게시물을 공개 뷰에서 숨길 수 있습니다. 숨겨진 리뷰는 즉시 고객 대면 화면 및 평균 별점 계산에서 제외됩니다.
- 신고된 리뷰는 어드민 결정이 내려질 때까지 공개 뷰에서 숨겨집니다.
- 어드민은 리뷰 상태를 `deleted`(소프트 삭제)로 설정할 수 있습니다.
- **모더레이션 사유 코드:** `spam`, `inappropriate`, `fake_review`, `irrelevant`, `other`

### 8.5 리뷰 신뢰성 및 남용 방지 (MVP)

SWIDA는 방문 인증 없이 리뷰를 허용하므로, 신뢰 유지를 위해 다음 안전장치가 구현됩니다:

**사용자 신고:**
- 고객은 "신고" 버튼을 통해 모든 리뷰를 신고할 수 있습니다 → `POST /api/reviews/:id/report`
- 신고 시 사유 선택: `spam`, `fake`, `inappropriate`, `irrelevant`, `other`
- 신고된 리뷰는 Strapi 라이프사이클 훅을 통해 `under_review` 상태로 전환됩니다.

**어드민 계정 잠금 (주요 남용 방지 수단):**
- 업체별 또는 일별 리뷰 제한 없음. 대신 어드민이 고객 계정을 완전히 제어하여 남용에 대응합니다.
- 어드민은 Admin Web을 통해 모든 고객 계정을 **잠금/정지** 처리할 수 있습니다. 잠긴 계정은 즉시 리뷰 및 기타 사용자 생성 콘텐츠 제출이 차단됩니다.
- 계정 잠금 사유 기록: `spam`, `fake_reviews`, `harassment`, `abuse`, `other`
- 잠긴 사용자가 콘텐츠 제출을 시도하면 계정이 정지되었다는 명확한 메시지가 표시됩니다.
- 어드민은 문제 해결 후 재량에 따라 계정 **잠금 해제**가 가능합니다.

**어드민 콘텐츠 숨김:**
- 어드민은 Admin Web에서 직접 모든 개별 리뷰 또는 게시물을 **숨길 수 있습니다**.
- 숨겨진 콘텐츠는 고객 대면 화면에서 즉시 제거되고 별점 계산에서 제외됩니다.
- 숨겨진 콘텐츠는 감사 목적으로 데이터베이스에 보존됩니다 (소프트 숨김, 완전 삭제 아님).

**리뷰 상태:**
| 상태 | 설명 |
|---|---|
| `published` | 모든 사용자에게 표시, 평균 별점에 반영 |
| `hidden` | 어드민 또는 시스템에 의해 임시 숨김 처리, 평균 별점에서 제외 |
| `under_review` | 사용자 신고 또는 시스템에 의해 신고됨, 어드민 결정 대기 중 |
| `deleted` | 어드민에 의해 영구 삭제, 평균 별점에서 제외 |

**별점 재계산:** Review 콘텐츠 타입의 Strapi 라이프사이클 훅으로 구현 — `afterCreate`, `afterUpdate`, `afterDelete`가 상위 업체의 `average_rating` 및 `total_reviews` 필드를 재계산합니다.

**향후 개선 사항:** 리뷰어 회원가입 시 SMS 인증, "인증된 고객" 배지, 쿨다운 기간, IP/기기 수준 부정 탐지, 행동 패턴 분석, 수정 기간 규칙, 업체 사장님 이의 제기 프로세스 — 12항 참조.

### 8.6 리뷰 피드 (메뉴)
- 모든 업체의 최신 리뷰를 표시하는 전용 페이지 → `GET /api/reviews?sort=createdAt:desc&populate=shop&filters[status][$eq]=published`
- 사회적 증거 역할을 하며 참여를 장려합니다.
- 각 리뷰 카드는 해당 업체의 상세 페이지로 연결됩니다.

## 10. 파트너십 흐름

### 10.1 파트너십 페이지 콘텐츠
파트너십 페이지는 다음을 설명하는 공개 랜딩 페이지입니다:
- SWIDA의 소개 및 업체 사장님에게 제공하는 가치
- 입점 혜택 (가시성 향상, 고객 리뷰, 검색 발견 가능성)
- 입점 단계별 절차
- 연락처 정보 (이메일, 카카오톡 ID, 인스타그램 핸들)
- 업체 사장님을 위한 FAQ

### 10.2 온보딩 프로세스
1. 업체 사장님이 파트너십 페이지를 방문하거나 다른 채널을 통해 SWIDA를 발견
2. 업체 사장님이 SNS(카카오톡, 인스타그램) 또는 이메일로 연락
3. 어드민이 응답하고 필요한 업체 정보 수집 (상호명, 주소, 테마, 편의시설, 이미지, 영업 시간)
4. 어드민이 Strapi에서 `draft` 상태로 업체 리스팅 생성
5. 어드민이 정보를 검토 및 확인
6. 어드민이 리스팅 게시 (상태 → `published`)
7. 어드민이 리스팅 활성화를 업체 사장님에게 알림

### 10.3 파트너십 문의 관리

#### 10.3.1 문의 콘텐츠 타입 (Strapi 컬렉션 타입: `partnership-inquiry`)

| 필드 | Strapi 필드 타입 | 필수 여부 | 설명 |
|---|---|---|---|
| 업체명 | 텍스트 (단문) | 예 | 사업체 이름 |
| 담당자 | 텍스트 (단문) | 예 | 연락하는 담당자 이름 |
| 전화번호 | 텍스트 (단문) | 예 | 연락처 전화번호 |
| 이메일 | 이메일 | 아니오 | 연락처 이메일 주소 |
| 주소 | 텍스트 (단문) | 예 | 업체 주소 |
| 업종 | 텍스트 (단문) | 아니오 | 마사지/웰니스 서비스 유형 |
| 선호 연락 채널 | 열거형 | 예 | `phone`, `kakaotalk`, `instagram`, `email` |
| 메시지 | 텍스트 (장문) | 아니오 | 추가 메모 또는 문의 사항 |
| 상태 | 열거형 | 예 | `new`, `contacted`, `awaiting_info`, `approved`, `rejected`, `published` |
| 출처 | 열거형 | 예 | `website_form`, `email`, `kakaotalk`, `instagram` |
| 어드민 메모 | 텍스트 (장문) | 아니오 | 내부 메모 (공개 비공개) |
| 연결된 업체 | 관계 (→ Shop, nullable) | 아니오 | 게시 후 생성된 업체 리스팅 연결 |

#### 10.3.2 문의 상태 흐름

`new` → `contacted` → `awaiting_info` → `approved` → `published`

| 상태 | 설명 |
|---|---|
| `new` | 문의 접수, 아직 연락 안 함 |
| `contacted` | 어드민이 업체 사장님에게 연락함 |
| `awaiting_info` | 업체 사장님이 리스팅에 필요한 정보를 제공하길 기다리는 중 |
| `approved` | 정보 확인 완료, 리스팅 생성 준비 완료 |
| `rejected` | 문의 거절 (사유 포함) |
| `published` | SWIDA에 업체 리스팅 활성화 완료 |

**공개 API:** 파트너십 문의 양식은 `POST /api/partnership-inquiries`로 제출됩니다 — 이는 공개 엔드포인트(인증 불필요). 해당 콘텐츠 타입의 Public 역할에 `create` 권한을 허용하도록 Strapi 권한이 설정됩니다.

**어드민 기능 (Admin Web을 통해):**
- 상태, 날짜, 출처별로 필터링 가능한 목록으로 모든 문의 조회
- 각 문의에 내부 메모 추가
- 문의 상태 업데이트
- 중복 문의 탐지 (커스텀 정책: 같은 업체명 + 주소가 이미 존재하면 플래그 처리)
- 승인된 문의를 새 업체 리스팅 초안으로 직접 변환 (커스텀 어드민 액션 버튼)

#### 10.3.3 응답 목표
새 문의 접수 후 **48시간 이내** 첫 연락을 목표로 합니다. 이는 운영 목표이며 계약상 SLA가 아닙니다 — Admin Web에서 기한 초과 문의(연락 없이 48시간 경과)를 시각적 표시기로 강조합니다 (Admin FSD F-INQ-12).

### 10.4 지속적인 커뮤니케이션
- 업체 사장님은 어드민에게 연락하여 리스팅 업데이트를 요청할 수 있습니다.
- 어드민은 **분기별(90일마다)** 등록된 업체가 여전히 운영 중인지 확인합니다. `last_verified_at`이 90일 이상 경과한 업체는 Admin 대시보드에서 재확인 필요로 강조 표시됩니다.
- 비활성 또는 폐업한 업체는 게시 취소(`draft` 상태로 전환)되고 `inactive_reason`이 설정되어 검색 결과에서 숨겨집니다.

## 11. 비기능 요구사항

### 11.1 성능
- 일반적인 조건에서 검색 결과가 2초 이내에 로드되어야 합니다.
- 주변 검색(GPS)은 3초 이내에 결과를 반환해야 합니다.
- 플랫폼은 성능 저하 없이 최대 10,000명의 동시 사용자를 지원해야 합니다.
- **Cloudflare 엣지 캐싱:** 정적 자산 및 캐시 가능한 API 응답은 대한민국(서울, 부산)에 가까운 Cloudflare PoP에서 제공되어 캐시된 콘텐츠의 한국 사용자 레이턴시를 한 자릿수 밀리초로 단축합니다.
- **3단계 캐싱 전략:** Cloudflare 엣지 캐시 (정적 자산, 이미지) → Redis (오리진의 API 응답 캐시) → PostgreSQL (원본 데이터)

### 11.2 반응형 디자인
- 모바일 우선 사용에 최적화된 완전한 반응형 디자인 (예상 모바일 트래픽 80% 이상)
- iOS Safari, Android Chrome, 데스크톱 브라우저에서 일관된 경험 제공

### 11.3 SEO
- 각 업체 리스팅은 고유하고 크롤링 가능한 URL을 가져야 합니다.
- 검색 엔진 가시성을 위한 적절한 메타 태그, Open Graph 데이터, 구조화 데이터(JSON-LD)
- 네이버 및 구글 코리아를 위한 한국어 SEO 최적화
- **크롤러 허용 목록:** Cloudflare 봇 관리는 검증된 네이버 및 구글 크롤러를 항상 챌린지 없이 허용하도록 설정됩니다. WAF 규칙에는 IP 검증을 포함한 `Yeti`(네이버) 및 `Googlebot` 사용자 에이전트 허용 목록이 포함됩니다.
- **자동 `sitemap.xml` 생성:** Strapi API에서 활성 업체를 가져오는 Next.js 기본 제공 사이트맵 생성

**SEO 페이지 분류:**

**색인 대상** 페이지 (사이트맵 포함, 크롤링 가능) — `/ko` 및 `/en` 버전 모두:
- 홈페이지 (`/ko`, `/en`)
- 업체 상세 페이지 (`/ko/shop/{slug}`, `/en/shop/{slug}`)
- 지역 탐색 페이지 (`/ko/location/{level1}/{level2}`, `/en/location/{level1}/{level2}`)
- 테마 탐색 페이지 (`/ko/theme/{theme-slug}`, `/en/theme/{theme-slug}`)
- 파트너십 페이지 (`/ko/partnership`, `/en/partnership`)

**색인 제외** 페이지 (`noindex`, 사이트맵 제외):
- 필터 파라미터가 포함된 검색 결과 (`/[locale]/search?theme=...&location=...`)
- 리뷰 제출 페이지
- 로그인/회원가입 페이지
- 모든 Admin Web 페이지 (`admin.swida.com/*`)
- Strapi 기본 제공 어드민 패널 (`api.swida.com/admin/*`) — 개발자 전용, 공개 접근 불가

### 11.4 현지화 (경로 기반 다국어)

SWIDA는 Next.js의 **경로 기반 라우팅**을 사용하여 두 가지 언어를 지원합니다:

**지원 로케일:**

| 로케일 | 코드 | URL 접두사 | 역할 |
|---|---|---|---|
| 한국어 | `ko` | `/ko` | 기본 언어 — 모든 콘텐츠를 먼저 한국어로 작성 |
| 영어 | `en` | `/en` | 보조 언어 — 외국인 방문자 및 외국 거주자용 |

**URL 구조:**

| 페이지 | 한국어 (기본) | 영어 |
|---|---|---|
| 홈페이지 | `www.swida.com/ko` | `www.swida.com/en` |
| 업체 상세 | `www.swida.com/ko/shop/{slug}` | `www.swida.com/en/shop/{slug}` |
| 테마 탐색 | `www.swida.com/ko/theme/{theme-slug}` | `www.swida.com/en/theme/{theme-slug}` |
| 지역 탐색 | `www.swida.com/ko/location/{level1}/{level2}` | `www.swida.com/en/location/{level1}/{level2}` |
| 파트너십 | `www.swida.com/ko/partnership` | `www.swida.com/en/partnership` |

**구현 — Next.js:**
- 미들웨어 기반 로케일 감지를 갖춘 Next.js App Router `[locale]` 동적 세그먼트
- 두 로케일 모두 명시적 URL 접두사 사용: 한국어는 `/ko`, 영어는 `/en` — 접두사 없는 라우트 없음
- 루트 경로(`www.swida.com/`)는 Next.js 미들웨어를 통해 `/ko`(기본 로케일)로 리다이렉트
- 메시지/문자열 관리를 위한 `next-intl` 사용
- 정적 UI 문자열(레이블, 버튼, 네비게이션, 시스템 메시지)은 로케일별 JSON 번역 파일에 저장 (`messages/ko.json`, `messages/en.json`)
- `hreflang` 대체 URL을 사용하여 다른 로케일의 동일 페이지로 연결하는 언어 전환 컴포넌트가 사이트 헤더/네비게이션에 제공됩니다.

**구현 — Strapi (콘텐츠 i18n):**
- 현지화가 필요한 콘텐츠 타입에 Strapi 기본 제공 **국제화(i18n) 플러그인** 활성화
- Strapi i18n 설정에서 기본 로케일을 `ko`로 설정
- `en`을 추가 로케일로 설정
- 어드민은 먼저 한국어로 콘텐츠를 작성한 후, Admin Web의 로케일 전환 기능을 통해 영어 번역을 선택적으로 추가 (Strapi의 i18n API 호출)
- Customer Web은 `locale` 쿼리 파라미터와 함께 콘텐츠를 요청: `GET /api/shops?locale=ko` 또는 `GET /api/shops?locale=en`

**i18n이 활성화된 콘텐츠 타입:**

| 콘텐츠 타입 | i18n 활성화 | 현지화 필드 |
|---|---|---|
| 업체 | 예 | 업체명, 소개, 주소, 정기 휴무일, 임시 휴무, 영업 시간, 영업 중 태그, 영업 종료 태그 |
| 테마 | 예 | `name` 필드가 로케일별로 현지화됨 (예: `ko`에서 "스웨디시", `en`에서 "Swedish") |
| 광역 | 예 | 광역명 (예: 서울특별시 / Seoul) |
| 구/군/시 | 예 | 구/군/시명 (예: 강남구 / Gangnam-gu) |
| 리뷰 | 아니오 | 리뷰는 작성된 언어로 저장 — 번역 없음 |
| 파트너십 문의 | 아니오 | 사용자의 언어로 제출 — 번역 불필요 |

**폴백 동작:**
- 업체 또는 콘텐츠 항목에 영어 콘텐츠가 없는 경우, Customer Web은 미묘한 표시와 함께 한국어 버전을 표시합니다 (예: "이 내용은 아직 번역되지 않았습니다" / "This content is not yet translated")
- Strapi의 i18n 플러그인은 폴백 로케일 설정 지원 — `ko`를 `en`의 폴백으로 설정합니다.
- 위도, 경도, 전화번호, 이미지, 별점, 불리언 등 현지화 불필요 필드는 로케일 간 자동으로 공유됩니다.

**다국어 SEO:**
- 각 현지화 페이지에 `<link rel="alternate" hreflang="ko" href="..." />` 및 `<link rel="alternate" hreflang="en" href="..." />` 태그 포함
- 사이트맵에는 색인된 모든 페이지의 두 로케일 버전 포함
- `x-default` hreflang은 `/ko`(기본) 버전을 가리킵니다.
- 로케일별 별도 Open Graph 및 메타 설명 태그

**어드민 워크플로우:**
- 어드민은 모든 콘텐츠를 먼저 한국어로 작성합니다 (필수).
- 영어 번역은 선택 사항 — 어드민이 Admin Web의 로케일 관리 인터페이스를 통해 언제든지 추가 가능합니다 (Strapi의 i18n API 호출).
- Admin Web UI는 영어로 제공됩니다 (어드민 대면, 고객 대면 아님).

### 11.5 보안
- **Cloudflare 엣지 보호:** 오리진 서버에 트래픽이 도달하기 전에 엣지에서 DDoS 완화, 웹 애플리케이션 방화벽(WAF), 봇 관리, 속도 제한 처리
- **SSL/TLS:** Cloudflare가 공개 SSL 종료 처리 (엣지 인증서). Nginx의 오리진 인증서와 함께 Cloudflare Full (Strict) 모드를 통해 오리진 연결을 보호하여 엔드투엔드 암호화 보장
- **Strapi 기본 제공 어드민 패널 인증:** 모니터링 및 디버깅을 위한 개발자 전용 접근 (기본 제공, JWT를 사용한 세션 기반). Strapi 기본 제공 어드민 패널(`api.swida.com/admin`) 접근은 IP 허용 목록 또는 VPN을 통해 권한 있는 개발자만 사용 가능하도록 제한해야 합니다.
- **Admin Web 인증:** Admin Web(Next.js)은 Strapi 어드민 API(이메일/비밀번호, JWT 방식)에 대해 인증합니다. 권한 있는 어드민만 로그인 가능 — 고객, 업체 사장님, 어드민 자격 증명 없는 개발자는 Admin Web에 접근할 수 없습니다.
- 커스텀 카카오/네이버 프로바이더를 사용한 Strapi Users & Permissions 플러그인을 통한 고객 인증
- XSS, SQL 인젝션에 대한 Strapi 기본 제공 입력 살균 및 보호
- Strapi 미들웨어를 통한 CSRF 보호
- 모든 페이지에서 HTTPS 강제 적용
- Strapi 미들웨어 플러그인을 통한 Strapi API 속도 제한 (애플리케이션 수준, Cloudflare 엣지 속도 제한 보완)
- **오리진 IP 보호:** 서버의 실제 IP는 공개적으로 노출되지 않습니다. 모든 DNS 레코드는 Cloudflare를 통해 프록시됩니다 (오렌지 클라우드 활성화). Cloudflare IP 범위로만 제한된 Nginx `allow` 규칙을 통해 오리진 직접 접근을 차단합니다.

### 11.6 데이터 프라이버시
- 대한민국 개인정보보호법(PIPA / 개인정보보호법) 준수
- 명확한 개인정보처리방침 및 서비스 이용약관 제공
- 고객 데이터(이메일, 위치)는 적절한 동의와 암호화를 통해 처리됩니다.

## 12. 향후 고려 사항 (MVP 범위 외)

이 기능들은 초기 출시에서 의도적으로 제외되었으나 향후 버전의 강력한 후보입니다:

- **업체 사장님 포털:** 셀프서비스 대시보드 — Strapi의 커스텀 역할/권한 활용 가능
- **예약 통합:** 업체 캘린더에 연동된 인앱 예약/예약 시스템

- **푸시 알림:** 새 리뷰, 주변 할인, 저장된 업체 업데이트 알림
- **쿠폰/딜 시스템:** 업체 또는 어드민이 관리하는 프로모션 행사 및 할인 쿠폰
- **채팅/메시징:** 고객과 업체 사장님 간의 인앱 커뮤니케이션

- **업체별 분석:** 리스팅별 조회수, 검색 노출 수, 리뷰 분석
- **초성 검색:** 더 빠른 이름 검색을 위한 한국어 자음 기반 검색 (예: ㅅㅇㄷ → 스웨디시)
- **고급 한국어 검색:** `LIKE`에서 `pg_trgm`(PostgreSQL 트라이그램 확장)으로 업그레이드하여 퍼지/오타 허용 매칭. 검색 수요가 더 증가하면 내장 CJK 토큰화를 지원하는 Meilisearch 도입.
- **리뷰 신뢰성 강화:** 리뷰어 회원가입 시 SMS 인증 (AlimTalk/Solapi를 통해), 영수증 사진 리뷰에 "인증된 고객" 배지, 쿨다운 기간 (예: 사용자당 업체별 주 1회 리뷰), IP/기기 수준 부정 탐지, 리뷰 도배 및 스팸 방지를 위한 행동 패턴 분석.
- **서버 측 리뷰 속도 제한:** Cloudflare WAF 제한 외에 리뷰 도배를 방지하기 위해 Strapi 미들웨어로 사용자별 시간당 및 업체별 일일 제한(예: 10건/사용자/시간, 3건/사용자/업체/일)을 적용합니다.

> **MVP로 이동:** 북마크 / 찜 기능은 이제 MVP 범위에 포함됩니다 (FSD §16 마이페이지).

**신규 기능 관련 향후 범위:**
- 커뮤니티: 사용자 게시글 수정/삭제, 게시글 신고, 포인트 사용
- 이벤트: 참가 신청, 이벤트 쿠폰 발행
- 게시판: 사용자 작성 게시글, 키워드 검색

## 13. 기술 아키텍처

> **참고:** 정확한 패키지 버전, 설정 세부 사항, 구현 세부 사항은 **기술 사양 문서(TSD)**에서 정의됩니다.

### 13.1 아키텍처 개요

SWIDA는 Strapi를 API 전용 백엔드로, 두 개의 Next.js 애플리케이션을 프론트엔드로 사용하는 **헤드리스 CMS 아키텍처**를 채택합니다: 업체 탐색을 위한 Customer Web과 플랫폼 관리를 위한 Admin Web입니다. Cloudflare는 CDN, 보안, SSL을 위한 엣지 레이어로 오리진 서버 앞단에 위치합니다.

| 컴포넌트 | 기술 | 목적 |
|---|---|---|
| **엣지 / CDN** | Cloudflare | DNS, CDN, DDoS 보호, WAF, SSL 종료, 엣지 캐싱 |
| **백엔드 (API 전용)** | Strapi (v5, TypeScript) | 헤드리스 CMS, REST API, 콘텐츠 관리, 인증 |
| **고객 프론트엔드** | Next.js 16 | 업체 탐색, 검색, 리뷰 제출 |
| **어드민 프론트엔드** | Next.js 16 | 커스텀 어드민 대시보드, 업체 CRUD, 리뷰 모더레이션, 분석 |
| **데이터베이스** | PostgreSQL + PostGIS | 관계형 데이터 + 지리공간 쿼리 |
| **오브젝트 스토리지** | MinIO (S3 호환) | Strapi Upload 프로바이더를 통한 이미지 저장 |
| **캐시** | Redis | 오리진에서의 API 응답 캐싱 |
| **리버스 프록시** | Nginx | 내부 라우팅, gzip, 업스트림 로드 밸런싱 |

> **참고:** Strapi 기본 제공 어드민 패널은 모니터링, 디버깅, 긴급 운영을 위해 **개발자 전용**으로 제한되며 일상적인 플랫폼 관리에는 사용되지 않습니다. Admin Web(Next.js)은 인증된 어드민 사용자만 접근할 수 있는 SWIDA 특화 커스텀 어드민 경험을 제공합니다.

### 13.2 백엔드 — Strapi

Strapi는 Customer Web과 Admin Web 모두를 위한 공개 REST API를 제공하는 **헤드리스 API 전용 백엔드**로 작동합니다. Strapi 기본 제공 어드민 패널은 모니터링, 디버깅, 긴급 운영을 위해 **개발자 전용**으로만 사용되며 — 주요 어드민 인터페이스는 커스텀 Admin Web(Next.js)입니다. 콘텐츠 타입은 JSON 스키마 파일로 정의되며 CRUD API는 자동 생성됩니다. 커스텀 비즈니스 로직은 컨트롤러, 라이프사이클 훅, 정책, 미들웨어를 통해 구현됩니다.

**설정:**

| 설정 | 값 |
|---|---|
| 언어 | TypeScript |
| 데이터베이스 | PostgreSQL (Strapi 내부 쿼리 빌더인 Knex.js를 통해) |
| 업로드 프로바이더 | MinIO용으로 설정된 `@strapi/provider-upload-aws-s3` |
| 인증 | 커스텀 카카오/네이버 프로바이더가 포함된 Users & Permissions 플러그인 |
| i18n | 국제화 플러그인 활성화 — 기본 로케일 `ko`, 추가 로케일 `en`. Shop, Theme, Region, District 콘텐츠 타입에 활성화. |
| API 스타일 | REST 전용 (MVP에서 GraphQL 미사용) |
| API 접두사 | `/api` (Strapi 기본값) |

**커스텀 확장:**

| 확장 유형 | 목적 |
|---|---|
| 커스텀 컨트롤러: `shops/nearby` | PostGIS 기반 주변 검색 엔드포인트 |
| 커스텀 컨트롤러: `shops/search` | pg_trgm을 사용한 고급 검색 (향후) |
| 커스텀 정책: `is-active-shop` | Strapi 기본 제공 초안 및 게시 시스템 활용 — 공개 API 응답에서 게시된 업체만 반환. Strapi가 기본적으로 REST API 쿼리에서 초안 항목을 제외하므로 이 정책은 미게시 업체가 고객 대면 엔드포인트에 노출되지 않도록 추가적인 안전장치 역할을 합니다. |
| 커스텀 미들웨어: `account-lock` | 어드민이 스팸 리뷰, 허위 리뷰 등 남용 행위를 하는 고객 계정을 잠금/정지 처리. 잠긴 계정은 리뷰 및 게시물을 제출할 수 없습니다. |
| 라이프사이클 훅: Review | 업체 average_rating 및 total_reviews 재계산 |
| 라이프사이클 훅: Shop | 모든 변경 사항에 대한 감사 로그 (`audit-log` 컬렉션 타입에 기록) |
| 커스텀 프로바이더: 카카오 인증 | 카카오를 통한 소셜 로그인 |
| 커스텀 프로바이더: 네이버 인증 | 네이버를 통한 소셜 로그인 |

> **참고:** 대시보드, 지도 선택기, 콘텐츠 숨김 기능 등 이전에 Strapi 어드민 플러그인으로 계획되었던 기능들은 현재 커스텀 Admin Web(Next.js) 애플리케이션에 구현됩니다.

### 13.3 프론트엔드 — Customer Web

| 설정 | 값 |
|---|---|
| 프레임워크 | Next.js 16 (최신 안정 버전) |
| CSS 프레임워크 | Tailwind CSS v4 |
| 컴포넌트 라이브러리 | Headless UI |
| 렌더링 전략 | SSG + ISR 하이브리드 |
| i18n | 경로 기반 라우팅 — `ko` (기본값), `en`. 두 로케일 모두 명시적 URL 접두사 사용 (`/ko/...`, `/en/...`). `next-intl` |
| 데이터 페칭 | `fetch`를 통한 Strapi REST API (`locale` 파라미터 포함) |

**렌더링 전략:**
- **SSG (정적 사이트 생성):** 테마 목록 페이지, 지역 탐색 페이지, 파트너십 페이지, 업체 상세 페이지 — `ko` 및 `en` 로케일 모두 생성
- **ISR (점진적 정적 재생성):** 60초마다 재검증하는 업체 상세 페이지 — 전체 재빌드 또는 요청별 서버 렌더링 없이 콘텐츠(리뷰, 별점, 영업 상태)를 최신 상태로 유지. 두 로케일 버전이 독립적으로 재검증됩니다.
- **SSR (서버 사이드 렌더링):** 검색 결과 (동적 필터/정렬 조합으로 SSG 비현실적). 로케일은 `[locale]` 라우트 세그먼트를 통해 전달됩니다.
- **CSR (클라이언트 사이드):** 리뷰 제출 양식, 주변 검색 (GPS 의존적)

### 13.3.1 프론트엔드 — Admin Web

| 설정 | 값 |
|---|---|
| 프레임워크 | Next.js 16 (최신 안정 버전) |
| CSS 프레임워크 | Tailwind CSS v4 |
| 컴포넌트 라이브러리 | Headless UI |
| 렌더링 전략 | SSR + CSR (동적 어드민 인터페이스) |
| 데이터 페칭 | `fetch`를 통한 Strapi REST API + Strapi Admin API |
| 인증 | Strapi 어드민 API를 통한 Admin JWT (`/admin/login`) |

Admin Web은 Strapi의 기본 제공 어드민 패널을 대체하는 주요 어드민 인터페이스로서 커스텀 제작된 Next.js 애플리케이션입니다. 업체 CRUD, 리뷰 모더레이션, 파트너십 문의 관리, 고객 계정 관리, 플랫폼 분석 대시보드 등 SWIDA의 어드민 워크플로우에 맞게 맞춤화된 UX를 제공합니다.

**접근 제어:** Admin Web은 전용 어드민 도메인(`admin.swida.com`)에서 제공되며 인증된 어드민 사용자만 접근 가능합니다. 고객, 업체 사장님, 개발자는 Admin Web에 접근할 수 없습니다 — 개발자는 모니터링 및 디버깅을 위해 Strapi 기본 제공 어드민 패널을 사용합니다.

### 13.4 데이터베이스

- **RDBMS:** PostgreSQL (최신 안정 버전)
- **스키마 관리:** Strapi가 콘텐츠 타입 정의를 기반으로 스키마를 자동 관리합니다. Strapi는 마이그레이션에 내부적으로 Knex.js를 사용합니다.
- **지리공간:** 주변 검색을 위한 PostGIS 확장 (커스텀 컨트롤러에서 원시 SQL / Knex를 통해 사용)
- **한국어 텍스트 검색 (MVP):** Strapi의 `$containsi` 필터 (내부적으로 `ILIKE` 사용). 향후 규모 확장 시, 커스텀 컨트롤러를 통한 `pg_trgm` 또는 전용 검색 엔진으로 Meilisearch 도입.

### 13.5 인프라 및 DevOps

**엣지 레이어 — Cloudflare:**
- 모든 공개 도메인(`www.swida.com`, `api.swida.com`, `admin.swida.com`)은 Cloudflare를 통해 프록시됩니다 (오렌지 클라우드 활성화).
- Cloudflare가 DNS, 공개 SSL 인증서, 엣지 캐싱 관리
- **CDN 및 엣지 캐싱:** 정적 자산(JS, CSS, 폰트, 이미지)은 대한민국 사용자에게 가장 가까운 Cloudflare 엣지 PoP에서 캐시됩니다. Cache-Control 헤더는 Nginx/Next.js에서 설정하며 Cloudflare가 이를 준수합니다. 특정 경로에 대해 Page Rules 또는 Cache Rules로 재정의 가능합니다.
- **DDoS 보호:** Cloudflare의 자동 L3/L4/L7 DDoS 완화가 항상 활성화됩니다 (무료 등급 포함).
- **WAF (웹 애플리케이션 방화벽):** 엣지에서 오리진에 도달하기 전에 일반적인 OWASP 위협(SQLi, XSS, RCE)을 차단하기 위해 Cloudflare Managed Rulesets 활성화
- **봇 관리:** 의심스러운 자동화 트래픽에 챌린지 처리. 스크래퍼 및 자격 증명 도용자를 차단하면서 합법적인 봇(네이버 크롤러, Googlebot)은 허용하도록 설정
- **속도 제한:** Strapi 수준 속도 제한을 보완하기 위해 민감한 엔드포인트(예: `/api/auth/*`, `/api/reviews`, `/api/partnership-inquiries`)에 엣지 수준 속도 제한 규칙 적용
- **SSL 모드:** Full (Strict) — Cloudflare가 Nginx에 설치된 Cloudflare Origin Certificate를 사용하여 오리진으로의 트래픽을 암호화합니다. Cloudflare와 서버 간에 평문 전송 없음.
- **이미지 최적화 (MVP 이후):** Cloudflare Polish 및/또는 Cloudflare Images는 엣지에서 MinIO가 제공하는 업체 사진을 최적화 가능 (WebP 변환, 리사이징) — 오리진 대역폭을 줄이고 모바일 로드 시간 개선. 유료 Cloudflare 플랜(Pro+) 필요로 MVP 이후로 연기. MVP에서는 Nginx 캐시 헤더를 통해 MinIO에서 직접 이미지 제공.

**리버스 프록시 — Nginx (오리진):**
- Nginx는 오리진 서버에서 Cloudflare 뒤에 내부 리버스 프록시로 위치합니다.
- 적절한 업스트림 서비스로 트래픽 라우팅:
  - `admin.swida.com` → Admin Web (Next.js) — 인증된 어드민 사용자만 접근 가능
  - `api.swida.com` → Strapi (공개 REST API + 어드민 API)
  - `www.swida.com` → Customer Web (Next.js)
- **Strapi 어드민 패널 접근 제한:** Strapi 기본 제공 어드민 패널(`api.swida.com/admin`)은 개발자 전용으로 제한됩니다. Nginx는 IP 허용 목록(개발자 IP 또는 VPN 범위만)을 통해 `/admin` 경로 접근을 제한하도록 설정됩니다. 이를 통해 Strapi 어드민 패널이 모니터링 및 디버깅 전용으로만 사용되고 일상적인 운영에는 사용되지 않도록 보장합니다.
- **오리진 접근 제한:** Nginx는 Cloudflare IP 범위에서만 연결을 수락하도록 설정됩니다 (Cloudflare의 공개된 IP 목록을 사용한 `allow` 지시문). 다른 모든 소스 IP는 거부되어 오리진 직접 공격을 방지합니다.
- 응답에 대한 Gzip 압축 (Cloudflare도 엣지에서 압축, Nginx는 오리진 압축 처리)
- Nginx가 MinIO 이미지 전달을 위한 캐싱 프록시 역할 (Cloudflare 엣지 캐시를 보완하는 오리진 수준 캐시)
- Full (Strict) SSL을 위한 Cloudflare Origin Certificate 설치

**오브젝트 스토리지:**
- 모든 업체 이미지 및 썸네일 저장을 위한 MinIO (자체 호스팅, S3 호환)
- S3 호환 프로바이더로 MinIO를 가리키도록 설정된 Strapi Upload 플러그인
- PostgreSQL은 이미지 URL 참조만 저장 (Strapi가 자동으로 처리)
- MinIO는 다른 서비스와 함께 Docker 컨테이너로 실행

**캐싱:**
- 트래픽이 높고 읽기가 많은 API 응답 캐싱을 위한 Redis (Docker에서 자체 호스팅)
- 커스텀 Strapi 미들웨어(`src/middlewares/api-cache.ts`)를 통해 구현, Redis 기반 라이프사이클 훅 무효화
- 캐시 대상 데이터: 광역/구 목록, 테마 목록, 상위 별점 업체, 자주 접근하는 업체 상세 정보
- 관련 콘텐츠 타입 변경 시 Strapi 라이프사이클 훅에 의해 캐시 무효화 트리거

**컨테이너화:**
- 모든 오리진 서비스(Strapi, Customer Web, Admin Web, PostgreSQL, MinIO, Redis, Nginx)를 Docker로 컨테이너화
- 로컬 개발 환경에는 `docker-compose` 사용
- 프로덕션 오케스트레이션 전략은 TSD에서 정의
- Cloudflare는 외부 SaaS 서비스 — 컨테이너화되지 않으며 Cloudflare 대시보드 또는 API를 통해 설정

**CI/CD:**
- GitLab에 저장소 호스팅
- 자동화된 빌드, 린트, 테스트, 배포를 위한 GitLab CI 파이프라인
- 파이프라인 단계: `lint` → `test` → `build` → `deploy`
- 환경 브랜치: `develop`, `staging`, `main` (프로덕션)

### 13.9 환경 설정

모든 서비스는 환경별 `.env` 파일로 관리되는 환경 변수를 설정에 사용합니다:

| 변수 범주 | 예시 |
|---|---|
| **데이터베이스** | `DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_NAME`, `DATABASE_USERNAME`, `DATABASE_PASSWORD`, `DATABASE_SSL` |
| **Strapi** | `APP_KEYS`, `API_TOKEN_SALT`, `ADMIN_JWT_SECRET`, `TRANSFER_TOKEN_SALT`, `JWT_SECRET` |
| **인증 (고객)** | `KAKAO_CLIENT_ID`, `KAKAO_CLIENT_SECRET`, `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` |
| **서버** | `HOST`, `PORT`, `NODE_ENV`, `URL` (공개 Strapi URL) |
| **오브젝트 스토리지** | `MINIO_ENDPOINT`, `MINIO_PORT`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `MINIO_BUCKET_NAME` |
| **캐시** | `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD` |
| **Cloudflare** | `CLOUDFLARE_ZONE_ID`, `CLOUDFLARE_API_TOKEN` (CI/CD 또는 Strapi 라이프사이클 훅을 통한 프로그래밍 방식 캐시 제거용) |
| **외부** | `KAKAO_MAP_APP_KEY` (카카오맵 JavaScript API 및 지오코딩용) |

환경 파일은 저장소에 **절대 커밋하지 않습니다**. 각 프로젝트에 대해 `.env.example` 템플릿이 관리됩니다.

### 13.10 Strapi 관련 고려 사항

**콘텐츠 타입 명명 규칙:**
- 컬렉션 타입: 케밥 케이스 단수형 (예: `shop`, `review`, `theme`, `region`, `district`, `partnership-inquiry`)
- 컴포넌트: 네임스페이스 적용 (예: `shop.service-menu-item`, `shop.amenities`, `shop.contact-channels`)

**API 응답 최적화:**
- 응답 페이로드 크기를 제어하기 위해 Strapi의 `populate` 및 `fields` 파라미터 사용
- 기본적으로 깊은 populate 피하기 — 엔드포인트별로 필요한 관계만 populate
- Customer Web은 각 뷰(목록 vs. 상세)에 필요한 필드만 요청해야 합니다.

**Strapi 버전 및 업그레이드 전략:**
- TypeScript와 함께 Strapi v5 (최신 안정 버전) 사용
- `package.json`에 주요 버전 고정
- 업그레이드 시 Strapi 공식 마이그레이션 가이드를 따릅니다.
