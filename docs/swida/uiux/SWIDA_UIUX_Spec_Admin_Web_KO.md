# UI/UX 사양서

## SWIDA — Admin Web

- **버전**: 1.2
- **날짜**: 2026-03-30
- **기반 문서**: SWIDA PRD v1.2, TSD v1.2, Admin Web FSD v1.2
- **범위**: MVP — 관리자용 플랫폼 관리 웹 애플리케이션
- **대상**: 데스크톱 우선 (데스크톱 사용을 위한 최소 지원 화면 너비)
- **Figma**: 아직 제공되지 않음 — 추후 개정 시 추가 예정
- **문서 역할**: 이 문서는 화면 레이아웃, 인터랙션 흐름, 컴포넌트 패턴을 정의합니다. **기능 로직, 비즈니스 규칙, 데이터 계약은 FSD v1.2에 정의되어 있으며, 모든 로직 결정의 권위 있는 출처입니다.** HTML 프로토타입은 시각적 참고 자료일 뿐이며 — 바인딩 인터랙션 계약이 아닙니다. 전체 문서 권한 체계는 FSD §1.5를 참조하세요.
- **변경 요약 (v1.1 → v1.2):** §1.1/§1.3 출처 모순 해결. §2.1 뷰포트 오버플로 전략 명확화 (칼럼 잘림, "가로 스크롤 없음"이 아님). §3.1 사이드바: 명시적 로그아웃 팝오버에 보이는 "Log Out" 버튼 추가; 지연된 사이드바 항목은 비활성화 상태로 표시. §3.4 상태 뱃지: `under_review`를 앰버(amber)로 변경. §3.4 데이터 테이블: 필터 칩 확장성 노트 추가; 일괄 작업은 post-MVP로 표기. §15 데이터 및 UI 상태 추가 (로딩 스켈레톤, 빈 상태, 에러 카드). §16 미리보기 시스템 UX 추가. §14.2 업데이트 (일괄 작업 post-MVP).

## 1. 문서 개요

### 1.1 목적

이 문서는 SWIDA Admin Web 애플리케이션의 화면 레이아웃, 컴포넌트 구조, 인터랙션 흐름을 정의합니다. 이 문서는 **인터랙션 권위 문서**로서 — 시스템이 어떻게 동작하는지, 관리자가 어떻게 탐색하는지, 모든 상태에서 무엇을 보는지를 정의합니다.

**이 문서에서 정의하지 않는 사항:**

- 비즈니스 규칙, 상태 로직, 데이터 계약 → **FSD v1.2** (기능 권위 문서)에 정의
- 색상, 타이포그래피, 간격, 아이콘 스타일 → 별도 **디자인 시스템 문서**에 정의
- 백엔드 API 동작 → **TSD v1.2**에 정의

**문서 계층 구조** (전체 사양은 FSD §1.5 참조):

1. **FSD v1.2** — 로직 권위 (시스템이 무엇을 하는지)
2. **이 문서 (UI/UX 사양서 v1.2)** — 인터랙션 권위 (어떻게 동작하는지)
3. **HTML 프로토타입** — 시각적 참고용 (어떻게 보이는지 — 바인딩 계약이 아님)

이 사양서와 프로토타입이 충돌할 경우, **이 사양서가 우선**합니다. 이 사양서와 FSD가 충돌할 경우, **FSD가 우선**합니다.

## 2. 레이아웃 시스템

### 2.1 뷰포트

표준 데스크톱 모니터(1280px 이상)에 최적화. 단일 데스크톱 레이아웃 — 반응형 브레이크포인트 없음.

**데이터 고밀도 테이블을 위한 칼럼 오버플로 전략:**

Admin Web에는 칼럼이 많은 테이블이 여러 개 있습니다 (예: 업체: 썸네일 + 이름 + 위치 + 테마 + 평점 + 상태 + 마지막 검증일 + 작업). "가로 스크롤 없음"을 강제하면 실제 데이터에서 오버플로가 발생하므로, 다음 칼럼 전략을 적용합니다:

| 기법                           | 사용 시기                                                                                                                                               |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `…`으로 텍스트 잘림 + 툴팁      | 고정 너비 칼럼의 긴 텍스트 (업체명, 설명, 이메일 주소)                                                                                                    |
| 칼럼 우선순위 숨김              | 좁은 뷰포트(1280–1440px)에서 낮은 우선순위 칼럼 (예: "마지막 검증일", "위치")이 축소 또는 숨겨짐. 핵심 칼럼(이름, 상태, 작업)은 항상 유지.                     |
| 최소 칼럼 너비                  | 작업 칼럼은 고정 최소 너비를 가짐. 이름 칼럼은 어색한 줄바꿈을 방지하기 위한 최소값을 가짐.                                                                   |
| 테이블 내부에서만 가로 스크롤    | 테이블이 정말로 맞지 않는 경우, 사이드바와 상단바는 고정된 채로 테이블 컨테이너만 가로 스크롤. 이것은 최후의 수단 — 잘림을 먼저 적용.                             |

**브라우저 창이 너무 좁은 경우** (< 1024px): 전체 페이지 안내 표시: "Admin Web은 데스크톱 브라우저에 최적화되어 있습니다 (최소 1024px)." 이 너비 이하에서는 앱이 동작하지 않습니다.

### 2.2 레이아웃 셸

```
┌──────────┬───────────────────────────────────────────────────────────┐
│  SIDEBAR │  TOPBAR (페이지 수준, 메인 영역 상단 고정)                    │
│  (왼쪽   │  [페이지 제목]  브레드크럼       [컨텍스트 작업]               │
│  고정,   ├───────────────────────────────────────────────────────────┤
│  전체    │  메인 콘텐츠 영역                                           │
│  높이)   │  ┌─────────────────────────────────────────────────────┐  │
│          │  │  페이지 본문 (테이블, 폼, 카드)                       │  │
│          │  │  (스크롤 가능)                                       │  │
│          │  │                                                     │  │
│          │  └─────────────────────────────────────────────────────┘  │
└──────────┴───────────────────────────────────────────────────────────┘
```

| 요소         | 동작                                                                                                                         |
| ------------ | --------------------------------------------------------------------------------------------------------------------------- |
| 사이드바      | 고정 너비, 왼쪽 고정, 전체 뷰포트 높이. 로고, 내비게이션 그룹, 하단에 관리자 사용자 정보 포함. 오버플로 시 스크롤 가능.              |
| 상단바        | 메인 콘텐츠 영역 상단에만 고정 (전체 너비 아님). 현재 페이지 제목, 브레드크럼, 우측 컨텍스트 작업 버튼 표시.                         |
| 메인 콘텐츠   | 사이드바 오른쪽의 나머지 너비를 채움. 세로 스크롤 가능.                                                                          |

> 별도의 전체 너비 글로벌 헤더 바는 없습니다. 로고와 관리자 사용자 정보는 상단 바가 아닌 사이드바 안에 위치합니다.

## 3. 공통 셸 컴포넌트

### 3.1 사이드바

사이드바는 주요 내비게이션 컨테이너입니다. 왼쪽에 고정되어 전체 뷰포트 높이를 차지하며, 페이지 콘텐츠와 함께 스크롤되지 않습니다.

```
┌──────────────────────┐
│  SWI[DA]             │  ← 로고 마크, /dashboard로 링크
│  Admin Console       │  ← 부제
├──────────────────────┤
│  ── Overview ──      │
│  📊 Dashboard        │  ← 활성: 흰색 텍스트 + 은은한 배경
│                      │
│  ── Content ──       │
│  🏪 Shops    [512]   │  ← 뱃지: 전체 업체 수
│  ➕ New Shop          │
│  🌿 Themes           │
│  📍 Locations        │
│  📋 Board Posts ···  │  ← 비활성 (지연됨)
│  🎉 Events      ···  │  ← 비활성 (지연됨)
│  📢 Notices     ···  │  ← 비활성 (지연됨)
│                      │
│  ── Moderation ──    │
│  ⭐ Reviews   [7]    │  ← 뱃지: under_review 수 (앰버)
│  🤝 Partnership [4]  │  ← 뱃지: 신규 문의 수
│  👥 Users            │
│  💬 Community   ···  │  ← 비활성 (지연됨)
│                      │
│  ── System ──        │
│  📋 Audit Log        │
│                      │
│  ░░░░░░░░░░░░░░░░░░  │  ← 스페이서로 나머지 높이 채움
├──────────────────────┤
│  [관] Admin          │  ← 클릭 시 로그아웃 팝오버 열림
│       admin.swida.com│
└──────────────────────┘
```

**비활성 사이드바 항목 (지연됨):**

`···`로 표시된 항목 (게시판, 이벤트, 공지사항, 커뮤니티)은 지연된 MVP 기능입니다. 사이드바에 회색으로 비활성화된 비대화형 항목으로 표시됩니다. 마우스 오버 시 툴팁에 "Coming soon."이 표시됩니다. 클릭해도 아무 동작도 하지 않습니다. 이를 통해 엔지니어가 전체 내비게이션 범위를 확인하고 라우트 슬롯을 예약할 수 있습니다.

**로그아웃 팝오버:**

하단의 관리자 사용자 정보 블록을 클릭하면 사이드바 하단에 고정된 작은 팝오버가 열립니다:

```
┌────────────────────────────┐
│  admin@swida.com           │
│  ─────────────────────     │
│  [  Log Out  ]             │
└────────────────────────────┘
```

"Log Out" 버튼은 팝오버 안에서 항상 즉시 보입니다 — 호버 상태나 2차 클릭 뒤에 숨겨져 있지 않습니다. "Log Out"을 클릭하면 F-LOGOUT-01~02가 트리거됩니다 (세션 초기화 → `/login`으로 리디렉션).

| 요소              | 설명                                                                             | FSD 참조     |
| ----------------- | ------------------------------------------------------------------------------- | ----------- |
| 로고 마크          | 브랜드 색상 강조가 있는 "SWIDA" 텍스트. `/dashboard`로 링크                          | F-NAV-01    |
| 부제              | 작은 대문자 뮤트 텍스트로 "Admin Console"                                           | —           |
| 그룹 라벨          | 대문자 뮤트 섹션 헤더: Overview / Content / Moderation / System                     | —           |
| 활성 항목          | 흰색 텍스트 + 은은한 반투명 흰색 배경                                                | F-NAV-02~10 |
| 업체 뱃지          | 전체 업체 수. 브랜드 색상 알약형                                                     | F-NAV-03    |
| 리뷰 뱃지          | `under_review` 수. **앰버** 알약형 (앰버 `under_review` 상태 색상과 일치)             | F-NAV-07    |
| 파트너십 뱃지      | `new` 문의 수. 브랜드 색상 알약형                                                    | F-NAV-08    |
| 비활성 항목        | 회색 텍스트, 호버 상태 없음, 마우스 오버 시 "Coming soon" 툴팁                         | F-NAV §2.2  |
| 관리자 정보        | 아바타 이니셜 + 닉네임 + 역할 라벨. 클릭 가능 — 로그아웃 팝오버 열림                     | F-NAV-12    |
| 로그아웃 팝오버    | 이메일 + 명시적 "Log Out" 버튼. 항상 보임, 호버 조건 없음                              | F-LOGOUT-03 |

### 3.2 상단바 (페이지 수준)

상단바는 메인 콘텐츠 영역 상단에 위치합니다. 전체 너비가 아니며 — 사이드바 오른쪽의 콘텐츠 영역에만 걸쳐 있습니다.

```
┌──────────────────────────────────────────────────────────────────────┐
│  Dashboard                              KST 2026-03-26 14:32        │
│  SWIDA Admin  ›  Overview                                            │
└──────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────┐
│  Shops                      [Export CSV]  [+ New Shop]               │
│  SWIDA Admin  ›  All Listings                                        │
└──────────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────────────────────────────────────┐
│  Edit Shop                  [Cancel]  [Save Draft]  [Publish]        │
│  Shops  ›  그린 힐링 스파                                              │
└──────────────────────────────────────────────────────────────────────┘
```

| 요소              | 설명                                                                  |
| ----------------- | -------------------------------------------------------------------- |
| 페이지 제목        | 현재 페이지 이름, 굵게 (예: "Dashboard", "Shops", "Edit Shop")          |
| 브레드크럼         | 제목 아래의 뮤트 경로 (예: "SWIDA Admin › Overview")                     |
| 컨텍스트 작업      | 우측 정렬 버튼 — 페이지별로 다름. 아래 페이지별 사양 참조.                  |

**페이지별 컨텍스트 작업:**

| 페이지              | 작업                            |
| ------------------- | ------------------------------- |
| Dashboard           | KST 타임스탬프 (버튼 없음)       |
| 업체 목록            | [Export CSV] [+ New Shop]       |
| 업체 생성 / 수정     | [Cancel] [Save Draft] [Publish] |
| 리뷰                | [Export]                        |
| 기타 모든 페이지     | KST 타임스탬프 (버튼 없음)       |

> 참고: 상단바에 "View Site ↗"나 "Admin ▾" 드롭다운은 없습니다. 이들은 프로토타입에 존재하지 않습니다.

### 3.3 페이지 헤더 패턴

모든 페이지의 상단바는 이 구조를 따릅니다. 필터 바는 상단바 바로 아래의 콘텐츠 영역에 페이지 본문의 일부로 표시됩니다:

```
TOPBAR:
┌──────────────────────────────────────────────────────────────────┐
│  페이지 제목                                [컨텍스트 작업]       │
│  브레드크럼 경로                                                  │
└──────────────────────────────────────────────────────────────────┘
CONTENT AREA:
┌──────────────────────────────────────────────────────────────────┐
│  [검색 / 필터 바]                                                │
├──────────────────────────────────────────────────────────────────┤
│  [페이지 본문]                                                   │
└──────────────────────────────────────────────────────────────────┘
```

### 3.4 공통 UI 패턴

#### 데이터 테이블

테이블 패턴을 사용하는 목록 페이지 (업체, 리뷰, 사용자, 감사 로그):

```
┌──────────────────────────────────────────────────────────────────┐
│  [검색 입력]  [필터 칩: 전체]  [필터 칩: 상태]  ...                │
├──────────┬────────┬───────┬────────┬─────────┬──────────────────┤
│ 칼럼 1   │ 칼럼 2 │ 칼럼 3 │ 칼럼 4 │ 상태    │ 작업             │
```

| 기능                 | 설명                                                                                                                                                   |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 체크박스 칼럼 없음    | 행 선택 / 일괄 작업은 MVP에 포함되지 않음. 아래 "일괄 작업" 노트 참조.                                                                                    |
| 필터 칩              | 단일 차원 필터링을 위한 가로 알약형 칩 (예: 상태). 활성 칩은 브랜드 색상 테두리와 밝은 배경. 칩 그룹당 한 번에 하나만 활성.                                     |
| 인라인 작업 버튼      | 각 행에 2–3개의 작은 인라인 버튼. MVP에서 ⋯ 오버플로 메뉴 없음.                                                                                          |
| 페이지네이션          | 페이지 번호 버튼 + "N–M / 전체" 정보 라인                                                                                                               |
| 로딩                 | 데이터 로딩 중 스켈레톤 행 (§15.1 참조)                                                                                                                  |
| 빈 상태              | 컨텍스트별 메시지 + 작업 (§15.2 참조)                                                                                                                    |

> **필터 칩 확장성 노트:** 필터 칩은 단일 차원 필터링(상태만)에 잘 작동합니다. 다차원 필터링(위치 + 테마 + 상태 동시)에는 칩이 불충분합니다. 다차원 필터링은 MVP 범위 밖이지만 컴포넌트 아키텍처에서 계획되어야 합니다 — 조합당 하나의 칩이 필요한 평면 단일 칩 그룹이 아닌, 결합 가능한 차원별 별도 칩 그룹을 사용하세요.

> **일괄 작업 — post-MVP:** 체크박스 칼럼과 일괄 작업 드롭다운(숨기기, 삭제)은 post-MVP 이터레이션에서 계획되어 있습니다. 데이터 모델과 API는 이미 일괄 작업을 지원합니다. 구현 시 테이블에 왼쪽 체크박스 칼럼이 추가되고, 1개 이상의 행이 선택되면 필터 바에 "일괄 작업" 드롭다운이 나타납니다. 엔지니어는 현재 테이블 구조가 영구적이라고 가정해서는 안 됩니다.

#### 확인 다이얼로그

모든 파괴적 작업에 사용됩니다:

```
┌──────────────────────────────────────┐
│  ⚠️ 작업 확인                         │
│                                      │
│  정말 {작업}하시겠습니까?              │
│  {추가 컨텍스트}                      │
│                                      │
│            [취소]  [확인]             │
└──────────────────────────────────────┘
```

#### 토스트 알림

- **성공**: 초록색, 5초 후 자동 사라짐
- **에러**: 빨간색, 닫기 전까지 유지
- **위치**: 메인 콘텐츠 영역 우측 상단

#### 상태 뱃지

상태 알약형은 밝은 틴트 배경에 색상 텍스트가 있는 작은 둥근 라벨입니다.

| 상태             | 색상        | CSS 클래스       | 사용 위치       | 근거                                   |
| ---------------- | ----------- | --------------- | -------------- | ------------------------------------- |
| Published        | 초록색      | `.pub`          | 업체, 리뷰      | 긍정적 / 공개적으로 표시됨               |
| Active           | 초록색      | `.pub`          | 사용자          | 정상 상태의 계정                        |
| Contacted        | 초록색      | 인라인 스타일    | 문의            | 진행 중                                |
| Draft            | 앰버        | `.draft`        | 업체            | 게시 전 주의 필요                       |
| **Under Review** | **앰버**    | `.under-review` | **리뷰**        | **조치 필요 — 관리자가 분류해야 함**     |
| Hidden           | 빨간색      | `.hidden`       | 리뷰            | 최종 / 공개 보기에서 제거됨              |
| Locked           | 빨간색      | `.hidden`       | 사용자          | 차단 상태                              |
| New              | 파란색      | `.new`          | 문의            | 미읽음 / 첫 연락 미완료                 |
| Awaiting Info    | 파란색      | 인라인 스타일    | 문의            | 외부 입력 대기 중                       |
| Approved         | 브랜드 색상  | 인라인 스타일    | 문의            | 다음 단계 준비 완료                     |
| Rejected         | 빨간색      | 인라인 스타일    | 문의            | 최종 / 거절됨                          |

> **`under_review`가 빨간색이 아닌 앰버인 이유:** `under_review`와 `hidden`은 기능적으로 다른 상태이지만, 둘 다 "Customer Web에서 보이지 않음"을 의미합니다. `under_review`는 "신고됨, 관리자 결정 대기 중"을 의미하며 — 조치가 필요합니다. `hidden`은 "관리자가 이미 숨기기로 결정함"을 의미하며 — 해결된 최종 상태입니다. 같은 색상을 부여하면 관리자가 스캔으로 분류하는 것을 방해합니다. 앰버 = 조치 필요. 빨간색 = 이미 처리됨 또는 차단됨. 이것은 둘 다 빨간색을 사용하는 HTML 프로토타입과 의도적으로 다릅니다 — 프로토타입의 색상 선택은 알려진 시각적 격차였습니다 (FSD §6 참조).

**신고 수 뱃지:** 높은 수(≥3)는 빨간색 배경 알약형, 낮은 수는 앰버.

**사유 칼럼:** 모노스페이스 텍스트로 원시 사유 코드 표시 (예: `spam`, `inappropriate`, `fake_review`).

**상태 알약형:** `under_review`는 앰버 `.under-review` 알약형 사용. `hidden`은 빨간색 `.hidden` 알약형 사용. 시각적으로 구분됨 — 앰버는 "관리자 조치 필요"를 신호하고, 빨간색은 "이미 처리됨"을 신호합니다. 전체 근거는 §3.4를 참조하세요. 참고: 프로토타입은 둘 다 빨간색을 사용 — 이것은 구현 시 수정해야 할 알려진 차이점입니다.

**행 작업 — 행당 두 개의 인라인 버튼:**

- `[Keep]` — 초록색 스타일 버튼 → 상태를 `published`로 설정
- `[Hide]` — 빨간색 스타일 버튼 → 숨기기 사유 다이얼로그 열림 → 상태를 `hidden`으로 설정

**체크박스 칼럼 없음. 일괄 작업 드롭다운 없음. ⋯ 오버플로 메뉴 없음.**

**숨기기 사유 다이얼로그**:

```
┌──────────────────────────────────────┐
│  리뷰 숨기기                          │
│                                      │
│  사유 *                              │
│  [▾ 사유 선택                   ]     │
│                                      │
│  사유: 스팸, 부적절, 가짜 리뷰,       │

│                                      │
```

| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

| 작업 버튼           | [메모 추가] (보조) + [주요 작업] (초록색 또는 브랜드 색상)                                                                                                                               |

**상태별 주요 작업 버튼:**

| 상태            | 버튼              | 스타일       |
| --------------- | ----------------- | ----------- |
| `new`           | 연락 →            | 초록색       |
| `contacted`     | 승인 →            | 브랜드 색상  |
| `awaiting_info` | 승인 →            | 브랜드 색상  |
| `approved`      | 초안 생성 →       | 브랜드 색상  |

**페이지 헤더 라인:** 뮤트 요약 텍스트 + 단일 [전체] 필터 칩.

### 스토리보드: 문의 라이프사이클

```
[1] 새 문의 도착 → 카드가 그리드에 나타남, 사이드바 뱃지 증가
    → 48시간 초과 시: 빨간색 좌측 테두리 + 카드에 "⚠ 지연" 경고

[2] 관리자가 "연락 →" 클릭 → 상태: new → contacted
    → 진행률 바가 2단계로 진행

[3] 관리자가 "승인 →" 클릭 → 상태: contacted/awaiting_info → approved
    → 진행률 바가 4단계로 진행

[4] 관리자가 "초안 생성 →" 클릭 → /shops/new에 문의 데이터가 사전 입력

[5] 업체 게시 → 문의 상태가 자동으로 "published"로 설정 (최종)

[*] 어느 단계에서든 "메모 추가" → 메모 입력 열림 → 내부적으로 저장
```

**플랫 행 형식:** 각 감사 항목은 하나의 플랫 행입니다. 확장/축소 없음. 단일 작업의 각 필드 변경은 자체 행을 생성합니다.

**칼럼:** 타임스탬프 (모노스페이스) | 관리자 | 업체명 | 작업 알약형 | 필드 (모노스페이스) | 변경 (이전 → 이후)

**작업 알약형 색상:**

| 작업          | 색상            |
| ------------- | -------------- |
| published     | 초록색 `.pub`   |
| field update  | 앰버 `.draft`  |
| unpublished   | 빨간색 `.hidden`|
| created       | 파란색 `.new`   |

**변경 칼럼 형식:** 이전 값은 빨간색 취소선으로 표시. 이후 값은 초록색으로 표시. 예: `~~draft~~ → published`

**필터 칩:** "전체 변경" | "게시/게시 해제" | "필드 업데이트" — 한 번에 하나만 활성. 활성 칩은 브랜드 색상 테두리와 채움.

**검색:** 텍스트 입력으로 업체명 또는 필드명으로 필터링.

## 14. 인터랙션 패턴 요약

### 14.1 CRUD 패턴

모든 관리 페이지는 동일한 인터랙션 루프를 따릅니다:

```
목록 (테이블/그리드) → 생성/수정 (폼) → 저장 → 목록으로 돌아감 (토스트와 함께)
                                       ↘ 미리보기 (새 탭, Customer Web 뷰)
```

### 14.2 인라인 vs 모달 vs 페이지

| 패턴                           | 사용 대상                                                                      |
| ------------------------------ | ----------------------------------------------------------------------------- |
| 전체 페이지 폼 (2단 칼럼)       | 업체 생성, 업체 수정                                                            |
| 모달/다이얼로그                 | 테마 생성/수정, 계정 잠금, 확인, 숨기기 사유                                      |
| 카드 그리드                     | 파트너십 문의                                                                   |
| 플랫 테이블 (확장 없음)          | 감사 로그                                                                      |
| 인라인 버튼                     | 모든 행 작업 (수정, 게시/게시 해제, 유지/숨기기, 잠금/잠금 해제) — MVP 전용        |
| 필터 칩                         | 모든 목록 페이지 — 칩 그룹당 단일 차원 필터링                                     |
| 체크박스 + 일괄 작업 드롭다운    | **Post-MVP** — 리뷰 및 업체에 대해 계획됨. 현재 UI에 없음.                        |

### 15.4 네트워크 에러 상태

```
  ╔══════════════════════════════════════════════╗
```

## 16. 미리보기 시스템 UX

> FSD 참조: §18 미리보기 시스템 계약, F-SHOP-11, F-SHOP-32

### 16.1 진입점

미리보기는 두 곳에서 트리거할 수 있습니다:

| 위치             | 요소                                                       | 조건                                                    |
| --------------- | ---------------------------------------------------------- | ------------------------------------------------------ |
| 업체 목록 행     | 👁 아이콘 버튼                                              | 항상 표시 — 게시된 업체와 초안 업체 모두에서 작동           |
| 업체 수정 페이지 | 게시 상태 카드의 "👁 Preview (Customer View)" 버튼           | 항상 표시                                                |

### 16.2 인터랙션 흐름

```
[1] 관리자가 👁 (업체 목록) 또는 "Preview (Customer View)" (수정 폼)을 클릭
    → 버튼이 로딩/스피너 상태로 전환

[2] Admin Web이 백엔드에 미리보기 토큰을 요청
    → POST /api/admin/shops/{id}/preview-token
    → 약 200ms 소요

[3] 성공 → 브라우저가 새 탭을 열음:
    {CUSTOMER_WEB_URL}/ko/shop/{slug}?preview_token={token}
    → 버튼이 정상 상태로 복귀

    실패 (토큰 요청 실패) → 에러 토스트:
    "미리보기를 사용할 수 없습니다. 다시 시도해주세요."
    → 버튼이 정상 상태로 복귀

[4] Customer Web 탭이 "미리보기 모드" 배너와 함께 로드:
    ┌──────────────────────────────────────────────────────────┐
    │  🔍 미리보기 모드 — 이 업체는 아직 공개되지 않았습니다      │
    └──────────────────────────────────────────────────────────┘
    → 나머지 페이지는 고객이 보게 될 업체를 그대로 표시

[5] 토큰은 15분 후 만료:
    → Customer Web에 표시: "이 미리보기 링크가 만료되었습니다."
    → 관리자는 새 토큰을 받으려면 미리보기를 다시 클릭해야 함
```

### 16.3 초안 vs 게시됨 동작

| 업체 상태    | 👁 동작                                                                                                          |
| ----------- | --------------------------------------------------------------------------------------------------------------- |
| `draft`     | 미리보기 토큰 + "미리보기 모드" 배너와 함께 Customer Web을 엽니다. 토큰 없이는 업체에 공개적으로 접근할 수 없습니다.    |
| `published` | Customer Web을 정상적으로 엽니다 (토큰 불필요). "미리보기 모드" 배너 없음 — 관리자가 고객이 보는 것과 동일하게 봅니다.   |

### 16.4 로케일

미리보기는 항상 한국어(`/ko/`)로 열립니다. 영문 콘텐츠가 있고 관리자가 영문 버전을 미리보기하려면 `/en/`을 수동으로 추가하거나, 추후 "Preview EN" 버튼이 추가됩니다.
